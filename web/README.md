# もじごと Web（Android + OneDrive / Google Drive / Dropbox）

ノート・構想メモの歯車でWeb専用の方向別自動反映をON/OFFできる。初期ON、このブラウザの全作品で共有し再読込後も保持する。自動保存とは独立し、作品内の個別設定・VS Codeの設定は変更しない。OFFでも手動反映は可能。各編集画面の歯車に保存ガイドへの入口を置き、原稿・ノートにはファイル読込ガイドへの入口も置く。詳しい説明はログイン後ガイドへ集約する。

## ローカル起動

HOMEの「最近開いた画面」は、クラウド接続前もページ全体の縦スクロールで末尾まで確認できます。

HOMEの「次回から前回と同じクラウドへ自動接続する」をONにすると、このブラウザの利用者ごとに設定を保存し、次回は接続成功時のクラウドへの再接続を開始します。認証の確認はクラウド側の状態により必要です。Google Driveの認証ポップアップが開けない場合は接続ボタンから続けます。認証失敗時の自動再試行は10分間抑制し、接続解除時は自動接続をOFFにします。

```powershell
npm run web:dev
```

ブラウザで `http://localhost:4173/` を開きます。

## Microsoftアプリ登録

審査専用のメールアドレス・パスワードログインは [設定手順](../docs/review-email-login.md) を参照してください。Cognitoでパスワードを管理し、サーバーの許可一覧にある一般の招待ユーザーだけが使用できます。既定では無効です。

OneDriveへ直接接続するため、Microsoft Entra管理センターでSPA用のアプリを登録します。

1. 「サポートされているアカウントの種類」で、次のどちらかを選ぶ
   - 個人用Microsoftアカウントのみ
   - 任意の組織ディレクトリ内のアカウントと個人用Microsoftアカウント
2. 「シングルページ アプリケーション」のリダイレクトURIに `http://localhost:4173/` を追加する
3. Microsoft Graphの委任されたアクセス許可 `Files.ReadWrite` を追加する
4. 発行された「アプリケーション（クライアント）ID」を、もじごとWebの接続設定へ入力する

SPAにクライアントシークレットは作成・入力しません。本番公開時は、公開先のHTTPS URLもリダイレクトURIへ追加します。

## 管理者設定と利用者設定の分離

`config.json` の `deploymentMode` を `managed` にすると、MicrosoftアプリIDの入力欄を利用者画面から隠せます。

```json
{
  "deploymentMode": "managed",
  "microsoftClientId": "管理者が登録した共通クライアントID",
  "googleClientId": "",
  "googleApiKey": "",
  "googleAppId": "",
  "dropboxClientId": "",
  "loginRequired": false,
  "authApiBase": "",
  "turnstileSiteKey": "",
  "loginProviders": ["microsoft", "google"]
}
```

- クライアントIDは公開情報としてWebアプリが使用します。クライアントシークレットは記載しません。
- `config.json` はキャッシュせず読み込むため、管理者設定の変更をWebアプリ本体の再ビルドなしで反映できます。
- 現在は `personal` が既定で、従来どおり端末内にMicrosoftアプリIDを保存できます。
- 将来の招待制ログインでは、管理画面またはサーバーAPIが同じ公開設定を返す構成へ置き換えます。

### Dropbox接続

Dropbox App Consoleで **Scoped access / Full Dropbox** のアプリを登録します。既存の任意の作品フォルダを使用するため、App folderではなくFull Dropboxを選びます。

1. Permissionsで `files.metadata.read`・`files.content.read`・`files.content.write` を有効にします。
2. OAuth 2のRedirect URIsに `http://localhost:4173/` と、本番の `https://web.mojigoto.com/` を登録します。別のサブディレクトリへ配置する場合は、そのディレクトリのURLを末尾の `/` まで含めて登録します。
3. Public clientsのPKCEを許可します。Implicit Grantは使用しません。
4. App keyをサーバー上の `config.json` の `dropboxClientId` に設定します。App secretは記載しません。
5. 開発用アカウントで接続を許可し、HOMEの「Dropboxに接続」からフォルダを選択します。ボタンはApp keyを設定した場合だけ表示されます。

```json
"dropboxClientId": "DropboxのApp key"
```

Dropbox認可にはPKCE（S256）を使用し、短期アクセストークンをSession Storageだけに保持します。更新トークンは発行を要求せず、期限切れ時は再接続します。原稿等はブラウザとDropbox APIの間で直接読み書きし、運営サーバーへ送信しません。保存時は `rev` を条件に更新し、競合する場合は自動上書きや競合コピーの作成を行いません。

一般公開にはDropboxの本番利用承認を別途確認してください。Businessのチームスペース全体を選ぶ専用UIには対応せず、ユーザーAPIから見えるホーム・共有フォルダを対象とします。

確認手順：接続→Single／Multi作品の検出→原稿・ノート・構想メモ・作品設定の保存→PC側の同期確認→同時編集の競合停止→バックアップの比較・復元・整理→ファイル移動→再読み込みと履歴復元→期限切れの再接続→接続解除。実アカウントでの確認はApp keyの設定後に行います。

公式資料：[OAuth](https://docs.dropboxapi.com/dropbox-api/docs/oauth)、[Upload API](https://docs.dropboxapi.com/dropbox-api/api-reference/user-endpoints/files/upload)。

### Google Drive接続の土台

GoogleアカウントログインとGoogle Driveへのファイルアクセス許可は別に扱います。Google Cloudで **Google Drive API** を有効にし、Googleログインで使用している「ウェブ アプリケーション」OAuthクライアントの承認済みJavaScript生成元へ、本番サイトのオリジンを登録します。

```text
https://web.mojigoto.com
```

そのOAuthクライアントIDを、サーバー上の `config.json` の `googleClientId` に設定します。クライアントシークレットは `config.json` やブラウザへ置かず、CognitoのGoogleプロバイダー設定だけに保持します。

```json
"googleClientId": "xxxxxxxxxxxx-xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx.apps.googleusercontent.com"
```

Google公式のフォルダ選択画面を表示するため、同じGoogle Cloudプロジェクトで **Google Picker API** も有効にし、APIキーを作成します。APIキーはウェブサイト制限を設定し、許可するリファラーを次に限定します。

```text
https://web.mojigoto.com/*
https://docs.google.com/*
```

Pickerは `docs.google.com` のフレーム内で表示されるため、上記2件を許可してください。APIの制限では **Google Picker APIとGoogle Drive APIの両方** を許可します。Google Cloudの「プロジェクト番号」（プロジェクトIDではない数値）とあわせて設定します。OAuthクライアントID、APIキー、プロジェクト番号はすべて同じGoogle Cloudプロジェクトの値を使用してください。

```json
"googleApiKey": "AIza...",
"googleAppId": "123456789012"
```

HOMEの「Google Driveに接続」で `https://www.googleapis.com/auth/drive.file` のみを要求します。Google Auth Platformのデータアクセスもこのスコープにそろえます。これは非機密スコープで、他の制限付きスコープを使わない構成では制限付きスコープのCASA評価を外す方向に変更できます。ブランド審査等は別途確認してください。

専用ページ `google-drive-setup.html` で初回登録と追加許可を行います。初回はPC推奨です。

- 既存Drive作品: 根フォルダを選び、使用する各フォルダ直下のファイル・子フォルダをPickerで複数選択します。子フォルダも順番に案内します。親の選択だけでは配下の許可になりません。書き出し専用ExportRoot・`.vscode`・`_WORK`・現行Webで使わないtrash／templates等の許可は省略できます。`note-images`はWebの文字編集だけなら省略できますが、VS Codeの画像に必要なファイルです。バックアップや集計を使う場合はそれぞれのデータも許可します。省略は取り込み除外や削除とは別です。既存作品は複製しません。
- PC作品: 原稿または`.mojigoto`を含むフォルダをブラウザで選び、新しいDriveフォルダへ構成とバイナリ内容を保持して取り込みます。事前確認欄で短い日時・識別末尾付きの名前を編集し、書き出し等の直下フォルダを除外できます。原稿・`.mojigoto`を含む作品フォルダと`.vscode`は除外できません。`.vscode`の設定・画像・履歴を保持し、各作品の正本を取り込みます。`_WORK`はリンク表示用なので取り込まず、空フォルダの事前作成も行いません。`.git`・`node_modules`・`.local-config`・`.env`系も自動除外します。同名でも新しい別フォルダを作り、既存作品へ結合しません。空フォルダはブラウザ選択に含まれません。元データを変更せず、途中失敗したフォルダも自動削除しません。対応版VS Code拡張は`.vscode/mojigoto-import-source.json`の出自と作品データを使い、_WORKがなくても原稿・作品・内部書き出し先のパスを取り込み先へ更新します。元々外部にある書き出し先は変更しません。G:は原稿の直接参照を維持し、MultiでView未設定の場合は作品切り替えを行います。
- VS Code: 取り込み先のDrive同期フォルダを開きます。端末切替前に同期完了を待ちます。PC側で新規作成・再作成したファイルは専用ページで追加許可します。未許可ファイルの自動検出はできません。
- Single→Multi移行後: Driveの同期完了を待ち、専用ページの追加許可で新しい作品フォルダ・`.mojigoto`・`work.json`と新規／再作成された項目を選択し、HOMEの作品一覧を再読み込みします。Google Driveで作品設定が見つからない場合、Webは未許可と不存在を区別できないため新規作成せず停止します。
- 管理ファイル: Google Driveで構想メモの`concept-memos.json`やノート保存先の`plots`／`references`が見つからない場合も、重複防止のため作成せず追加許可を案内します。まだない場合はVS Codeで構想メモ・ノートを作成して同期後に許可してください。`notes-index.json`と`work-metrics.json`が未許可／見つからない場合、Webからの索引・共有集計の更新は見送ります。原稿・ノート本体の保存は継続します。共有集計等も更新する場合はVS Codeが作成したファイルを許可し、作品一覧を再読み込みしてください。
- バックアップ: Google DriveではVS Codeで最初のバックアップを作成し、同期後に`.mojigoto/backups`・`index.json`・`snapshots`と中のファイルを許可してからWebで履歴を開きます。索引の破損／消失はVS Codeで再構築し、新規／再作成された項目を追加許可します。未許可の履歴が見えないためWebでは索引を再構築しません。VS Codeで新しい履歴を作った後も、Webで比較・復元するには追加許可が必要です。
- 執筆記録: VS Codeの集計更新時に`web-writing-events.json`の初回保存先を作成します。同期後に追加許可してからWebを使ってください。未許可・読み込み失敗・不正な形式では記録を作成／上書きせず停止します。原稿保存と記録保存の成否は別で、記録保存失敗は原稿保存後の警告として通知します。

追加許可はファイル／フォルダ単位です。許可済みファイルの本文更新だけでは不要で、ノートは各画面のJSON、構想メモは`concept-memos.json`全体を対象にします。0件からメモが増えたかではなく、ファイルが新規作成・再作成されたかで判断します。Webで作成したファイルはアプリ作成項目として許可対象です。

取り込み先の根フォルダは改名できます。古い表示名が残る／一覧に出ない場合は、専用ページの「フォルダの登録を復元する」で改名後の同じフォルダを選びます。再取り込みではありません。VS Codeは改名後のパスを開き、PC同期完了も確認します。内部の原稿・`.mojigoto`の名前変更とは別です。

専用ページの成功・エラーは画面下部にも閉じるボタン付きで表示します。ヘルプを開いている間は同じ通知をヘルプ内へ移し、閉じるとページへ戻します。エラーは後続の成功通知で消しません。

登録済みの場合も「別の許可済み作品フォルダへ切り替える」を表示します。「許可済み作品へ切り替える・登録を復元する」からも選択できます。PC取り込み済み・既存作品を手動許可した場合の両方を対象とし、Singleは作品フォルダ、Multiは親フォルダを選びます。キャンセル・作品確認失敗では前の登録を保持します。

フォルダ階層は専用ページの「許可するフォルダの見本」で確認できます。Multiでは`作品名/.mojigoto/work.json`が作品設定です。workRoot直下の`.mojigoto`は共通TODO等に使う場合があり、不要とは限りません。Single→Multi移行は作品用の構想メモ・画像・バックアップ・索引・集計・執筆記録も移し、共通テンプレートや未知ファイルは元の場所に保持します。空になった場合だけ元の管理フォルダを整理します。以前の版ですでに移行したフォルダは自動で整理しません。

見本の位置：`google-drive-setup.html#setupFolderExamples`。固定の「Google Driveのヘルプ」内にあり、接続欄の直接リンク・ヘルプの目次・既存のURLから開けます。幅1280px以上では右側パネル、狭い画面ではモーダルになり、幅変更後も項目・読んでいる位置を保持します。広い画面ではメインカラムの通常位置を保ち、ヘルプと重なる幅の場合だけ左へ配置を調整します。接続許可の取り消し・VS Code利用・追加許可・登録解除の説明もヘルプにまとめています。Google公式のファイル選択ポップアップ内の表示ではありません。

接続期限：Google DriveはブラウザのGISトークン方式を使用し、Googleが返す`expires_in`から60秒の余裕を引いて利用期限を設定します。30分固定の設定はありません。期限が近い／切れた場合は編集画面の案内から、本文・メモ・作品・保存基準を保持して再接続できます。期限切れ中の自動保存は再接続まで停止します。作業中の自動ポップアップやサーバー側のrefresh token管理は追加していません。診断用の速度計測コピーには発行日時・有効期間・利用期限を含め、トークン自体は含めません。

アクセストークンはSession Storageだけに保持します。旧 `drive` トークンは再利用せず、過去の権限の自動合算も無効にしています。旧許可をGoogleアカウント側で取り消してから再接続し、既存作品を再登録してください。旧フォルダ登録を新しい権限で登録済みとは扱いません。

本番反映・Console変更・動画と返信の順序は [Google OAuth 検証申請チェックリスト](../docs/google-oauth-verification.md) を参照してください。実アカウントでのPicker選択・保存・PC同期の確認は別途必要です。

更新用の公開ZIPには、サーバー固有の `config.json` と `api/auth/config.php` を含めません。既存のサーバー設定を残したまま、その他のファイルを上書きしてください。

利用申込は `/apply/`、問い合わせ、ログイン用メールアドレスの変更申請、登録アドレスの削除依頼は `/contact/` で受け付けます。受付内容は管理画面へ表示され、利用申込は管理者が確認してから招待へ追加します。

### 公開フォームとCloudflare Turnstile

Cloudflareの管理画面でTurnstileウィジェットを作成し、許可するホスト名へ本番ドメインを登録します。公開されるサイトキーはサーバー上の `config.json` に設定します。

```json
"turnstileSiteKey": "0x4AAAA..."
```

秘密キー、通知先メールアドレス、送信元メールアドレスは、公開されない `api/auth/config.php` にだけ設定します。

```php
'turnstile_secret' => '0x4AAAA...',
'form_notification_email' => 'owner@example.com',
'form_from_email' => 'no-reply@your-domain.example',
'form_submission_path' => __DIR__ . '/data/form-submissions.json',
```

受付時はTurnstileのサーバー側検証、ハニーポット、IPアドレスを秘密鍵でハッシュ化した1時間5回までの送信制限を適用します。受付内容は `api/auth/data/form-submissions.json` に保存され、同フォルダの `.htaccess` で公開アクセスを拒否します。通知メールに失敗しても受付内容は管理画面へ残ります。さくらインターネット側でPHPの `mail()` と独自ドメインの送信元アドレスを使用できることを確認してください。

受付完了後90日、利用終了後90日、管理履歴1年の保存期間を確実に適用するため、さくらインターネットのCRONを使用して `api/maintenance/cleanup.php` を1日1回PHP CLIで実行します。このファイルはWebからは実行できません。PHP実行ファイルと公開先の絶対パスはサーバーの環境に合わせて指定してください。

### 招待制ログインの入口

`loginRequired` を `true` にすると、アプリ本体より先にMicrosoft／Googleログイン画面を表示します。実際に有効化するには、`authApiBase` で指定した認証サーバーが次の処理を行う必要があります。

- `GET /session`：ログイン状態、招待状態、利用停止状態を返す
- `GET /login/microsoft`：Microsoftログインを開始する
- `GET /login/google`：Googleログインを開始する
- `POST /logout`：CSRFトークンを確認してセッションを終了する

アプリ本体は、サーバーが `authenticated: true` かつ `access: "active"` を返した場合だけ表示します。招待判定をブラウザの保存値だけで行うことはありません。本番の認証APIと招待設定の疎通を確認してから `loginRequired` を有効にします。

保護APIはサーバー側でもセッション・招待状態を検証します。公開フォーム・説明ページ・静的プログラムの配布と、利用者／管理者向けAPIへのアクセス制御は分けて確認します。作品本文は利用者が認可したクラウドドライブから読み書きします。

### Amazon Cognito登録

招待制ベータの認証基盤にはAmazon Cognitoのユーザープールを使用します。本番公開先に登録するURLは次のとおりです。

- コールバックURL: `https://web.mojigoto.com/api/auth/callback`
- ログアウト後URL: `https://web.mojigoto.com/`

登録項目と秘密情報の扱いは [`docs/cognito-registration.md`](../docs/cognito-registration.md) を参照してください。クライアントシークレットは `web/config.json` に記載しません。

認証APIは `api/auth` 配下のPHPで動作します。公開前に `api/auth/config.example.php` を `api/auth/config.php` として複製し、サーバー上でクライアントシークレット、セッション用秘密文字列、招待メールアドレスを設定します。`config.php` はGitと配布ZIPへ含めません。

Microsoft／GoogleをCognitoへ登録し、認証APIの疎通を確認するまでは、通常の `config.json` の `loginRequired` を `false` のままにします。確認後、`config.production.example.json` を参考に管理モードとログイン必須を有効化します。

### 招待利用者の管理画面

認証設定が完了したら、サーバー上の `api/auth/config.php` に管理者のログインメールアドレスを追加します。

```php
'admin_emails' => [
    'owner@example.com',
],
'user_registry_path' => __DIR__ . '/data/users.json',
```

管理ログインは `/admin/login/` と専用Cognitoクライアント・Cookieを使用します。`admin_client_id`・`admin_client_secret` の本番設定も必要です。管理者リストのアカウントを普段のアプリ用アカウントとして使わず、通常利用者と分けます。詳しい適用順は [admin-auth-setup.md](../docs/admin-auth-setup.md) を参照してください。`/admin/` では招待利用者の追加、有効化、停止、削除、最終ログイン日時の確認に加え、お知らせの追加・編集・削除ができます。

お知らせは `web/announcements.json` へ保存されます。管理画面から更新できない場合は、サーバー上でこのファイルをPHPから書き込める権限にしてください。利用者側ではお知らせIDごとの既読状態を端末内へ保存し、未読がある間はヘッダーに件数バッジを表示します。

管理画面で行った追加・停止・再開・削除は直近30件まで画面に表示されます。利用者側は1分ごと、および端末で画面へ戻った時に利用状態を確認します。停止または削除された場合は操作を止め、管理者が再開すると未保存の入力を保持したまま復帰します。

利用者は接続設定から表示用ニックネームを設定できます。認証元のMicrosoft／Googleアカウントに登録された氏名は保存・表示しません。ニックネーム未登録時はメールアドレスだけを表示します。

招待情報と管理操作履歴は `api/auth/data/users.json` にまとめて保存されます。利用者の状態変更と履歴記録は同時に更新されるため、片方だけが保存されることはありません。旧版の `admin-audit.json` / `admin-audit.jsonl` が残っている場合は表示時に読み継ぎます。このフォルダには直接アクセスを拒否する `.htaccess` が含まれています。PHPから書き込めない場合は、サーバーのファイル管理画面で `api/auth/data` の所有者と書き込み権限を確認してください。保存ファイルをWebから閲覧できる状態にはしないでください。

### `unauthorized_client` が表示される場合

`The client does not exist or is not enabled for consumers` は、個人用Microsoftアカウントが許可されていないアプリIDを `/consumers` で使用した場合に表示されます。

まず、入力した値が次のどれかではなく、概要画面の **アプリケーション（クライアント）ID** であることを確認します。

- オブジェクトID
- ディレクトリ（テナント）ID
- クライアントシークレットのIDまたは値

既存のアプリ登録を直せる場合は、アプリのマニフェストで次を確認します。

```json
{
  "api": {
    "requestedAccessTokenVersion": 2
  },
  "signInAudience": "AzureADandPersonalMicrosoftAccount"
}
```

個人用アカウント専用にする場合、`signInAudience` は `PersonalMicrosoftAccount` でも構いません。管理画面でアカウント種類を変更できない場合は、上記の種類を選んだ新しいアプリ登録を作成し、新しいクライアントIDに差し替えます。

リダイレクトURIは「Web」ではなく「シングルページ アプリケーション（SPA）」へ登録し、末尾の `/` まで含めて `http://localhost:4173/` と一致させます。

### `redirect_uri is not valid` が表示される場合

接続設定の「個人用OneDriveの登録条件」を開くと、アプリが実際に送るリダイレクトURIが表示されます。「コピー」ボタンで取得した値を、Microsoft Entraの次の場所へそのまま登録します。

1. アプリの登録 → 対象アプリ
2. 認証 → プラットフォーム構成
3. シングルページ アプリケーション
4. リダイレクトURIを追加

次の値は別のURIとして扱われます。

- `http://localhost:4173/`
- `http://127.0.0.1:4173/`
- `http://localhost:4173/index.html`
- `https://localhost:4173/`

ローカル開発では必ず `http://localhost:4173/` をブラウザで開きます。Microsoft側の登録変更が反映されたら、開いているもじごとWebを再読み込みして接続し直します。
