# Web読込用Markdownと取込画面の使いやすさ（2026-10-17）

原本を開く／コピーを作る結果が伝わらず、細かい説明が多く操作しづらいとの実機フィードバックを受けた。Dashboardの設定表示、生成ファイル名・階層、Webの操作選択・比較を一緒に見直した。

## VS Code

Dashboardの「Web読込用Markdown」は初期状態で折りたたむ。開閉状態をWebViewの状態に保存し、再描画で維持する。エラー時は開いて案内する。自動更新OFFでは「今すぐ更新」を非表示にし、ONで表示する。

生成先を `.mojigoto/web-import/` 直下に統一した。例：`プロット_サブキャラ--a1b2c3d4.md`。種類とノート名を先頭に置き、末尾8文字の識別子で同名ノートを区別する。資料は `資料_` で始まる。使用できない文字・長い名前も調整する。種類はファイルを見分けるための表示であり、Webでプロット／資料へ読み込める従来の動作は維持する。

通常保存は同じファイルを更新する。ノート名の変更では新しい名前へ更新し、以前の検証済み生成物を整理する。旧 `plots/`・`references/` の英数字名も、元のノートを更新／「今すぐ更新」した際に移行する。空になった旧フォルダだけを除去し、手書きファイル・元ノートを削除済みの生成物などを一律削除しない。

整理対象は生成元・ID・本文ハッシュを確認できる生成物だけ。手動編集を見つけた場合は移行前に停止して残す。新しい生成物を保存してから旧生成物を再確認・削除する。途中で旧生成物が変わった場合も残して案内する。作品内の通常フォルダのみ扱い、リンクを辿って作品外へ書き込まない。

## Web

操作をプルダウンから説明付きのラジオカードへ変更した。

| 選択肢 | 実行結果 |
|---|---|
| 原本を開く | VS Codeと同じノートを直接編集する。Markdownの内容で上書きせず、新規ノートも作らない |
| 新しいコピーを作成 | Markdownの分類・項目・本文で別ノートを1件作成する。元のノートは変わらない |
| 前のコピーへ反映 | 以前の読込先の基本構造・本文を更新する。Web側にも変更があれば停止する |
| 読込済みのノートを開く | 前回と同じMarkdownなので、Webのコピーを変更せず開く |
| 今後の読込先にする | 同内容の旧コピーに対応情報だけを登録する |

カードを選ぶと実行ボタンと、そのそばの実行結果も切り替わる。既存ノートを開く場合は新規ノート名の入力欄を隠し、画面名も「ノートの読み込み」にする。生成Markdownはランダム名を繰り返し表示せず、ノート名と構造の件数を目立たせる。

詳しい対象形式・対象外の情報・追加許可の説明はヘルプへ折りたたむ。解析上の警告は通常説明と区別して表示する。ヘッダーと実行欄はスクロール中も見えるようにし、スマホでボタンが切れない位置に置く。

選択先に既存ノートがある場合は「Webの内容と比較」を開ける。ファイル選択時点の分類・区分・補足・項目・本文を比較し、内部ID・対応情報・表示順・コピーの別名は差分にしない。項目メモ・画像などは今回のMarkdownに含まれないため比較対象外と明記する。広い画面は左右、狭い画面は上下にWeb／Markdownを表示する。変更箇所の前後2行を表示し、長い差分は100行ごとのページで確認できる。HTMLは実行せず文字列として表示する。

比較を開いた際は比較欄へ移動する。比較やカード選択だけで保存・新規作成しない。原本／既存コピーへの反映の保存保護は前段どおりで、比較から強制上書きする機能は追加していない。
