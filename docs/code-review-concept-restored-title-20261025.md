# 追加修正4：構想メモの復元タブ名（2026-10-25）

## 原因と変更

関連リンクの選択・表示は利用者確認済み。合意順4として、再読み込み／再起動で復元した構想メモタブの作品名が消える問題を修正。

- `notifyConceptMemoUpdated`の外部更新通知が`workDir`と`workTitle`を空文字で送信していた。クライアントは通知内容を状態へ取り込み、空になった作品情報をVS Codeの復元状態にも保存する。従来のシリアライザーはその情報だけを使うため、次の復元で「構想メモ」だけになった。
- 外部更新通知は、対象パネルが保持する作品ディレクトリと作品名を送信する。既存のデータ再読込・未保存の保護は変更しない。
- 通常オープンと復元は同じ作品情報の解決処理を使い、対象ディレクトリの作品設定から最新のタイトルを取得する。古い復元状態でディレクトリが空の場合、標準の`.mojigoto/concept-memos.json`の位置から作品ディレクトリを補う。
- 設定のタイトル→設定のフォルダ名→保存済み作品名→ディレクトリ名の順にフォールバックする。標準外の保存位置を推測で作品ディレクトリにせず、保存済み作品名がなければ従来どおり「構想メモ」とする。
- 設定がない別作品のタブへ、現在の別作品設定を流用しない。更新操作での名前取得も同じ解決処理を使う。
- タブの再利用時もパネルの作品情報を更新し、その後の外部更新・共通TODO更新で古い名前へ戻さない。
- 保存形式、メモ本文・関連付け、タブ復元の待機・重複防止は変更しない。版は1.0.68。インストール・公開・コミットは行わない。
