# 外部ExportRootの倉庫表示（2026-10-17）

実機確認追補：利用者から、もじごとフォルダ外でも倉庫が表示されることと、次の作業へ進めてよいとの確認を受領。次は呼び名一覧の編集用別タブ。

## 結果

Single／Multiとも、設定済みExportRootが開いているフォルダの外にあっても作品ツリーの「倉庫」に表示する。従来の直下にある書き出し先も引き続き表示する。既存の有効な設定は再選択不要。

倉庫はExportRoot全体を表示し、作品切替でも同じ設定先を使う。フォルダを展開してファイルをVS Codeで開ける。書き出しの作品別フォルダ名・ファイル構造は従来どおりで、移動や複製は行わない。

## 変更

- `src/core/export-root.js`：設定先の解決と、ワークスペース／Work Root自体を選ばない条件を共有。存在確認は表示側で行い、不在の設定先も監視開始を待てるようにした。
- `src/tree/work-tree-provider.js`：ExportRootの親が作品側と一致する表示条件を撤去。実在するディレクトリを倉庫として表示する。通常ファイル・未設定・不在・禁止ルートは表示しない。倉庫以外の項目を探すときは外部倉庫を全走査しない。祖先へ戻るリンクの循環展開も止める。
- `src/tree/work-tree-watchers.js`：設定先だけをRelativePatternで監視し、追加・削除を120msでまとめて一覧へ反映する。名前変更は削除＋追加として反映。内容変更による不要な一覧更新は省く。設定変更で旧監視と保留更新を破棄し、終了時に監視を解除する。従来のVS Codeの作成・削除・名前変更・保存イベントも維持。
- `src/export/export-utils.js`：選択時・完了時の説明を外部倉庫に対応。設定先が通常ファイルだった場合は選び直す。既存のルート自体を選ぶ制限と、直下の書き出しフォルダを作品一覧から除外する処理を維持。外部フォルダの名前はworkExcludeへ追加しない。
- 設定の説明、README、案内板を更新。案内板の倉庫の例にあった壊れたcodeタグも修正。

外部監視には[VS Code公式のcreateFileSystemWatcher／RelativePattern](https://code.visualstudio.com/api/references/vscode-api#workspace.createFileSystemWatcher)を使用。接続ドライブ・ファイルシステム・利用者の監視除外設定でイベントが届かない場合に備え、案内板には作品ツリーの更新ボタンも記載した。倉庫に削除・名前変更の新しいコマンドやメニューは追加していない。PCからDriveへの取り込み処理・パス修復処理・Webは今回の変更対象外。
