## 初期仕様の提案

### 対象と並び順

- 現在の作品の原稿ルート（manuscript／原稿）配下の.txt／.mdを、章フォルダを含めて取得する。原稿一覧で章の中を開いていても対象は作品全体と表示する。
- 初期順序はWebの原稿一覧に統一する。各階層をsortDriveItemsで並べ、フォルダを深さ優先で読み、その階層のファイルへ進む。章はフォルダ名、原稿はファイル名を目次に表示する。
- **章フォルダと直下の原稿が混在する場合、直下の原稿は章フォルダの後になる。** 例：01 第一章／01.txt → 02 第二章／01.txt → 00 プロローグ.txt。この順序を目次で確認できるようにする。直下を先頭にしたい場合の切替は別の仕様判断とする。
- VS Codeの番号による通常の並べ替えは反映されるが、全体書き出しの比較規則と常に同一とは約束しない。表示名ファイルの読込やVS Code書き出し順への切替は後続候補。
- 空の原稿も目次に残す。管理用・バックアップのフォルダ、ショートカットからの別作品への追跡は対象外とし、対象外と読み込み失敗を区別する。選択済みの作品ルート内を基準とする。

### 本文の取得元

| 条件 | 使用する内容 |
| --- | --- |
| 原稿一覧から開いたとき | クラウドから取得した内容 |
| 編集画面から開き、同じ作品・原稿ルート・対象ファイルを確認できたとき | その原稿だけ、開いた瞬間の入力欄の内容。未保存なら「未保存の内容を含む」と表示 |
| その他の原稿 | クラウドから取得した内容 |

プレビューを開くための保存は要求しない。閲覧だけでdirty、originalContent、currentFile、保存履歴、カーソル、自動保存設定を変更しない。原稿一覧に残っているcurrentFileだけでは下書きと判断せず、編集画面が表示中であることも確認する。

表示は開いた時点の入力と、各ファイルの取得時の内容の組合せ。複数ファイルを同時点に固定するクラウドのトランザクションはないため、「全ファイルの同時点の最新版」とは扱わない。別端末の更新や編集への追従は自動で行わず、「更新」で新しい閲覧用データを作り直す。

### 入口と画面

- 原稿一覧の見出し付近に「全体プレビュー」を置く。編集画面では、既存の「プレビュー」に「この原稿／作品全体」の対象選択を加える案。歯車の項目は増やさない。
- 上部は作品名・閉じる・目次・設定を基本とし、設定は折りたたむ。既存のプレビュー専用書体・文字サイズ・縦横・行間設定を使う。
- 目次は章→ファイルの階層。本文はファイルごとの区切りを付け、連続して読めるようにする。区切りは閲覧用で、原稿本文へタイトルや改ページを保存しない。
- 読み込み状況は閲覧画面内の「原稿を探しています…」「読込済み 12／30件」などの短い表示にする。全画面の起動カバーは再使用せず、読み込み中も閉じる操作を有効にする。
- 読めないものがある場合は「一部未取得」と件数を表示。空の本文として混ぜず、該当場所の再試行と、既知の原稿を先に読む操作を用意する。

## 読み込みと表示の構成

1. **対象一覧**：原稿ルートから章・ファイル・順序・親ID・相対パスを収集。本文の取得はここでは行わない。件数が確定するまで総数を断定しない。
2. **本文取得**：選択中の原稿を優先し、次の原稿を先読みする。共通の並列数はまず2件を案とし、実測で調整。OneDriveのフォルダ一括取得は利用可能な場合だけ使い、失敗分は通常取得へ戻す。
3. **ファイル単位の解析**：既存パーサーへ1ファイルずつ渡す。全原稿を1本の文字列へ連結せず、記法がファイル境界をまたぐことを防ぐ。
4. **段階的な描画**：横書きから検証し、小さな描画単位でブラウザへ制御を返す。大量データでは表示中と近隣のブロックを中心に保持する。既存の全件DOM生成をそのまま拡大しない。
5. **縦書きの位置保持**：ファイルID＋本文位置を基準に復元する。単純なscrollLeftの保存だけでは、追加読込・フォント・画面回転による幅変化を吸収できないため、別段階で検証する。

対象数・総文字量・1ファイルの表示ブロック数には上限を設ける設計とするが、値はAndroid実測前には確定しない。上限を超えたら完了扱いで切り捨てず、章・ファイルを選んで読む状態へ案内する。

### 状態と中止

閲覧用の状態は通常の編集stateから分離する。jobId、利用者、provider、クラウド、作品、原稿ルート、対象一覧、本文の取得状態、表示位置を持つ。閉じる・別作品・別クラウド・再読込でjobIdを更新し、古い応答を無効にする。通常の保存中フラグを読込ロックに流用しない。

共通providerに実通信の中断機能はない。初期は、中止後に新しい取得を始めず、すでに進行中の応答は表示へ使わない方式。即時にHTTP通信も止める対応はprovider側の拡張として区別する。

循環・重複はproviderとドライブを含むIDで検出し、階層数も制限する。フォルダ取得失敗は「下位原稿の件数不明」、ファイル取得失敗はそのファイル名を残す。再試行は失敗した範囲だけを対象にする。

本文はこの閲覧セッション内で保持し、未保存の下書きを永続キャッシュへ書き出さない。キャッシュ本文を使う場合も現在のproviderの検証契約に従い、未検証の古い本文を最新として表示しない。
