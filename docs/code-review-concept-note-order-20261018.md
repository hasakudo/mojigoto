# 構想メモの関連ノート絞り込み・項目順（2026-10-18）

利用者確認済みのVS Code書出／Web Markdown読込から、優先6へ進んだ。VS Codeのインポート選択UIは後続でまとめて検討する。

## 操作と表示順

- VS Codeは既存の「絞り込み」にノート選択を追加。「並び順」に「ノートの項目順」を追加する。Webは構想メモ一覧に同じ選択を追加。既存の検索・フォルダ・タグ・状態等とANDで組み合わせる。
- 出典のnoteItemと、ノート項目メモのlinkedConceptMemoIdsを両方確認する。項目順ではプロット→資料、ノートの設定順／タイトル順、大分類と区分内の項目の配列順に並ぶ。
- ピン留めは通常の並び順では先頭のまま。「ノートの項目順」ではノート順を優先する。初めて項目順を選ぶと昇順。同じ項目のメモは更新が新しい順、同日時はIDで安定させる。
- 複数箇所と関連するメモは、絞り込んだノート内の最初の項目を採用し、一度だけ表示する。すべてのノートではノート順を含めて最初を採用する。降順でも最初の関連先を採用する規則を変えず、その順序を反転する。
- 関連先のないメモ・削除や権限不足で参照できないメモは末尾。「関連なし・参照不可」で絞れる。特定ノートを選んだ場合はそのノートに関連するメモだけを表示する。
- コピーで項目IDが重複する場合は出典ファイル名・大分類IDで絞り、依然曖昧な場合は勝手に結び付けない。ファイル名変更時は一意の項目IDを使う。名称が同じというだけでは関連付けない。
- ノートを新規作成したり、本文・メモ・同期設定を保存する操作は行わない。表示順専用の共通モジュールをVS CodeとWebで使う。

## 読込と表示状態

- VS Codeのノート取得はフォルダ作成を伴わない読み取り専用。構想メモ一覧の初期表示を待たせず、絞り込み／並び順を開くたびにも再確認する。壊れたJSONは個別に除外して通知する。
- Webは一覧を表示してから既存キャッシュを使って確認する。構想メモの先読みだけの場合はノートを取得しない。ノート取得にフォルダ作成を伴わせず、読み取れたノートで表示する。一部の取得失敗は短い案内を表示し、失敗キャッシュは次回に再試行する。
- 作品・プロバイダー変更後の古い応答を無視。取得完了で編集画面・未保存入力を再描画しない。
- VS Codeは既存のWebview表示状態へノート選択を保存。Webはクラウド種別・作品IDごとにノート選択を保存する。対象ノートが参照不可になっても黙って「すべて」へ戻さず、未取得・参照不可の選択として保持する。
- フィルター状態は端末の表示設定だけで、作品データには書き込まない。Webの編集画面内の常時一覧は今回の変更対象に含めない。

Web本体・boot 1.0.204／SW v249、styles.css 1.0.181。設定ファイルの変更は不要。
