# 追加修正1：ノートの名前変更・自動保存・構想メモの出典表示（2026-10-25）

## 変更

VS Codeコード整理の最終保存は利用者確認済み、計画1～7を一区切り。追加修正の提案順を利用者が承認。ノート名・大分類名だけでなく、既存項目名を変更した場合の未保存表示・自動保存も対象に追加された。

- 原因：名前の入力処理が未保存表示より先に`touchAutoSyncedItemMemos`を呼び、全体の自動反映既定がONだと項目メモを持たない行も対象になる。`item.memo.updatedAt`で例外が出て、名前のモデルは変わっても未保存表示と自動保存要求に到達しなかった。区分行を含む大分類・ノート名の変更でも発生する。
- 名前変更からメモ更新時刻の変更を除去し、既存の`markDirty`→表示更新・自動保存要求へ確実に進める。項目メモがない行へ不要なメモを作ることもない。既存の区分名・補足・詳細・ふりがなの保存経路も検証。
- 構想メモの出典表示は、リンクIDに対応する保存済みノートの名前を読込時に導出する。本文・タグの一致だけで新たに関連付けず、リンク切れ・クリア済みの古いメモを復活させない。
- ノート名・大分類名・項目名等の出典名構造が変わった保存時は、開いている構想メモへ出典名専用の通知を行う。本文の自動反映ON/OFFとは独立した表示更新であり、本文同期を有効にしない。
- 構想画面ではIDと出典アドレスを照合して名前3項目だけをマージし、一覧と出典テキストのみ更新する。エディターを再描画せず、独自タイトル・本文・カーソル・未保存状態・変更リビジョン・同期指紋・保存版を保持。
- 出典名の導出のみで構想メモファイルへ書込みは行わない。次の読込・再起動でも保存済みノートから最新名を表示し、構想メモ自体の保存時には表示モデルの出典名が通常の保存経路に乗る。
- 保存形式・リンクID・既存の本文同期・競合保護・Webは未変更。版は1.0.68。インストール・公開・コミットは行わない。
