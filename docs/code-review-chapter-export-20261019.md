# VS Codeの章単位原稿書き出し（2026-10-19）

復元タブの重複修正を利用者が確認済み。既存のView原稿全体の結合書き出しに、章ごとの個別出力を追加した。

## 操作と出力

- 既存の「原稿：書き出し」またはコマンド「View 原稿を書き出し（全体／章ごと）」から、全体を1ファイルにするか、章ごとに別ファイルを作るか選ぶ。コマンドIDと既存の入口は維持。
- 章は現在の集計と同じくmanuscript直下のフォルダ。子フォルダも含む。原稿のない空フォルダは候補に出さず、直下の原稿は章なしとして別候補にする。全章を初期選択し、必要な章だけにも絞れる。
- 章フォルダは数値を考慮した名前順。章内は既存の原稿結合で使うファイル順をそのまま保つ。本文に章名や新たな見出しを追加せず、結合時の改行設定も共用する。
- TXT・Markdown・Word用HTML・ブラウザー横書きHTML・縦書きHTMLへ対応。縦書きは通常／二面／実寸優先の既存設定を全章に共用する。本文プレビューは先頭の選択章を対象とし、設定画面とプレビュー結果にその範囲を明記する。各HTMLのページ計算・開始番号設定は独立。
- 保存先はフォルダを一度選ぶ。標準候補は既存ExportRootの作品別「原稿書き出し/章ごと」。ファイル名は作品名と章名、HTMLの用途・版組の接尾辞を使う。直下の原稿は「作品名（直下の原稿）」とし、実在する章フォルダ名と区別する。
- 長い名前の短縮などでファイル名が衝突した場合だけ、章のIDから得た短い固定値を付ける。候補全体で名前を決め、選択する章を変えても別の章用ファイルを上書きしない。既存出力は件数と名前を示して一括確認し、取消では保持する。

## 対象の保持と書き込み

- 作品の切り替えで設定中の対象がすり替わらないよう、開始時のmanuscriptRoot・実パス・作品名を保持。MultiのViewリンクが同じパスのまま別作品へ付け替わった場合も検出し、出力を止める。
- 章別出力は選択した原稿を厳格に読み、読み取りに失敗したファイルを空本文として扱わない。全章を描画した後で保存先を確認し、一時ファイルへ準備してから置換する。
- 新たな出力が次回の原稿結合に混ざらないよう、原稿フォルダ内への章別書き出しは選び直してもらう。出力先にディレクトリ・シンボリックリンクなどがある場合は停止。通常のハードリンクは出力の置換により原稿を変更しない。
- 確認後に出力先ファイルが変わった場合は上書きせず、一時ファイルを片付ける。途中の確定でI/Oエラーが起きた場合は、作成済みの件数とファイル名をエラーへ付ける。バッチ全体の完全な巻き戻しは行わない。
- 縦書き設定画面がすでに開いている場合は、その画面を先に再利用して別の選択対象・コールバックを混ぜない。
