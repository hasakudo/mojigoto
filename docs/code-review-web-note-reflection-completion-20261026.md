# 項目メモ反映完了表示と反映対象の修正（2026-10-26）

利用者から、構想メモの入力停止から保存済みまで実環境で約13秒かかる、項目メモ更新後に反映中が残る、メモのない項目詳細保存で保存済み・反映失敗になるとの報告を受領。最後の症状では通知は出ていないとの補足あり。

## 確認できた原因と変更

自動反映の成功時、noteConceptSyncPendingを解除する前に保存済みを設定していた。appの実際のsetNoteStatusは反映中フラグがある限り反映中表示を優先するため、内部フラグが解除されてもバッヂだけが残っていた。解除後に成功・未保存状態を設定し直すよう修正。失敗・同期競合表示は保持する。

従来はノート保存時、メモを変更していなくても有効な連携項目全体を探索していた。保存前の本文と比較し、項目メモの本文・タグ・形式・設定・リンクに変更がある項目、初回連携の必要な非空メモ、前回の反映失敗項目だけを反映する。メモのない項目の詳細保存と、変更のない別項目の連携処理を切り離す。連携済みメモを空欄にする変更は反映する。

未完了の反映IDは編集中ノートのメモリ上に保持し、本文保存待ち中の追加入力や、反映失敗後の再保存でも予定を落とさない。本文データのJSONには追加しない。画面を閉じた後まで反映キューを永続化する変更ではない。競合保護と失敗通知は維持する。

「通知なしで保存済み・反映失敗」の実環境条件そのものは再現できておらず、原因を断定しない。今回、不要な反映を省略した経路で連携先を読まず保存済みになることを検証した。反映後の利用者確認が必要。
