# 接続・履歴の整理2-B2：履歴保存とHOME履歴からの復元（2026-10-27）

## 利用者確認と承認

利用者から、Google Driveで接続後に自動接続ONとし、再ログイン後も接続が維持されたとの報告を受領。Googleの有効な接続情報がある場合の自動復帰は利用者確認済み。接続情報がない場合の無操作再認証を確認したという意味ではない。その後、次の作業単位へ進む承認を受領した。

## 分離した範囲

web/lib/recent-view-history.mjsを追加し、createRecentViewHistoryへ以下の6関数を移した。

- recentViewsStorageKey、readRecentViews
- workRecentViewsStorageKey、readHomeRecentViews、readWorkRecentViews
- recordRecentView

createRecentViewRestorerへrestoreRecentViewとopenRecentViewを移した。履歴の認証開始、OneDrive／Dropboxの再認証先の保持、Googleの認証後の直接復元、復元前の別クラウドのキャッシュ破棄、二重オープン抑止を扱う。具体的な画面復元と表示は注入されたappの関数へ委譲する。

8関数の処理本体は変更前と一致することを確認。利用者・クラウド・ルート・作品単位の保存キー、旧形式の移行、通常履歴5件と作品のピン留め、履歴が空のときに旧履歴を復活させない扱いを維持する。本文や認証情報ではなく画面を再読込するための安全な参照だけを保存する。保存領域が使えなくても編集を止めない。

履歴一覧・ピン留めボタンの描画、古いノート履歴のタイトル補完、原稿一覧の最近の原稿機能、ブラウザhistoryの更新と戻る／進む、具体的なrestoreRoute・作品切替・スクロール位置復元はapp側と既存モジュールに残す。認証方式・権限・保存形式・履歴件数は変更しない。

履歴の保存処理は保存コントローラからも呼ばれるため、保存コントローラの初期化より前に生成する。復元処理は接続初期化が参照するため接続コントローラより前に生成する。コンストラクタ内で画面操作や保存を実行せず、相互に依存する描画・ルート処理をコールバックとして接続する。
