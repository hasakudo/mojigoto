# WebViewの警告通知の統一（2026-10-13）

利用者が、項目メモ・構想メモの未保存内容と異なる内容について、手動・自動の反映でも上書きされず、エラー通知で止まることを実機確認した。確認済みとして記録し、他のWebView警告もノートと同じ「閉じるまで残す」表示へ揃えた。

## 対象と動作

ノートで導入済みの表示を基準に、構想メモ、作品設定、ノートコピー、初回セットアップへ適用した。

- 警告・エラーは自動で消さず、閉じるボタンを表示する。
- 警告中は通常の成功・進行状況・消去要求で上書きしない。新しい警告は内容を更新する。
- 閉じる操作で警告を消し、その後の通常通知を受け付ける。
- 通常の成功通知は従来の1.8秒表示を維持する。セットアップ実行中など、もともと継続表示する進行状況も維持する。
- 警告の文字は選択でき、通知本文はtextContentとして描画する。閉じるボタンは標準buttonを使い、警告はalertとして読み上げ対象にする。

`src/views/shared/webview-notice.js` へ通知の共通処理とCSSを追加した。生成HTMLへ埋め込むため、外部スクリプトの追加読み込みは不要。ノートコピーのエラーを通常通知と区別し、セットアップの入力不足・移行操作の警告を警告として扱うよう修正した。構想メモの部分失敗に指定していた12秒の自動消去も除去した。

調査したDashboardの短時間通知とコピー操作の短時間通知は成功結果だけに使われていた。取り込みプレビューの警告は既に閉じる／再表示ができる。確認操作や並べ替え等のVS Code標準通知は標準の通知操作を使用する。入力欄に付随する説明文・常設の検証結果は通知トーストへ移動しない。
