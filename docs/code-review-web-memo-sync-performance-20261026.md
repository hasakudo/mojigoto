# メモ保存・同期の待ち時間改善 第1段階（2026-10-26）

利用者から、自動保存後の項目メモ・構想メモの同期完了まで約10秒かかる場合があり、その間の画面移動制限を短縮したいとの依頼を受領した。実環境の10秒は利用者報告であり、今回の計測値とは別である。

## 変更

- 構想メモの出典探索をconcept-source-resolver.mjsへ分離。出典ファイル名が一意なら対象の本文だけを読み、従来の同種ノート全件読込を省略する。ファイル一覧と本文は毎回取得し、完了済み本文をキャッシュしない。
- 改名・項目移動・同名ファイルではIDとグループIDによる従来の探索へ戻す。対象ファイルの破損時は他のファイルで代用せず失敗させる。作品・接続・ルートが途中で切り替わった場合は停止する。
- 同時に発生した同じ探索だけを共有し、結果は呼出元ごとに複製する。プレビューと保存が互いの本文を変更しないようにする。
- 両方向に本文保存、バックアップ、反映の段階別計測を追加。項目→構想には探索・本文取得・書込・リンク保存も記録する。既存の環境情報の性能記録とコンソールで確認できる。追加する計測内容に本文やファイル名は含めない。

## ブラウザ比較

実クラウドを使わない同一の検証用データで、自動保存から構想→項目の反映まで比較した。ノート13件、対象本文150ms、他12件の本文各2000ms、一覧40ms、書込各100msの模擬通信条件。自動保存待ち2000ms、バックアップは比較用環境のみOFF。変更前appの全件探索と変更後appの対象探索を、同じ保存・同期モジュールと条件で比較した。

| 指標 | 変更前 | 変更後 |
| --- | ---: | ---: |
| 本文読込 | 13件 | 1件 |
| 一覧取得 | 1回 | 1回 |
| 書込 | 3回 | 3回 |
| 最初の書込開始〜保存・同期完了 | 2.380秒 | 0.531秒 |
| 入力停止〜完了（自動保存待ち込み） | 4.382秒 | 2.538秒 |

最初の書込開始〜完了は移動制限中の処理時間の近似値であり、制限開始の全区間を厳密に測った値ではない。両側の保存本文一致、dirty/saving/syncingの解除、ブラウザエラー0件を確認した。証跡は.review-baseline/web-memo-sync-performance-20261026/before-after.json、after-sync-performance.jpg。模擬条件の結果であり、実クラウドで10秒が0.531秒になるとは保証しない。

## 検証・残る範囲

全1,493テスト成功（失敗0）。追加13件で対象1件取得、次回の最新本文取得、同時取得共有と複製、改名・移動・同名、破損、失敗後の再試行、接続切替を検証。変更したJavaScriptの構文確認も実施した。

今回の読込削減は構想→項目が対象。項目→構想には段階別計測を追加したが、速度改善を実測したとは扱わない。自動保存の2秒待ち、バックアップの待機順序、最新本文とeTagによる競合保護、画面移動の保護は維持する。バックアップの非同期化は共有state・接続先の固定と失敗時の扱いを別途整理してから検討する。
