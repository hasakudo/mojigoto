# 長いルビの対策とグループ／単一ルビの設計（2026-10-17）

## 利用者の意図と今回の区切り

Webノートのふりがな・ルビと案内の配置は利用者実機で確認済み。次のV01では、縦書きプレビュー、簡易書き出し（通常／二面）、実寸優先の書き出しを一緒に対象とする。利用者は「単一ルビ」を「東＝とう／京＝きょう」のように親文字ごとに読みを対応させる意味と明示した。

今回は実装経路の調査、モードと操作の設計、調査で再現した無限の行送りの修正を行った。モード設定・右クリックの編集UI・長いルビの最終的な字送り／見た目の調整はまだ実装していない。停止修正だけを長いルビ対応全体の完了とはしない。

## 現状の実装で確認したこと

| 経路 | 行分割と描画 |
|---|---|
| 縦書きプレビュー | `server/vertical-dev.mjs` → `src/preview/vertical-layout-core.js` の行分割・ruby描画 |
| 簡易・通常／二面 | `src/export/merged-manuscript-browser-html.js` → 共通トークン化と `vertical-print-line-utils.js` の行調整。通常／二面はページの並べ方を切替 |
| 実寸優先 | `src/export/merged-manuscript-browser-realprint-html.js` → 同じ行分割・印刷用行調整。描画とmm単位の配置は独自 |

現行ルビは親文字数を `displayWidth` に保持しており、文字数として1字扱いしているわけではない。ただし1つのrubyトークンは分割せず行送りする。親文字が行長より長い場合、その塊を1行に残す。行に収まる複数文字のグループでも、行末で塊ごと送るため空きが大きくなる。

描画はプレビューと印刷で別。単一ルビの記法が読めるだけでは十分ではない。例えば現行プレビューで `｜京《きょう》` の計算上の占有長は0.750em、親文字側の送りは1.147emとなった。これだけでDOM上の重なりを確認したとは言えないが、単一ルビを並べるときの占有長と描画長を再測定すべき根拠になる。短い読みを短くする現行調整を、そのまま新モードへ適用しない。

## 提案するモードと原稿の表現

| 種類 | 操作結果の例 | 行分割の考え方 |
|---|---|---|
| グループルビ | `｜東京《とうきょう》` | 親文字と読み全体を1組として配置。読みを機械的に分断しない |
| 単一ルビ（モノルビ） | `｜東《とう》｜京《きょう》` | 親文字ごとの対応を保持し、その組の間で行分割できる |

既存の一般的な記法を組み合わせる方法を優先する。グループの読みを均等な文字数で割らない。熟字訓や意味による読みはグループのまま扱える。新しい不可視注釈、原稿の位置を指す別ファイル、独自の区切り文字は初期案では導入しない。コピー・移動・外部編集・Web・字数集計・プレーンテキスト書き出しでも意味が残りやすい。

3～4文字は1つの親文字へ付ける読みの確認目安とし、文字数だけで切り捨てる上限にはしない。読みを小さくし過ぎないこと、前後のルビと衝突しないこと、行末に収まることを実際の寸法で決める。長い読みや1行を超えるグループは、判定と案内を別途設ける。モード変更だけで全ての長いルビが収まるとは扱わない。

参照：W3Cの作業草案 [Rules for Simple Placement of Japanese Ruby](https://www.w3.org/TR/simple-ruby/) はモノ・グループ・熟語ルビと、親文字と読みの対応・前後との配置を分けて説明している。参考となる設計資料であり、今回これに完全準拠したとは扱わない。熟語ルビを第3モードとして実装することは今回の初期範囲に含めない。

## デフォルトと箇所ごとの操作

デフォルトは「新しくルビを挿入するときに最初に選ぶ種類」としてVS Code設定に置く案。初期値はグループ。既定を単一へ変えても、既存のグループ記法を勝手に分割しない。原稿内でどの種類になっているかは、保存された記法そのものを正とし、プレビューと全書き出しが同じ対応を使う。

1. 範囲選択して右クリックの「ルビを挿入／編集」へ進む。ルビ内にカーソルがある場合も、その1組を対象にする入口を検討する。
2. 「グループ／単一」を選ぶ。単一は「東」「京」の各読み欄を出し、利用者が対応を確認・入力する。グループから変更する際は元の読みをそばに表示する。自動で正しい分割を推定したとは扱わない。
3. 適用結果を確認して、対象範囲を1回の編集で置き換える。取消では原稿を変更しない。Undoでまとめて戻せる。
4. 単一からグループに戻す場合は、選択範囲内の連続する対応をまとめて読みを連結する。途中に通常文字や別注釈が混在する場合は対象範囲を確認する。

既存の右クリック「ルビを挿入」があるため、同じ導線の拡張候補となる。既存ルビの途中選択では二重に記号を入れず、対象を明示する。編集UIを開いている間に原稿が変わった場合は、古い範囲へ適用しない。複数選択、改行、サロゲートペア・結合文字・異体字セレクタも受入条件に含める。

「1字」はUTF-16のコード単位ではなく、表示上の文字単位を確認して分ける。単一の字送りは親文字数だけでなく読みの占有長も含め、禁則、句読点、傍点、ページ・段の境界も既存の行計算へ返す。

## 今回先に修正した不具合

共通の長いルビの行末調整は、最後のトークンを次の行へ移す際、1行にルビ1組しか残らなくても移し続けていた。配列末尾に新しい空行が増え、同じルビがその次へ送られ続ける。確認用の4字行＋ `｜東京都市部《とうきょうとしぶ》` で再現し、確認プロセスを中断した。

プレビュー用 `normalizeWideRubyLineEnds` と印刷用の同処理へ、1組だけの行はそれ以上送らない条件を追加した。元の親文字・読みは残す。長いグループのはみ出しやルビの重なりを自動で解消する変更ではない。

## 当て字・発音以外のルビの追補

利用者から、ふりがな欄へ読み以外の当て字等を入力した場合も単一ルビで検証したいとの要望を受領。ルビ文字列は発音とは限らず、漢字・カタカナ・英字・記号を含む任意の注釈として保持する。ひらがなへの自動変換、辞書による読みの訂正、文字数均等での分配はしない。

| 確認例 | 意図 |
|---|---|
| `｜運《デス》｜命《ティニー》` | カタカナの別読みを利用者が文字ごとに割り当てた対応を保持 |
| `｜あ《亜》｜て《天》｜じ《字》` | ルビ側が漢字でも同じ処理 |
| `｜夜《Night》｜空《SKY》` | 英字と大文字を保持 |
| `｜星《スター★》｜光《Light光》` | 記号・異種文字の混在を保持 |
| `｜運命《デスティニー》` | 語全体の指定を勝手に単一へ分割しない |

既存のプレビュー／印刷の行分割を狭い2字行・組版調整ON/OFFで実行し、前後の本文と各対応がそのまま残ることを追加検証した。Webノートの解析も同じ対応になることを検証。通常／二面／実寸優先の実HTML生成にもカタカナ・漢字・英字の例を含め、注釈が残ることを確認した。関連14件成功、失敗・省略0件（`.review-baseline/nonphonetic-ruby-tests.log`）。今回はテストと記録だけを変更し、製品コードと配布物は変更していない。

UI実装後の受入条件にも、(1)グループ→単一で対応を利用者が確認するまで自動分配しない、(2)単一→グループで文字種・順序を保って連結、(3)対応を決められなければグループの維持または取消ができる、(4)長いカタカナ・漢字・英字・混在注釈の重なり／はみ出し／行末／ページ境界を各描画経路で目視確認、を追加する。今回の文字列保持テストを、配置や未実装モードUIの検証完了とは扱わない。
