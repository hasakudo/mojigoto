# 再読み込み時の編集位置復元の修正（2026-10-27）

## 報告と原因

利用者がブラウザの戻る／進む、未保存時の確認は問題ないと確認。一方、原稿・ノート・構想メモはいずれも再読み込み時に先頭へ戻ると報告。前回1.0.231のブラウザ検証は原稿→一覧→戻るの経路に限られており、直接の再読み込みを確認できていなかった。

位置の記録が画面移動時に偏り、直接再読み込みすると現在のカーソルが履歴に残らなかった。ノートと構想メモには入力欄の選択範囲・内部スクロールの保存がなかった。構想メモは復元後にも先頭へ戻す遅延処理が動く経路が残っていた。

## 変更

- view-navigation.mjsで現在の履歴の位置だけを更新する処理を追加。選択・入力・スクロール等は500ms単位にまとめ、ページ離脱や再読み込みキー、クリックによる移動直前には即時に記録する。ブラウザの自動スクロール復元との競合を避ける。
- 移動先の表示初期化後に元の位置を上書きしない。同一画面の履歴置換でも位置を維持する。復元中の記録を抑止し、位置保存に失敗しても編集を中断しない。
- 原稿は選択設定後に内部スクロールを復元。ノート・構想メモは入力欄と範囲・内部スクロール・画面内の位置を記録／復元する。ノートの動的な入力欄は分類・項目のIDで照合し、並び順の変更に対応。折り畳まれた入力欄は祖先のdetailsを開く。
- 構想メモの履歴復元ではresetScroll:falseを指定し、復元後に先頭へ戻さない。

位置情報に本文や入力値は含めない。既存の保存中・未保存・同期中の離脱保護を維持する。保存先の本文形式や同期処理は変更しない。
