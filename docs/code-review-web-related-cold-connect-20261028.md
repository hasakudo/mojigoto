# 接続直後・履歴復元時の関連作品候補欠落（2026-10-28）

## 原因

利用者から、クラウド切断状態から接続し原稿／ノートの関連作品プレビューを開くと作品名が候補に入らず、相手作品を開いてから戻ると表示されるとの報告。

HOMEの履歴から編集画面を復元するrestoreRecentViewは、作品一覧を空にしてrecentWorkCatalogPending=trueとし、保存済みの作品スナップショットで編集画面を復元する。全作品の検出は作品一覧へ戻るまで延期される。また高速初期復元では作品一覧が一時的に現在作品だけになる。一方、関連参照の両コントローラーは開いた時点のstate.worksをコピーし、それだけで関連先を照合していた。単に相手のノート本文が遅いのではなく、未取得・不完全なカタログで候補を確定する経路があった。相手作品を訪問すること自体は必要条件ではない。

## 修正

reference-work-catalog.mjsを追加し、作品一覧が未取得なら参照用に読み取り検出する。進行中の作品検出があればそのPromiseを共有し、取得済みなら現在のカタログを使う。候補解決は基本の作品検出完了を待ち、文字数・ノート数の詳細集計の完了は待たない。検出結果は参照コンテキストへ渡すだけで、selectedWork・state.works・編集対象・dirtyや画面を差し替えない。

履歴経由の参照用検出は同じprovider・利用者／クラウド／ルート・作品読込世代で共有し、失敗時は次回再試行できる。接続先や世代の変更後は古い検出結果を返さない。関連設定の保存済みID照合、重複ID・追加許可・読込失敗の扱い、ノート本文の読み取り専用処理は維持する。

原稿とノート両方に同じ候補解決を接続。確認中は既存の「関連作品を確認しています…」を表示し、取得完了後に候補へ追加する。プレビューや作品を開き直す操作は不要。通常のHOME表示・履歴の先行復元は維持し、参照を開くまでは新たな作品検出を開始しない。
