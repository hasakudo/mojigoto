# 関連設定の待機短縮・不明な関連整理・作品名表示（2026-10-28）

利用者が3クラウドの関連登録・解除とVS Codeへの設定反映を確認済み。Web1.0.251の基本動作は確認済みとする。新たに一覧表示・登録解除の待ち時間、削除済みと思われる3件の関連、一覧を開く前の作品名表示を要望。今回Web1.0.252／シェルv297へ更新。CSS1.0.194・拡張機能の版は変更なし。本番／テスト環境は未反映。

## 変更

- 保存後の全作品再探索・全設定再読込を省略。保存前に取得した最新候補と成功／失敗した両側の実際の保存結果で一覧を再構成し、完了直後から次の操作が可能になる。片側失敗時の再試行を維持。
- 保存前はルートを再確認するが、既知の作品カタログを探索へ渡し子・管理フォルダの重複探索を減らす。候補設定は対応providerのmetadata batchで確認し、失敗は個別取得へ戻す。
- 同じ利用者・クラウド・ルートのメモリ内で本文を保持し、毎回の最新メタデータのeTagと一致した場合だけ再利用。版なし・版変更なら本文を再取得。保存した最新版も反映する。接続スコープ変更で破棄し、永続キャッシュは追加しない。
- 作品設定の関連件数に作品名を併記。関連がある場合は一覧を開かず読み取り取得し、確認中の表示から作品名と不明件数へ更新。別作品・接続へ移動後は旧応答を反映しない。一覧を開く際は確認済み候補を先行表示し、最新確認中は操作を無効にする。
- 参照できない関連をIDごとに表示し、「この関連を整理」→対象と注意事項の確認→「この作品から解除する」で1件ずつ外す。権限不足・移動・ID重複もあり得るので削除済みと断定せず、自動削除・相手作品の更新は行わない。元作品が存在しない場合、IDから過去のタイトルは復元できない。
- 整理の直前も候補と現在設定を確認し、参照可能になったID・解除済みIDは処理せず、eTag競合は上書きしない。未知フィールド・他の関連・他作品設定を保持する。
- 「関連設定・作品候補取得」「関連設定・設定確認」「関連設定・保存全体」「関連設定・不明な関連解除」を計測。利用者の既存ログは通常作品一覧約11.8秒とOneDrive書込約2.1／2.7秒で、関連操作内訳がなかったため、反映後にこの計測で再評価する。実クラウドの短縮秒数は未計測。
