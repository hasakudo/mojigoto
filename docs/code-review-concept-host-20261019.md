# 3-C 構想メモのホスト受付・タイマー・終了処理（2026-10-19）

## 現在地と整理範囲

3-Bの編集保存・反映・表示は利用者実機確認済み。3-Cは実装・自動検証済み、利用者確認待ち。

- `concept-memo/host-actions.js`にメッセージ受付を分離。ホストから操作に必要なサービスとパネル情報を渡し、`currentData`・`saveQueue`・`autoSaveTimer`はsessionのアクセサーで最新値を共有する。初期値をコピーして古い状態へ戻す形にはしない。
- 元のホストにはタブ作成／再利用／復元、設定監視、共有データ取得と通知、保存キュー・同期・バックアップの既存処理を残す。
- `concept-memo/host-lifecycle.js`で自動保存タイマーと終了状態、安全な応答を管理。開いているタブの設定変更・操作受付と、再利用／他タブからの通知もこの応答経路へ寄せる。
- HTML/CSS・画面スクリプト、編集内容、リンク修正、パーサー、Webは変更しない。

## 点検で見つかった不具合と対応（単なる移動と区別）

- 終了後もタイマーが残り、閉じたWebviewへ保存完了・失敗の応答を送る経路があった。通常のタブ終了ではタイマーを解除して受け付け済みの待機自動保存を一度だけ実行する。すでに進行中の保存も完了させ、閉じた画面への応答を省く。
- 未保存のまま閉じることを確認した場合は、まだ待機中の自動保存を取り消す。確認をキャンセルした場合は待機保存を継続する。すでに開始した保存を取り消したり、保存済みの内容を巻き戻したりはしない。
- WebviewのpostMessageは同期例外・Promise拒否を処理し、破棄後は呼び出さない。設定購読は従来どおり終了時に解除する。
- 確認ダイアログやノート読込の待機中にタブを閉じた場合は、後から追加保存・画面更新を開始しない。閉じた後に届く新規メッセージも無視する。
- バックアップ前の保存など、一部ケースの例外が外へ漏れる経路は受付全体で捕捉し、開いている画面へ操作エラーを通知する。手動／自動保存の既存の専用エラー応答は維持する。
- すでに受け付けたバックアップ復元が終わった場合、元タブが閉じていても集計更新は実行する。
