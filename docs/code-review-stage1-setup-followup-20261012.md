# G:の初回セットアップ・監視・View追従の追加修正

確認日：2026-10-12。

## 原因

前回は作品切り替え本体に直接参照のフォールバックを追加したが、初回セットアップは `createJunction` を直接呼ぶままだった。この経路では同じEISDIRを捕捉できず、セットアップが完了しなかった。

さらに監視サーバーと文字数集計は、MultiモードでworkRootがあると、設定済みのmanuscriptRootより `_WORK/manuscript` を優先していた。作品切り替えが成功しても、監視対象が存在しない旧Viewパスとなり、報告された通知が出る経路が残っていた。

前回の検証は切り替えコマンドまでで、初回セットアップから監視・Viewへ追従する確認が不足していた。

## 修正

- 初回セットアップの既存作品選択、新規作品作成、Single→Multi移行に、切り替え本体と同じ直接参照のフォールバックを適用。
- セットアップ開始時に `_WORK/manuscript` を再帰削除しない。移行後の直接参照を旧Viewパスへ上書きしない。
- 存在しないリンクを先にmanuscriptRootへ設定する処理を除去。
- Single→Multi移行時も完了フラグと結果を返す。
- 監視サーバー、文字数集計、既存Viewツリーは共通の `getResolvedManuscriptRoot` を使用する。設定済みの実原稿フォルダが優先される。
- セットアップ完了後にView・集計を更新し、監視サーバーを再起動して新しい原稿フォルダへ切り替える。
- 自己診断と修復は、存在する直接参照の原稿フォルダを異常扱いせず、その設定を保持する。

## 検証

`setup-direct-root.test.js` に6件を追加した。実ディレクトリの原稿を使用し、リンク作成時にG:で報告されたEISDIRを発生させる。

1. 既存作品を選ぶ初回セットアップが成功し、完了フラグ・原稿保持・サーバー再起動・監視パスを確認。
2. 新規作品のセットアップが成功。
3. SingleからMultiへの移行が成功し、原稿と直接参照を保持。
4. 既存の `_WORK/manuscript` 内の実データを保持。
5. Viewツリーの実際のメソッドで、原稿と作品設定が選択作品へ追従。
6. 自己診断・修復後も直接参照を維持し、旧View原稿フォルダを作成しない。

全体は**420件すべて成功**。ログ：`.review-baseline/stage1-setup-followup-tests.log`。既存junction実機テストのため制限外で実行し、書き込み先はリポジトリ内の専用テストフォルダに限定した。

今回も利用者のG:作品の設定・原稿には書き込んでいない。2026-10-12、利用者からG:フォルダでVS Codeの表示・読み書き同期が成功したとの実機確認を受領した。初回セットアップ・移行の全組み合わせの確認まで完了したとは扱わない。

修正版VSIXを `release/mojigoto-1.0.68-gdrive-setup-fix.vsix` に作成する。既存のローカル作業ツリー全体を収録するため、前回までの修正も含む。同じ1.0.68の修正版であり、自動インストールやMarketplace公開は行わない。
