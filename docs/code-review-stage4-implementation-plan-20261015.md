## 1：別タブ表示

プレビューと全体ボードの近くに「別タブで開く」を置く。同じノート・同じ表示種別なら既存タブを表示する。既存の画面内表示も引き続き使える。

編集パネルが持つ下書きと保存状態をホストへ送り、ホストが登録済みの表示パネルへ渡す。識別は正規化したノートパス＋表示種別、通知の識別は編集セッションID＋単調増加の連番。表示準備完了後に最新スナップショットを送り、通常入力は100～200msでまとめる。別作品の内容や古い連番を表示へ混ぜない。

表示側は本文・ボードの描画と画像参照だけを共用し、編集・削除・保存・同期の操作は持たせない。画像URIは表示先のWebviewごとに変換する。全HTMLの再生成を避け、表示のスクロール位置を維持する。未保存の内容はVS Code再起動用に新しく永続化しない。

`notifyNoteUpdated`は保存済み更新の通知なので、下書きの通知とは区別する。`openNotePanelsByPath`の編集管理へ表示専用タブを混ぜず、削除・移動・終了時は両管理を対象にする。保存失敗後は下書きと警告を保持し、編集タブ終了後は「編集終了」と最後の保存状態を示す。作品切替では参照元を勝手に変えない。

呼び名一覧の別タブ導線は編集機能を伴うため、この表示専用タブとは別の小単位にする。既存の独立タブを再利用し、未保存のまま同じ内容を二重編集させない保存確認が必要。初期のプレビュー／ボード実装へ同時に含めない。

受入確認：自動保存OFFの追従、保存中の追加入力、画像、保存失敗、編集終了・再開、同じタブの再利用、別作品・ノートの分離、削除・移動、表示位置保持。左右配置と別ウィンドウへの移動はVS Code実機で確認する。

## 2：Web構想メモの常時一覧

既存の「一覧」ダイアログへ「一覧プレビューを常時表示」のON/OFFを追加する。初期OFF、同じブラウザの表示設定として保存する。広い画面では編集欄の横、狭い画面では開閉パネルで表示する。狭い画面へ変更してもONの設定を勝手にOFFへ書き換えない。実装時に既存のノートプレビューの幅条件と合わせて確認する。

表示内容はタイトル、TEXT／LIST／TODOの種別、本文または項目の先頭1～2行。選択中・未保存を示し、文章はtextContentで描画する。既存の編集用一覧と同じ対象・順序を使い、`state.conceptDocument`から作る。表示のたびにクラウドを再読込しない。

`openEditorList("concept")`の既存経路も含め、切替入口を`requestConceptMemoSwitch`へ揃える。現行`openConceptMemo`はdirtyを解除するため、確認なしの直接呼出しを追加しない。保存結果を明示して返すようにし、「保存して切替／保存せず切替／キャンセル」を扱う。同じメモなら何もしない。保存・同期中は切替を保留し、連打で並行実行しない。

保存後に追加入力・競合・反映先の未解決エラーが残った場合は元の画面を維持する。破棄を明示した場合だけ最後の保存済みスナップショットへ戻す。原本保存済みで付随処理だけ失敗した結果を「未保存」と混同しない。メモの削除・外部更新時も選択中の入力を勝手に消さない。

受入確認：ON/OFFの保持、広い／狭い表示、3種別の本文、同じ行の再選択、未保存3択、保存・同期中の連打、追加入力、競合、反映先失敗、削除、再読込。

## 3：テンプレート／Markdown読込と自動生成

利用者の意図は「Webで新規作成した原稿／ノートに、選んだファイルの内容を読み込む」。新規作成の画面または新規作成直後の空の編集画面に「ファイルから読み込む」を用意する。名前・保存先はWeb側の新規作成で選び、選択ファイルは内容の供給元として扱う。読み込んだ内容を確認して保存するまでは下書きとし、ファイル選択取消や解析失敗で既存内容を変更しない。明示的に空ファイルを作成済みの場合はその新規IDへ保存し、もう一つノートを作らない。

手数を減らす「ファイルから作成／Markdownから作成」も同じ解析・内容確認・保存処理へ接続できる補助導線とする。通常の新規作成から読める導線を優先し、毎回空ファイルの事前保存を必須にはしない。既存の非空ノートへの挿入・置換は別の後続機能。新規画面でも入力済みなら置換前に確認し、保存・同期中は読込を始めない。自動保存で読込直後の内容が確認前に確定しないよう、確認中は下書きとして扱う。原稿はUTF-8のtxt／mdを本文として、ノートは既存の大分類・区分・補足・項目・本文へ変換する。

ノート変換は`src/import/note-markdown-import.js`の`parseMarkdownImport`と`src/export/export-service.js`の`formatNoteMd`を照合し、純粋な変換処理を共有できる形へ分離する。先にコードフェンス内の見出しを構造と誤認する問題を修正し、VS Code既存インポートも回帰確認する。Webの保存先・ID採番・索引更新は既存の新規作成経路へ接続する。

通常Markdownは新しいノートとして作る。タイトルはファイル名から補い、`#`は大分類として扱う。独立ふりがな・画像・メモ・リンク・呼び名一覧を復元できると表示しない。元IDを新規ノートへ複製しない。選択・解析だけではクラウドへ作成せず、未許可・キャンセル時に空ファイルを残さない。作成成功後の索引失敗では作成済みIDを保持し、再試行で複製しない。

自動生成は[最新版Markdownの設計](web-note-latest-markdown-design-20261015.md)の通り、作品単位・初期OFF、ノートごとに固定パス1ファイルとする。`saveNoteFile`は既存のIDを維持して`writeStructuredFile`成功後に返すため、保存成功後の共通処理へ接続する候補とする。新規・コピー・インポート等の別保存経路も点検し、生成失敗を原本保存失敗として扱わない。元JSONのID・項目・画像等は変更しない。

保存先は作品の`.mojigoto/web-import/plots/`または`references/`、ファイル名は固定IDを候補とする。タイトルは専用メタデータに持ち、作品＋ノートの識別子・形式版・保存版の指紋で対応させる。任意ファイルへの上書きを防ぎ、同じノートの生成を直列化する。対応情報の保存形式は現行JSONの正規化で落ちないか確認してから決める。

初回の読込先が元JSONを許可済みなら原本を開く。未許可なら追加許可、または明示的な別コピー作成を選ぶ。以前に作ったコピーは対応情報から提示し、同じ元保存版は何もしない。コピー側も変更されている場合は黙って置換しない。Markdownから原本JSONへの自動的な双方向反映は含めない。

G:の保存置換後も同じDrive項目として許可を維持できるかは未検証。3bは確認用作品で通常更新・仮ファイル置換・改名・削除再作成を比べてから保存方式を確定する。専用生成物もPC側で作るなら初回許可は必要であり、「追加許可が不要になる」とは案内しない。

受入確認：UTF-8／BOM、ファイル選択取消、コードフェンス、基本構造と補完、同名、未許可、保存先消失、二重作成防止、生成ON/OFF、改名後の固定パス、生成失敗と再試行、元ノート削除、同じ版の再読込、両側変更、別作品。

### 将来の詳細項目の読込

項目メモ・関連リンク・独立ふりがなを扱うことは可能。現行Webデータにもmemo、relatedReferences、headingRubyの項目がある。ただし通常Markdownの手動書き出しで省いた情報を、読み込む側だけで復元することはできない。対応時は自動生成側と読込側を同じ形式版で拡張する。

- ふりがな：項目名とheadingRubyを専用メタデータに分けて保持し、本文に直接あるルビ記法も維持する。読込対応とWebのふりがな表示／編集対応を併せて確認する。
- 項目メモ：本文・種別・タグ等を保持する。別作品の構想メモIDや自動反映ONを無条件で複製しない。新規コピーは同期を勝手に開始せず、対応先を選ぶ仕組みを別途設ける。
- 関連リンク：新しい項目IDとの対応表を作り、同時に読み込む範囲内の参照だけ新IDへ置換する。別ノート・別作品の参照は存在と権限を確認し、確認できなければ未解決として案内する。タイトルの一致だけで別項目へ接続しない。
- 画像：メタデータだけでは画像本体を移せない。必要になればJSON＋画像のパッケージ形式を別途設計する。

第一候補は読みやすいMarkdown本文＋版付きの専用メタデータを持つ拡張形式。完全なノート複製が必要なら、現行ノートJSONを読み込む方式も比較する。どちらも解析・検証後に新規IDへ変換する層を共用し、実行可能なHTMLや外部リンク先を勝手に取得しない。初期版では基本構造だけを対象とするが、将来の形式判定・移行を追加できる境界を作る。
