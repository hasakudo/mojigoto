## Google Driveの許可・取り込みについての初期回答

Google Driveのdrive.fileはアプリ作成項目と利用者が選択して共有した項目を扱う。[Google公式のスコープ説明](https://developers.google.com/workspace/drive/api/guides/api-specific-auth)。以下は現行もじごとWebの利用範囲に関するコード上の整理で、Driveの権限を解除・データを削除する指示ではない。

| 項目 | 既存作品をWebで使う際の追加許可 | PC取り込みでの扱い |
|---|---|---|
| ExportRoot内の書き出し専用データ | Webで開かない場合は省略候補。原稿・作品データと重なる場所は一律対象外にしない | 除外を選べるとよい。フォルダ名だけで自動判定しない |
| .vscode | Web機能では使用していないので許可省略候補 | PC複製では設定を保持する。対応版VS Codeで、取り込み元に属するもじごとのパスだけを取り込み先へ更新 |
| _WORK | VS CodeのView用で、Webでは許可省略候補 | 取り込まず、事前作成もしない。原稿は各作品の正本を保持。G:は直接参照 |
| .mojigoto/trash | 現行WebはVS Codeのゴミ箱復元を提供しないため省略候補 | VS Codeで復元できるデータを含む。任意除外は説明し、自動で削除しない |
| .mojigoto/note-images | 現行Webは画像メタデータを保持するが画像ファイルの表示／編集経路は未提供。文字編集だけなら許可省略候補 | VS Codeのノート画像に必要。取り込まない場合は画像が欠けるため、一律除外しない |
| .mojigoto/templates | 現行Webにテンプレート読込機能がないため省略候補 | VS Codeの再利用データ。新機能を追加したら許可要件も更新する |
| .git、ローカル設定・生成物等 | Web作品編集で使わないものは省略候補 | 資格情報・設定を含み得るため、取り込み前の対象確認と除外方針を優先する。実際の利用者データは今回読んでいない |
| backups/index.json・snapshots | Webで履歴表示・比較・復元を使うなら必要 | 履歴を引き継ぐため保持 |
| 原稿、plots／references、work.json／singleWork.json、concept-memos.json | 使用するデータと保存先フォルダを許可 | 作品の正本として保持 |
| notes-index.json、work-metrics.json、web-writing-events.json | 索引・共有集計・執筆記録の機能を使うなら必要 | 更新・取り込み機能を引き継ぐため保持 |

件数の増加とファイル作成は別。すでに許可済みのconcept-memos.jsonに0件→1件のメモを保存するだけなら、その件数変化を理由とする追加許可は不要。初めてそのファイルを作成、削除して再作成、PC同期で別項目になった場合は追加許可の対象となる。ノートは1画面に対応するJSONファイルごと。新規のフォルダも対象になる。

Webで保存先フォルダを許可して新しい原稿／ノートを作り、その内容をローカルファイルから読む案は実装可能。アプリ作成ファイルはdrive.fileの対象になるため、PC側で新規作成して追加許可する手間を減らせる。既存の保存先・既存の構想メモ・画像等の許可を全部不要にするものではない。

ルートの単純な名前変更は、既存の項目IDを使う更新と考えられる。Drive APIは[fileIdを指定してメタデータを更新](https://developers.google.com/workspace/drive/api/reference/rest/v3/files/update)する。もじごとは根フォルダをIDで登録しているため、最新名の再取得・復元手順を整備する。G:での改名に伴うVS Codeの絶対パス更新・再作成との区別は実機確認が必要。
