# 構想メモ全体の検索・置換と一覧メニュー（2026-10-29）

## 変更

利用者は1件の検索・置換動作に問題なしと確認したうえで、本文の短い構想メモは全メモ横断の検索・置換が適していると要望。対象を「開いている作品の全構想メモ」へ変更し、入口を一覧の歯車へ移動した。バックアップ（全メモ）も同じメニューへ収めた。ノート・原稿の検索範囲は変更しない。

## 対象と操作

- 一覧の検索・フォルダ・タグ・保管状態・ページの絞り込みに関係なく、その作品の全メモのタイトルと本文を検索する。タグ自体・出典・同期情報・別作品は対象外。
- 結果にメモ名、タイトル／本文、行・文字位置を表示。結果から該当メモを開き文字選択する。未保存置換があれば既存の保存・破棄・キャンセル選択を経由し、同期等で本文が変化した場合は古い選択位置を適用しない。
- 複数メモを選択して一括置換し、保存後も同じ一覧セッションなら直前の一括操作を戻せる。1フィールドが後から編集された場合は取り消し全体を拒否。別フィールドや同期メタ情報は保持する。メモを開く・再読込・scopeや型／行構造の変更で履歴を破棄。
- リスト・TODOの行構造とチェック記号、タイトル改行、ルビ・傍点の保護範囲を変える置換は適用前に止める。不正な変更を含む一括操作は一部も適用しない。
- 一覧に保存状態と保存ボタンを表示し、自動保存設定ONなら従来の予約保存を使う。自動保存OFFでは一覧で保存する。

## 保存・反映の境界

concept-search-controllerは全メモを一時的な検索用groupへ対応付け、実データに戻すのは変更したタイトル・本文だけ。実ドキュメント内の行ID・完了状態・未知フィールドを保持する。

concept-batch-saveは変更したメモIDを記録する。まず共有JSONを既存の条件付き保存とバックアップ経路で保存し、その後、変更した全メモについて既存の自動同期判定を順番に実行する。非表示の編集欄を同期対象に合わせ、保存・同期中は一覧移動を抑止する。同期情報の内部保存はskipSyncで再帰を防ぐ。

本文保存失敗では全変更を未保存のまま保持し反映を始めない。あるメモの反映失敗・競合はメモ名付き通知と「保存済み・反映未完了」で表示し、他メモの処理を続ける。再試行は失敗した対象だけ。同期情報が未保存になったときは後続処理を止める。別作品・破棄後の異なる保存基準には古いキューを使わない。個別メモを開くと一括キューを終了し、そのメモの通常同期操作に戻す。
