# 復元タブの再利用とHOME履歴のスクロール（2026-10-19）

利用者がインポートの追補を確認済み。次の章単位書き出しへ進む前に、再起動・再読み込み後のタブ重複と、クラウド接続前HOMEで履歴の全体を見られない点を修正した。

## VS Code

- 背景のWebviewタブは、タブ自体が存在しても選択するまでシリアライザーが呼ばれず、拡張内のMapには登録されないことがある。またノート・構想メモはディスク読込の後で登録するため、その途中で開く操作が入ると新規タブを作れた。
- 共通の復元調停を追加。シリアライザー登録時点の既存タブを控え、通常の開く操作ではその種類の復元・登録を待つ。必要な背景タブを既存エディターの選択コマンドで復元し、タイトルではなく復元したファイルの登録を使う。同名の別作品を取り違えず、連続した開く操作も直列化する。
- ノート編集、表示専用プレビュー／ボード、構想メモ、Dashboard、縦書きプレビューへ適用。呼び名一覧・作品設定にも復元用の保存先情報とシリアライザーを追加。状態のない旧タブは閉じて通常の入口から開き直す。
- ノート・構想メモの再利用は相対パス・Windowsの大文字小文字を正規化。表示タブ・呼び名一覧・構想メモは古いパネルの終了で新しい登録を消さないようにした。
- 作品設定は再表示のためだけにHTMLを再生成せず、入力中の状態を保持。復元する保存先が現在のモードと一致しない場合はその古いタブを復元しない。
- 背景タブの復元のため初回の開く操作で一時的にタブ選択が切り替わる場合がある。操作失敗・復元待ちのタイムアウトでは新規作成へ進めず、元タブを閉じない。初回復元中のVS Code実機操作は利用者確認が必要。
- API挙動を確認した一次資料：[VS CodeのWebviewシリアライザー実装](https://github.com/microsoft/vscode/blob/main/src/vs/workbench/api/browser/mainThreadWebviewPanels.ts)、[既存エディターの選択コマンド](https://github.com/microsoft/vscode/blob/main/src/vs/workbench/browser/parts/editor/editorCommands.ts)。
