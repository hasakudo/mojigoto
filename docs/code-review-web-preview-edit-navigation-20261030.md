# 全体プレビュー：表示設定の配置と原稿への編集導線（2026-10-30）

Web1.0.270／シェルv315／共有CSS1.0.207。本番・テスト環境への反映と実クラウド・Android実機の新機能確認は未実施。

## 変更

表示設定パネルを左寄せにし、表示設定ボタンの近くへ配置。右上の閉じるボタンの直下を避け、幅も閉じるボタンへ寄りすぎない範囲にした。

全体プレビューの上部に「編集」を追加。現在の表示位置から原稿を判定する。最後に読み込んだ原稿だけで判断せず、保持されている前の原稿へスクロールして戻った場合も見えている原稿を対象にする。取得エラーなどで本文の位置が得られない場合は選択中の原稿を使う。

- 原稿一覧から開いた場合：対象原稿の現在のメタデータと本文を取得して編集画面を開く。
- 原稿編集画面から開き、同じ原稿を選んだ場合：プレビューを閉じて編集へ戻る。未保存内容・カーソルを保持し、再読込や保存をしない。
- 別原稿を選び、現在の原稿が未保存の場合：通常の保存処理を実行し、未保存・競合が残らず、保存基準が現在の入力と一致することを確認してから移る。手動保存の版確認・執筆記録・バックアップの経路を維持する。
- 保存失敗・競合・対象の移動／削除・権限不足・本文取得失敗では、原稿を切り替えず状態をプレビュー内に表示する。既に保存中などの場合は完了後の再操作を案内する。

## 保護と経路

preview-manuscript-navigation.mjsへ保存と遷移を分離。目次の階層から章とtrailを求め、対象ファイル・原稿ルート・章のメタデータでIDと親子関係を確認する。本文はプレビューのキャッシュを編集の最新版として流用せず、現在のクラウド内容を取得する。同じ原稿に戻る場合だけ入力をそのまま使う。

遷移中は二重操作・自動保存の予約・外部確認の干渉を抑える。保存や通信を待つ間に閉じる・作品変更・利用者変更・別のファイル読込・元入力の変更があれば、遅い応答で遷移しない。元の原稿の保存が済んでから対象の取得に失敗した場合は、元原稿は保存済みのまま編集画面を維持する。

manuscript-load.mjsは読込が成功して現在の編集状態が一致してから章とtrailを適用し、正しい履歴・一覧へ戻れるようにする。保存・移動に失敗した場合にフォルダだけ切り替えない。編集中の行へのジャンプは追加しておらず、別原稿は通常の編集画面の先頭から開く。

## 検証

新規7件を含む全1,828テスト成功。階層、同じ原稿、保存順、失敗・競合・保存中、入力／作品変更／閉じる、移動・削除・本文失敗、二重操作を確認。ガイドも編集導線と保存条件を説明するよう同期した。

実クラウドを使わない仮データのブラウザで確認した。

- 未保存の原稿を1回保存した後、プレビューの小章本文を編集で開いた。currentFolder=chapter-sub、trail=chapter-a／chapter-sub、dirty=false。
- 保存失敗ではプレビューに理由が表示され、元原稿qa-fileの未保存入力を保持。同じ原稿へ戻る操作では追加の保存はなく、入力を保持した。
- 最後に読み込んだ原稿が別の原稿でも、保持範囲の先頭へスクロールして戻り「編集」を実行すると、表示中のnestedを開いた。
- 406px幅で設定パネルの左右は13.5〜327.5px、閉じるボタンは340.4〜377.5px。パネルを左寄せし、閉じるの直下へ重ならない。

仮の保存成功テストでは執筆記録の新規作成を禁止した検証providerの通知が出た。本文保存・章移動の成功は確認したが、実クラウドへの執筆記録・バックアップ書込の再検証を行ったものではない。iframeでは一部クリックがツールの座標取得で失敗したため、キーボード操作も使って確認した。

## 実機確認

1. 表示設定の位置と、開閉時の押し間違いが減るか確認。
2. 一覧から全体プレビューを開き「編集」で正しい原稿・章へ移るか確認。
3. 原稿を未保存にして別原稿の「編集」を押し、保存後に移ることと、元原稿を開き直した内容を確認。同じ原稿に戻る場合の未保存内容保持も確認。
4. 前の原稿へスクロールして戻ってから「編集」、複数の章・3クラウドも確認。保存失敗や競合が出た場合は、元原稿を保ち移動していないことを確認。
