## 復元パネル

復元の保存・画面反映後に履歴の再取得をawaitしており、履歴側の遅延で復元のロック・ボタンが解除されない経路があった。保存完了と履歴更新を分離し、復元済みを表示してロック・ボタンを解除する。履歴の取得が終わらない場合も「復元しました。履歴を更新しています」と区別できる。取得失敗時は復元済みを維持し、履歴更新の失敗を案内する。作成・保護変更も同様に履歴取得を保存完了の条件にしない。

dialogの最前面に通知専用領域を置いた。成功・警告をパネル内に表示し、警告は後続の成功通知で消さず、「閉じる」で消せる。一般の通知をパネル内へも表示するため、復元後の執筆記録保存失敗も隠れない。履歴の遅れた応答が別作品・別対象・新しい取得結果を置き換えないよう取得世代と対象も確認する。

実機で止まった通信箇所のログは取得していない。今回の修正はコード上の履歴待ち経路とUI表示の再現テストに基づく。復元の本体保存前の通信自体が停止する場合まで解決済みとはしない。

## 移行後の管理フォルダ

従来の移行は原稿・plots・references・作品設定のみで、構想メモ・画像・バックアップ等が元の.mojigotoに残る経路があった。新しい移行では以下も作品フォルダ内へ移す。

- concept-memos.json、address-book.json、note-images
- backups、trash
- notes-index.json、work-metrics.json、web-writing-events.json
- manuscript-display-names.json

元のSingle設定をwork.jsonに変換する際に未知の設定項目も保持する。破損したSingle設定では移行前に停止する。移動先にデータがある場合は削除して置き換えず、両方を保持して停止する。

直下の.mojigotoはMultiでも共通TODO・共通テンプレートに使うため、一律に不要ではない。共通データと未知ファイルは保持し、空になった場合だけrmdirで整理する。workRootを別の場所に変える場合は共通TODOも新しい共通保存先へ移す。移行先に共通TODOがある場合は移行開始前に停止し、両方を保護する。共通テンプレートはワークスペース直下の保存先を維持する。

VS Codeの移行選択画面と完了通知・ガイドで共通用／作品用を説明する。Google Drive専用ページにはSingle／Multiの階層見本を追加し、作品設定・ノート・構想メモ・履歴・執筆記録の位置と_WORKの役割を示した。独立Webガイドからも見本へ移動できる。

以前の版ですでに移行した利用者のG:は変更していない。既存の直下.mojigotoは丸ごと削除・上書き統合せず、各ファイルの内容と現在の作品データを比較してから整理する。新しい移行処理は複数のファイル移動をまとめた単一トランザクションではなく、途中のI/O失敗で一部が移動済みになる可能性が残る。ゴミ箱内や未知ファイルに記録された旧絶対パスの変換は今回未検証。
