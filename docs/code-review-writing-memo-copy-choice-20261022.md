# 執筆メモから構想メモへの反映方法の選択（2026-10-22）

## 変更

従来は操作のたびに構想メモを新規作成していた。利用者の要望で、同じ出典の反映先がある場合に既存更新／新規作成を選ぶ機能を追加した。コード整理とは別の動作改善として扱う。

- ボタン名を「構想メモへ反映」に変更。初回は従来どおり新規作成し、反映先がある場合は「既存を更新／新しく作成」を選ぶ。取消では保存しない。
- 既存コピーが複数あれば更新先をタイトル・本文の抜粋から選択する。既存の重複を自動で削除・統合しない。
- 新しいコピーは、執筆メモIDと保存元のwriting-memosパスを出典として保持。保存元が同じなら原稿名が変わっても同じ反映先を候補にする。従来コピーは保存元情報を持たないため、同じIDと原稿パスに限って候補にし、更新時に明示確認する。
- 更新はID、作成日時、タグ、フォルダ、ピン、保管、Dashboard表示、並び順・未知項目を保持し、形式・タイトル・本文を反映する。形式はテキストへ置き換え、リスト／TODOの内容は空にする。形式を変更したコピーも上書き前の確認対象。
- 出典に反映時の内容指紋を保存し、構想メモ側で形式・タイトル・本文・リスト内容が変わっていた場合だけ追加確認。現在と反映後の内容を一部表示する。古いコピーなど指紋がない場合も確認する。配置やタグだけを変更した場合は追加の上書き確認を挟まない。
- 選択・確認後はストアを再読込し、他メモの追加等を保つ。選んだメモ自身が変更・削除されていれば中止する。最新のstorageRevisionを既存の競合検出付き書込みへ渡し、再読込後の競合も上書きしない。
- 同じ保存先への反映をコントローラー内で直列化。連打した2回目は最初の作成後に候補を確認する。初回作成中に外部から反映先が増えていた場合も重複追加を中止する。
- コピー元の執筆メモは変更せず、編集中の本文を反映に使う。保存完了→構想メモの更新通知→成功通知を維持。構想メモの既存の未保存内容保護も変更しない。
