# 作り直したノートの上書き取込とGoogle再接続（2026-10-17）

取込の主目的は、VS Codeで新規作成・作り直したJSONをWebで追加許可する手間を減らし、Markdownから内容を持ち込むこと。すでに同じ原本JSONを両方で共有している場合は通常の同期が働くため、それを別々に編集して再取込の検証をする必要はない。

## 操作の意味

| 操作 | 結果 |
|---|---|
| 原本を開く | Webで読める既存の原本JSONを開く。Markdownを取り込んで上書きする動作ではない |
| 新しいコピーを作成 | Markdownの分類・区分・補足・項目・本文から別ノートを作成。元のJSONの完全な複製ではない |
| 既存ノートに上書き（今回追加） | 明示的に選んだノートを、作り直したMarkdownの内容に置き換える。元と対象のIDが違っていても選べる |

上書きは対象の選択、比較、確認チェックを経て「バックアップして上書き」で実行する。対象のノート名・ノートID・種類・並び順を維持し、構成・本文を置き換える。Markdownにない項目メモ・画像参照・関連リンク・呼び名表などは引き継がないことを画面上に明記した。画像ファイル自体を削除する処理は行わない。

上書き前のJSON全体を既存のバックアップ機能へ保存する。バックアップできない場合は対象を変更しない。理由 `before-import` をWeb／VS Code両方で保持し、「取込上書き前」と表示する。自動バックアップOFFでも実施する。

比較時点と実行直前の内容が違う場合、バックアップ中に対象が更新された場合、条件付き保存で競合した場合、未保存・保存／同期中・作品切替は停止する。他ノートから参照される項目を消す変更も停止する。既存の自動対応先反映では引き続き両側変更を停止し、今回の明示した置換では退避後に進める。

元の項目IDや有効な読込対応が確認できる部分はIDを引き継ぐ。作り直しで対応情報が合わなくなっていても、上書き候補の表示自体は止めない。新しい生成元へ対応を付け直す場合も、同じ生成元の別コピーを二重登録しない。

## 再接続

編集画面の再接続案内を、右下の枠付きパネルへ移した。操作ヘッダーと位置を分け、見出し・読みやすい本文・幅のある再接続ボタンで表示する。狭い画面では下部メニューや入力補助・キーボード位置を考慮する。スクロールバーのある画面でも左右が切れない幅にした。

HOMEへ戻ったときも認証の期限を反映する。期限切れ／更新時期には接続済みボタンを再接続可能な表示にし、スマホでも接続操作欄を隠さない。再接続が必要な間は追加許可の案内を隠し、認証と許可の操作を混同しにくくする。接続後は通常の追加許可の表示へ戻す。

HOMEの再接続も既存の認証更新を直接呼び、作品一覧を更新する。Google専用ページ・Picker・「選択待ちフォルダ」へ移動しない。編集画面では入力内容・保存基準・選択中のノートを保持し、再接続成功後に監視／自動保存を再開する。失敗・キャンセル時は入力を保持する。HOMEに編集用の浮動案内は出さず、接続パネルから操作する。
