## 変更

### 確認済みの作成時刻

automatic-backup-window.mjsを追加し、クラウド索引で確認した自動履歴の作成時刻、または今回の本文・索引保存が成功した自動履歴の作成時刻をsessionStorageへ記録する。再読み込み後も、同じタブの保存間隔内では管理一覧・保存先一覧・索引読込を省略する。記録は時刻と形式版だけで、本文・索引・eTagは保存しない。

キーは利用者、クラウド、作品ルートとdriveId、作品管理フォルダとdriveId、対象種別、対象パスで分離。キーにある対象パスは端末内の区分にのみ使い、計測へ含めない。保存間隔は実際の作成時刻から数え、再確認で延長しない。作成失敗・索引保存失敗・不正値・未来時刻を確認済みとして使わない。sessionStorageが使えない場合は従来のクラウド確認へ戻る。

手動バックアップはこの記録で省略しない。作成間隔が過ぎた場合も最新の保存先と索引を取得する。間隔内の自動処理は索引の外部変更を再確認しないため、別クライアントで履歴を削除した場合も次の間隔までは再作成しない。確認済みの履歴がある間は再作成しないという自動間隔の扱いであり、実データの同期本文をキャッシュする変更ではない。

既存の段階別計測にresult=confirmed-intervalを追加。再利用により通信を省略した場合に表示する。この場合は索引を読んでいないためindexEntriesは未取得としてnullにし、コピー表示には件数を出さない。通常のintervalは今回クラウド索引を読んで間隔内と判定した結果。

### 同時一覧取得

OneDriveProviderで、同じ接続インスタンス・同じフォルダの実行中のlistChildrenだけを共有する。全ページの取得とエラーを共有し、呼出元にはそれぞれ複製した結果を返す。完了した一覧は保持せず、次回要求は必ず新しく取得する。失敗した要求も保持しない。異なるフォルダ・接続インスタンスは共有しない。

これにより、項目メモ本文保存後にバックアップと構想反映が同じ管理フォルダを同時に調べる重複をまとめる。最新本文の取得・保存前の版確認・If-Matchを使った条件付き保存・競合停止は維持する。構想→項目の同期情報書込は今回変更していない。
