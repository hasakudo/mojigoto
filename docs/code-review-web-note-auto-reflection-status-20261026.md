# ノート自動反映中の表示・画面移動保護（2026-10-26）

## 報告と原因

利用者から、ノートから構想メモへの手動反映には反映中表示がある一方、自動反映ではノート保存後に完了したように見え、移動すると通信失敗になるとの報告を受領した。整理2-A3の確認中に見つかった機能修正として扱う。

ノート保存は本体保存のfinallyでstate.savingを解除した後、自動反映を実行していた。その区間にはstate.syncingが設定されず、共通の画面移動抑止、beforeunloadの警告条件、自動保存と外部監視の抑止条件から外れていた。表示もノート本体の保存済みのままだった。前段の4関数分離時には処理本体を変更しておらず、今回この動作を修正した。

## 修正

- 自動反映対象のリンク済み項目があるとき、反映先の一覧取得から読込・条件付き書込の完了までstate.syncingと専用のnoteConceptSyncPendingを保持する。
- ステータスを「構想メモへ反映中…」にし、保存ボタンを無効にする。アプリ内の画面移動を共通ガードで止め、「反映が終わってから移動してください」と通知する。ページ離脱も既存のbeforeunloadの警告条件に含まれる。ブラウザが離脱確認を表示するかはブラウザの制御に従い、利用者が離脱を強行する場合まで保証するものではない。
- 反映中も編集は可能。追記した場合は「反映中・未保存あり」を表示し、送信中の本文には混ぜない。終了後は未保存表示へ戻し、自動保存を再予約する。
- 自動反映中はskipConceptSync指定の保存も止め、手動反映用の保存が並行して割り込まないようにする。手動反映自体の既存の保存順序は維持する。
- 正常完了後に保存済みへ戻す。競合時は同期競合表示を維持し、通信失敗時は「ノート保存済み・反映失敗」を表示して通知する。ノート本体の保存成功を取り消さない。finallyで反映中フラグと同期中フラグを必ず解除する。
- 自動反映OFF、未連携、個別反映OFFの場合は反映中表示や追加通信を行わない。保存形式・条件付き書込・同期方向の判定は変更しない。

- 完了後に保護を解除する。ノートが保存済みで反映だけ失敗した場合の状態・表示を区別する。
- 反映中の追記は送信内容へ混ぜず、表示と下書きを保持する。終了後の保存予約、反映中の重複保存抑止も確認した。
