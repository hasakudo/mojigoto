## 全体設定の範囲・個別設定の互換性

- 全体の範囲は、接続中の作品ルート内の全作品。同じブラウザ内でも利用者・クラウド・作品ルートごとに分離し、localStorageへ保存する。別の端末・ブラウザへ全体設定を同期する機能ではない。
- VS CodeのWorkspace設定に対応するWeb側の既定として扱う。既存のVS Code用設定ファイルを書き換えない。
- 個別例外はVS Codeと共通のautoSyncToConceptMemoOverride／autoSyncToNoteItemOverrideを使用する。例外のtrue／falseを優先し、旧形式のtrueも維持し、それ以外は全体の既定へ従う。判定はVS Codeの実装と組合せ照合した。
- 全体OFFでも個別ONは有効。すべてを強制停止するスイッチではないことをUIとガイドで説明する。
- 方向ごとに初回設定を完了するまで、その方向は従来の端末側許可と個別ONで動作し、勝手に初回作成を始めない。初回設定前のチェック表示は未設定のためOFF。
- 設定が壊れている・利用者や接続先が確認中に変わる場合は、全体ONへ進めない。

## 初回ONと既存メモ

初回ON時に次の選択を表示し、選択確定まで実際の全体設定はOFFのまま。キャンセルで変更しない。同方向で確認済みなら再質問しない。

1. 既存メモにも適用：未指定の既存・新規メモが全体の既定へ従う。個別例外を一括で消さず、設定変更だけで過去のメモを反映しない。次の通常保存から適用する。
2. 今後のメモだけ：接続中ルート内の読み込める既存メモを列挙し、未指定だけに個別OFFを保存した後、全体をONにする。既存の個別ON／OFF・旧形式のON・本文・未知項目を保持する。
3. キャンセル。

「今後のメモだけ」は、未保存の編集があれば保存を案内して中止する。全メモの列挙・読込・形式・版を確認してから、版を条件に順に書き込む。読込失敗・壊れたJSON・版不明・競合では全体ONにしない。途中まで個別OFFを保存して停止した場合は、その件数を通知する。書込済みの個別OFFは残り、自動巻き戻しは行わない。再試行は最新状態を読み直す。

## 保存時の初回作成・連携

- 項目メモ→構想メモが有効で、未連携かつ本文またはタグがある項目を対象にする。空欄だけの項目や個別OFFは作成しない。連携済みの空欄への変更は従来どおり反映対象。
- 最初にノート本体を保存し、構想メモの最新文書を取得する。出典の項目IDとパスを照合し、既存の構想メモがあれば再利用する。
- 構想メモの作成・反映に成功した後だけ、保存済みノートのスナップショットへリンク情報を付けて保存する。反映先とリンク情報の保存の双方で版を確認する。
- 二つ目のノート保存に失敗しても、リンク情報を下書きへ残す。次回は出典から既存メモを再利用し、重複作成しない。同期情報の保存失敗を自動で無限再試行しない。
- 通信中の追記はリンク保存用スナップショットへ混ぜない。現在の入力を保持し、反映終了後に未保存として自動保存を予約し直す。
- 重複項目ID、版不明、反映先の競合、両側変更は停止する。反映中の表示・アプリ内の移動抑止・ページ離脱の警告条件を維持した。
- 出典のない独立した構想メモについて、反映先ノートを勝手に選んで作成する処理は追加しない。
- Google Driveで構想ファイルを一覧から確認できない場合は、既存の重複防止方針を維持して自動作成せず、追加許可を案内する。構想ファイル自体がまだない場合は、従来の初回ファイル作成手順が必要。OneDrive／Dropboxではファイル自体がない場合もプロバイダーの競合保護付き作成を使用する。
