# 執筆メモ一覧の参照先表示（2026-10-22）

## 問題と変更

作品別の執筆メモ一覧は、作成／付け替え時に保存した`targetLocation`をそのまま「View側／作品元側」と表示していた。Viewで作成したメモは過去の作品でもView側と表示され、現在解決されている参照先と区別しづらかった。

- Multiの作品別一覧で、既存の解決処理が決定した原稿の絶対パスを現在のView原稿フォルダ・各作品の原稿フォルダと比較し、表示用`resolvedLocationLabel`を組み立てる。
- View配下は「View側」、作品元配下は「作品元側」、原稿を解決できない場合は「参照先不明」、既知の原稿フォルダに分類できない解決先は「参照先未確認」。フォルダが入れ子の場合は最も具体的な一致を採用し、同じ長さならViewを優先する。
- Windowsの大文字小文字・区切り・正規化を扱い、似た接頭辞の隣接フォルダを配下と誤認しない。分類処理は`writing-memo-location.js`に置き、追加のファイル走査は行わない。
- バッジは表示用の値を優先し、ホバーには「現在の参照先」を表示する。作品見出しの「View連携中」は従来どおり現在の作品との連携状態を示す。
- 保存されている`targetLocation`、実際の参照先を決める処理、ジャンプ用のメッセージ情報は保持する。保存データの移行や自動の再関連付けは行わない。ファイル単位の表示とSingleの既存表示は維持する。
- 5-B2の編集保存は利用者確認済み。今回の変更はコード分離とは別の表示改善として記録する。
