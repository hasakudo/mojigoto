# 項目メモと構想メモのリンク不整合（2026-10-19）

## 利用者の報告と範囲

VS Codeで、項目メモが作り直されたと思われる状態で、古い構想メモと新しい構想メモが同じ項目を参照し、リンク切れの表示も食い違うとの報告。クリアボタンか本文削除かは不明。利用者の実作品ファイルを直接調査・更新していないため、そのデータでの発生経路は断定しない。コード整理3-Bには進まず、確認できた再発経路を個別の不具合修正として扱った。

## 確認できた問題と修正

- ノートの「クリア」は旧リンクIDと個別の自動反映ON指定を残していた。`script-groups.js`で旧IDを通知用に退避してから、リンクを空にし個別自動反映もOFFにして保存する。構想メモ本文は削除しない。
- `createConceptMemoFromNoteItem`は同一のノート／大分類／項目のアドレスに一致すると、現在のリンクIDより先に古い構想を選べた。現在の逆リンクを優先し、明示したリンクIDがある場合に別IDへフォールバックしない。クリア済み／リンク切れの構想をノートからの反映で自動復活・上書きしない。
- 構想の表示状態は保存されていたsource.statusを読むだけだった。`concept-source-status.js`で参照ノートを読み、項目・逆リンクと照合する。ノートの現在リンクが別IDなら古い参照をmissing、正しい逆リンクがあるのにmissingだった参照はactive、空の項目メモはclearedとする。明示的な複数リンクは維持する。
- この照合は同じノートの読取をキャッシュし、本文やノートファイルを書き換えない。権限・JSON解析エラーをリンク消失と決めつけない。逆リンクがない旧形式データは、本文一致などで勝手に接続先を推測しない。すでにclearedの参照を内容の再入力だけで自動復活させない。逆リンクがある通常の本文編集では、一時的に本文を空にしても接続を解除しない。
- 構想→項目の自動反映はmissingに加えてclearedも対象外。利用者が構想から明示的に手動反映したときだけ、ホストと画面の状態をactiveへ戻して保存する。

既存のメモを自動削除・統合しない。二つのメモが両方ともノートの逆リンクに登録されている場合は、意図した複数リンクとの区別ができないため、その登録を勝手に削除しない。保存時の競合検出は維持する。Webソースは変更していない。
