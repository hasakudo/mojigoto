## V02：VS Codeのノートを別タブで表示

追加対象：ノート内の呼び名一覧を既存の独立タブへ開く導線も検討する。呼び名一覧のサイズ統一は[表示修正](code-review-layout-followup-20261015.md)で対応したが、編集可能な呼び名一覧を複数開く際の保存待ち・同時編集とパネル再利用は、表示専用プレビューとは分けて設計する。

### 操作

- 現在のプレビューと全画面ボードは残し、各表示の近くに「別タブで開く」を追加する。
- 同じノート・同じ表示種別のタブが開いていれば再利用する。編集タブとは別の表示専用タブにする。
- 別タブは通常のVS Codeのタブ移動で左右へ配置できる。別ウィンドウへの切り離しはVS Codeの機能・実行版に依存するため、拡張独自のウィンドウ生成を初期版には入れない。
- ボードの「別タブ」は、そのタブ内でボードを広く表示する意味。OSの全画面表示を自動で切り替えない。

### 表示する内容と終了時

初期版は**編集中の内容も追従する表示専用タブ**を推奨仕様とする。自動保存OFFでもプレビューと本文の内容がずれず、別タブを開くための保存操作を増やさない。

| 状態 | 表示専用タブの扱い |
|---|---|
| 編集中 | 入力をまとめて短い間隔で最新スナップショットを送る。「未保存」を表示する |
| 保存成功 | 保存済み状態を通知。保存中の追加入力があれば最新の下書きを維持する |
| 保存失敗・外部更新の競合 | 編集側の下書きと警告状態を表示。勝手に保存済みデータへ戻さない |
| 別タブを閉じる | 表示だけを閉じる。保存や編集側の終了を発生させない |
| 編集タブを閉じる | 編集側の既存の未保存確認を優先。表示側は最後の表示を保持し、編集終了／保存済みか未保存かを明示する |
| 編集を再開する | 同じノートの編集タブへ接続し直す。古い表示側データを編集へ書き戻さない |
| 作品切替 | 開いている表示は元のノートを参照し続ける。作品名・ノート名を常に示す |
| 元ノート／作品の削除・移動 | 既存の終了処理に表示タブも含める。失敗時は元の場所を確認できないと表示し、再作成しない |
| VS Code再起動 | 復元できるのは保存済みデータ。編集中スナップショットを永続的に保存しない |

### 実装境界

現在の`src/views/note-webview.js`はノートごとの編集パネルを管理し、`notifyNoteUpdated`で保存済み内容を編集パネルへ渡す。現在のプレビュー・ボードは同じWebview内の編集中stateを使う。保存済み通知だけを別タブへ流用すると未保存入力を表示できないため、新しい下書き通知経路が必要。

- 編集側が内容と保存状態の唯一の供給元。表示側には編集・保存・削除・同期のハンドラーを持たせない。
- パネル管理を編集と表示で分け、表示は正規化したノートのファイルパス＋表示種別で識別する。作品削除時の終了対象から漏らさない。
- メッセージは`noteView.snapshot`（セッションID、連番、ノート内容、保存状態、表示種別）と`noteView.sourceState`を軸にする。ホストが登録した編集元と接続先を照合し、古いセッション／連番のメッセージは採用しない。
- 表示が準備できた通知後に最新内容を送る。入力通知は100～200ms程度でまとめ、保存・初回表示・表示再開は待たせない。実装時にノート規模を変えて調整する。
- 本文描画・ボード描画を既存から切り出して共用し、巨大な編集用スクリプトを表示タブへ丸ごと埋め込まない。
- 画像URIは表示先Webviewごとにホストで変換する。編集用URIの文字列やDOMをそのまま転送しない。許可するローカル画像の範囲も既存ルールを維持する。
- スクロールや表示設定は表示タブ側で保持し、内容更新のたびにHTML全体を作り直さない。保存設定の変更やノートのJSON形式は追加しない。

受入確認：保存前の入力追従、自動保存OFF、保存中追加入力、外部更新競合、画像、タブ再利用、別表示のスクロール保持、編集終了・再開、作品切替・削除、再起動を確認する。別ウィンドウでの操作はVS Code実機で確かめる。

## W08：Web構想メモの一覧プレビュー

### 操作と表示

- 既存の「一覧」を開いたところへ「一覧プレビューを常時表示」のON/OFFを追加し、操作の入口を増やしすぎない。
- 初期値はOFF。設定は同じブラウザの表示設定として保存し、作品ファイルへは保存しない。
- ONかつ広い画面では編集画面の横に常時表示。狭い画面では編集領域を圧迫しない開閉パネルとし、「一覧」に戻った扱いで編集を終了させない。
- 各行はタイトル、TEXT／LIST／TODOの種別、本文または項目の1～2行。選択中のメモと未保存状態を表示する。本文はテキストとして描画する。
- 最初は既存の編集用一覧と同じ対象・順番を使う。メインの一覧画面の検索・フォルダ・タグ・ページ番号まで新しいパネルに追加しない。後から検索が必要なら同じ一覧モデルへ追加する。
- 削除済みのメモは行から除外し、保管中の扱いも既存の編集用一覧と合わせる。選択中のメモが存在しなくなった場合は入力を保持して案内し、別の行へ自動移動しない。

### 切替の保存ルール

現在の`openConceptMemo`は呼出し時にdirtyを解除する。常時一覧から直接呼ばず、既存の「一覧」からの切替も含めて`requestConceptMemoSwitch(id)`に集約する設計とする。

| 状態 | 切替 |
|---|---|
| 選択中と同じメモ | 何もしない。未保存確認を出さない |
| 変更なし | そのまま切り替える |
| 未保存 | 「保存して切り替え」「保存せず切り替え」「キャンセル」を提示する |
| 保存中・同期中 | 処理終了を待つか、処理中と表示して切替を保留。連続クリックを重複実行しない |
| 保存して切替を選択 | 保存成功かつdirty=false、競合なし、保存・同期処理終了を確認してから切り替える |
| 保存失敗・競合・通信中の追加入力 | 元の編集を保持し、切り替えない。エラーは閉じるまで残す |
| 保存せず切替を選択 | 明示的な破棄。構想メモ全体の最後に確認できた保存内容から戻し、古い編集中オブジェクトを残さない |

保存後のバックアップや反映先だけの失敗は、元メモの保存結果と区別する。未解決の反映があれば結果を確認できるまで切り替えず、後続の保存成功で警告を隠さない。

`saveCurrentConceptMemo`は現状、保存失敗を内部処理し、単純な戻り値だけでは成功を判定できない。実装時は保存結果を明示する戻り値とdirty／外部競合／同期結果の確認を組み合わせる。`state.conceptDocument`を唯一の一覧データとし、編集中の表示はそこから作る。パネルを開くたびにDriveを読み直さない。失敗を握りつぶして次のメモへ進む経路を作らない。

受入確認：ON/OFF保持、広い／狭い画面、選択状態、TEXT／LIST／TODO、未保存3択、自動保存中・同期中・追加入力・競合、保存失敗後の再操作、再読み込み、戻る操作を確認する。

## W07：Webのファイルから作成

### 手数を抑える入口

原稿一覧に「ファイルから作成」、プロット／資料一覧に「Markdownから作成」を追加する。テンプレート登録・テンプレート専用Driveフォルダ・事前の空ファイル作成は初期版に入れない。

1. ボタンからローカルのファイルを1つ選ぶ。
2. 選択後の1画面に名前・保存先・内容概要を表示。名前はファイル名から補い、原稿の拡張子やノートの分類は開いている一覧から補う。必要な場合だけ変更する。
3. 同じ画面の「作成」で内容入りの新規ファイルを保存して編集を開く。構造プレビューはその画面内に置き、追加の確認ダイアログを連続で出さない。

選択しただけではクラウドに作成しない。キャンセル・解析失敗・未許可の保存先では空ファイルや代替フォルダを作らない。既存ノートへの挿入・置換えは初期版から分ける。

### 原稿

- `.txt／.md`を対象とし、本文は文字列として読み込む。Markdownをノートの構造やHTMLへ変換しない。
- ファイル名と拡張子を初期入力し、既存の原稿名の検証と保存先を使用する。既存ファイルへの更新として扱わない。
- UTF-8／BOM付きUTF-8から開始する。BOMは読み込み時に除去し、文字化けや置換文字があれば作成前に案内する。Shift JIS等の自動推測や複数ファイル・フォルダ一括読込は後続。
- 本文中のルビ記法はそのまま保持する。画像の参照先を勝手に読み込み・アップロードしない。

### ノートの対応範囲

既存VS CodeのMarkdown書き出しと読込は次の基本構造を共有する。

| Markdown | ノート |
|---|---|
| `# 大分類` | group.title |
| `## 区分` | divider.label |
| 区分直後の`> 補足: 内容` | divider.value |
| `### 項目` | entry.heading |
| 項目以下の本文 | entry.body |

ノート名はMarkdownの最初の`#`から取らず、ファイル名を初期値にする。`#`は大分類だからである。プロット／資料は開いている一覧の種類を使う。構造が不足する場合の「無題大分類／項目」の補完と警告を既存仕様へ合わせ、件数・概要・補完内容を作成画面に表示する。

**既存のMarkdown書き出しは完全なバックアップではない。** 画像・項目メモ・同期リンク・関連資料リンク・呼び名一覧・項目の独立したheadingRuby・元のIDは出力しない。本文に直接書かれたルビ記法は文字列として残るが、これらのメタデータを復元できるとは表示しない。画像やメモまでの引継ぎが必要なら、後続で既存JSON形式等を利用する別経路を検討する。

基本構造を読み込んだ後、`web/lib/notes.mjs`の既存schemaVersion:4へ変換する。ノート・分類・項目のIDを新しく割り当て、画像・メモ・リンクは既存の新規ノートと同じ初期状態にする。テンプレートの元作品や項目メモと自動でリンクさせない。

### 解析の共有と事前対応

`src/import/note-markdown-import.js`はNodeのpathを使うCommonJSモジュールであり、Webへそのままimportできない。ファイル名処理・ID発行・ファイルI/Oを解析本体から分離し、ブラウザで動く解析本体と既存APIのアダプターを用意する。配置／モジュール形式はVS CodeのNode実行版で読み込めることを確認して決め、async importへの変更を全呼出し元の点検なしに広げない。VS CodeとWebで別々のパーサーを育てない。

既存解析ではコードフェンスを警告付き本文として扱う一方、その内側の`#`を構造として解析する例を確認した。共有化の前にフェンス内を本文として保持する対応と、既存VS Codeインポートの回帰確認が必要。一般的なMarkdownすべての書式をノート構造へ変換する機能にはしない。表・チェックリスト等は本文として残し、HTML／スクリプトを実行しない。

### 作成と保存の責務

- ブラウザのFileから読む工程と、選択中のプロバイダーへ新規作成する工程を分離する。原稿は既存`createTextFile`、ノートは新規ノート作成と索引更新の経路を利用する。
- 保存先は現在の原稿フォルダ、または許可・存在を確認できたplots／references。既存のGoogle Driveの未許可時の停止と追加許可案内を維持する。既存のconcept-memos.json等への許可まで不要になる機能とは説明しない。
- 許可済み一覧で同名を検出したら既存の検証・採番へ合わせる。Driveで見えない兄弟ファイルの不存在は断定できない。同名検出を根拠に既存IDへ更新せず、新規IDを作る。ファイル名の衝突対策は実装時にプロバイダー別に点検し、上書きしないことと同名の不存在保証を混同しない。
- 作成成功後に索引更新・画面表示・集計等が失敗しても、作成済みIDを保持し「作成済み／開き直す」と案内する。画面の再試行で同じファイルをもう一度新規作成しない。
- 保存先を変える・作品を切り替える・二重送信する操作は作成中に止める。作成後の通常編集・保存は既存の版照合と競合保護へ戻す。

受入確認：UTF-8／BOM、空・不正・長いファイル名、キャンセル、基本構造と補完、コードフェンス、画像参照・ルビ本文、同名、未許可、保存先消失、通信失敗、二重クリック、作成成功後の索引失敗、一覧・編集への反映を確認する。
