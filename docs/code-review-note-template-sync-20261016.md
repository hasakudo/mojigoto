# 生成Markdownの再読込・読込先管理（2026-10-16）

生成ファイルの選択・ドロップ読込は利用者実機で確認済み。次の小単位3cとして、同じ生成元から作ったWebのコピーを繰り返し増やさず、明示的に再読込する仕組みを追加した。今回の実装は利用者実機では未確認。

## 動作

新規ノートで専用Markdownを選ぶと、現在の作品で読めるプロット・資料を確認し、読込先を表示する。選択・プレビューだけでは書き込まない。

| 確認できた対象 | 実行時の動作 |
|---|---|
| 許可済みの生成元JSON | 原本を開く経路を優先。Markdownで原本を置換しない |
| 以前の読込先と同じ元保存版 | 書き直さず既存ノートを開く |
| 生成元だけ更新・読込先は前回反映時のまま | 名前・並び順・既存の項目IDを維持して基本構造・本文を反映 |
| 読込先にも編集がある | 上書きを停止し、ダイアログ内で案内 |
| 旧実装で作った、対応情報のないコピー | 内容が一致する場合だけ明示的に読込先へ登録。複数候補は選択を求める |
| 読込先がない | 新しいコピーを作り、対応情報を保存 |

実行直前にも再確認する。未保存・保存／同期中、作品切替、外部からの同時保存は既存の版照合と合わせて停止する。読込先が既にあれば追加コピーの入口は出さない。新規コピーのファイル名も生成元から固定し、同名を見つけても末尾番号で増やさない。表示失敗後の再試行は処理済みの同じIDを開く。通常のMarkdown・原稿は従来どおり新規作成。同じタイトルだけを根拠に置換しない。

## 対応情報・互換性

生成形式v2に元の大分類・区分・項目IDを追加した。元の並替え・改名後もWeb側のIDを維持する。解析後の構造と項目数・種類が一致しない場合、項目種類が変わった場合、確認できる他ノートの関連リンク先を消す／大分類間で移動する場合は停止する。

コピーJSONの任意項目 `importSource` に生成元、前回の保存版、反映後の内容ハッシュ、項目IDの対応を保存する。ブラウザだけの記録にせず、VS Codeで読み書きしても保持する。作品間コピーは従来どおり新規IDを発行し、この対応情報を引き継がない。

v1も引き続き読める。新版VS Codeの「今すぐ更新」で、原本が同じ保存版でもv2へ更新する。v1の対応先には同内容のv2から項目対応を補える。旧実装の未登録コピーは、同じ内容の版から登録する必要がある。すでに両側を別々に編集したものを、名前や順番から推測して統合しない。

項目メモ・ふりがな設定・画像・呼び名一覧等を含む完全な往復同期は対象外。コピー側にそれらを追加した場合も編集として検出し、再反映で消さない。Webから生成Markdownや元JSONへの書戻しは追加していない。

## 実機確認

1. 新しいVSIXでDashboardの「Web読込用Markdown」から「今すぐ更新」。生成したv2をWebへ選択／ドロップする。
2. 原本JSONが許可済みなら「原本を開く」が先に表示され、そのまま開けること。別コピーで試す場合は「新しいコピーを作成」を選ぶ。
3. 同じMarkdownを再度読むと以前の読込先を開き、ノート数が増えないこと。
4. 元ノートだけ変更・保存して生成物を読み直すと、既存コピーへ本文・追加項目が反映され、名前・並び順が維持されること。
5. コピー側にも別の変更を保存して次の生成物を読むと停止し、両方の内容が残ること。エラー文を読めること。
6. 旧実装のコピーは同じ内容の生成物から「読込先に登録」を試す。すでに元と違う場合は自動では登録しない。

## 残る確認

Googleの未許可ファイルは判定できない。以前の読込先が見えなければ先に追加許可して読み直す。異なる端末で同時に新規作成する操作全体を排他する仕組みではなく、Googleの同名作成を完全に防ぐ保証はない。関連リンクも読めるノートが確認対象で、複数ファイルを一括で固定する取引ではない。

G:で生成ファイル更新後のDrive項目ID・許可維持は引き続き実機確認が必要。ローカル選択／ドロップではGoogle APIでMarkdownを直接読まないため、確認済みと扱わない。この小単位の確認後、長いルビのプレビュー・書き出し等と大きな責務分割へ進む順番を再確認する。
