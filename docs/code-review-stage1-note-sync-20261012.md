# 第1段階：ノート・構想メモの保存と同期（2026-10-12）

利用者から、Google DriveストリーミングのG:でVS Codeの表示・読み書き同期が成功したとの実機確認を受領した。今回の作業単位はWeb側の構想メモ保存と、構想画面からの双方向同期、ノート保存後の自動同期の途中失敗である。

## 修正

- 構想メモ本体の保存失敗では、自動保存を際限なく再予約しない。入力は未保存のまま保持する。
- バックアップの失敗は本体保存と区別して通知する。バックアップ待ちに入力された未保存内容を自動同期へ混ぜない。
- ノートへの反映と同期情報の更新はコピーを作って書き込み、成功後にキャッシュへ反映する。失敗時に画面内のノートだけ更新しない。成功時は読み込み基準のrawも更新する。
- 構想側の保存失敗後に、ノートの同期基準を更新しない。片側だけ保存できた場合は、どちらが未保存かを明示し、同期成功を通知しない。
- 出典の読み込み中に作品・接続・入力が変わった場合は同期を停止する。書き込み中の移動と同期の重複、外部更新による読み替えを抑止する。
- ノート保存後の自動反映は、保存された内容のコピーと開始時のプロバイダー・作品を使用する。途中の追加入力や別接続を使用しない。
- Webキャッシュを更新（app 1.0.161、shell v203）。公開・配備は行っていない。

## 検証

全体 **428件成功、失敗0件**。ログ `.review-baseline/stage1-note-sync-tests.log`。クラウド通信は模擬検証であり、実アカウントの通信断・別端末との同時編集やブラウザ操作を検証済みとは扱わない。二つのファイルをクラウド上で一括確定する仕組みはないため、片側成功後の失敗は通知と未保存情報の保持で扱う。
