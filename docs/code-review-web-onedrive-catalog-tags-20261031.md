## 調査と判断

前回の実機報告では10作品の子一覧に約4〜6秒、管理一覧に約4〜5秒を要していた。通常のdiscoverWorksは前回カタログを表示に使っても探索には渡さず、全作品の2段階の一覧を再取得していた。関連設定側は既に最新メタデータのbatch確認とeTag一致の本文再利用を実装しており、その確認や相互書込を省略する方針にはしない。

Microsoftの[driveItem仕様](https://learn.microsoft.com/en-us/graph/api/resources/driveitem?view=graph-rest-1.0)では、OneDriveのフォルダcTagは配下の内容・メタデータ変更で変わる。フォルダeTagや日時だけでは同じ保証がない。OneDrive for Business／SharePointのフォルダではcTagが返らないため、存在し一致する場合だけ最適化する。

## 実装

- loadWorksで既存の利用者・クラウド・ルート別カタログをdiscoverWorksへ渡す。OneDriveProviderだけsupportsFolderContentTagsを有効にする。新しい永続キャッシュやキャッシュの保持期間は追加しない。
- 最初に最新ルート一覧を取得する。前回作品とID・driveId・cTagが一致し、管理一覧が完全な形で保存されている作品は、子と管理の一覧を再利用する。
- 作品側cTagが変わった場合は子一覧を再取得する。そこで新しく確認した.mojigotoのcTagが前回と一致する場合は、管理一覧だけを再利用する。管理側の変更時は管理一覧も再取得する。
- タグ欠損・別ドライブ・原稿／管理フォルダの親の不一致・不完全な管理スナップショットは再利用せず、従来の取得へ戻る。eTagや日時だけでは省略しない。
- Singleはルート内の最新.mojigoto一覧項目を照合し、Multiは作品ごとに照合する。新規作品は探索し、削除・移動した作品は最新ルート一覧で除外する。
- 設定・共有集計の本文は、既存のファイル版キャッシュをそのまま使う。本文キャッシュがなければ読み取る。前回のタイトルだけを最新設定として採用しない。コピーした一覧を用い、保存済みスナップショットを書き換えない。
- 関連設定の最新確認、書込時の条件付き保存、切断時のキャッシュ破棄、Dropbox／Google Driveの探索は変更しない。初回で前回一覧がない場合、全作品に変更がある場合、フォルダcTagが得られない場合の取得量は従来と同じ。
