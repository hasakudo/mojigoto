# Google Driveの構想メモ・ノート索引・集計の未許可時点検

前段の作品設定は利用者が実機で、未許可時に作成されず注意文が出ること、許可後にVS Codeと同じ内容を表示してWebで編集・保存できることを確認した。

次の対象として構想メモ・ノート索引・共有集計を調査し、設定と同様に未許可を不存在と判断して作成する経路を確認した。drive.fileの一覧では未許可と本当の不存在を区別できないため、Google Driveでこれらが見つからない場合は作成を止める。

## 今回の修正

- 構想メモ画面を開くensureConceptDocument：最新の一覧を取得し、concept-memos.jsonが見つからない場合は追加許可を案内して停止。空の構想ファイルを作らない。
- 項目メモから構想メモを作成するcreateConceptFromNoteItem：構想ファイルが見つからない場合は停止し、ノートのリンクを変更しない。まだファイルがない場合はVS Codeで構想メモを作成・同期して許可するよう案内。
- ensureNoteFolder：plots／referencesが見つからない場合は追加許可を案内し、ノート用フォルダの重複作成を防ぐ。新規ノート用のファイル作成そのものは今回変更しない。
- updateNoteIndex：notes-index.jsonが見つからない場合は索引を新規作成せず、補助更新を見送る。
- updateSharedWorkMetrics：work-metrics.jsonが見つからない場合は共有集計ファイルを新規作成せず、補助更新を見送る。

原稿・ノート本体の保存は、補助ファイルの更新ができないだけで失敗扱いにしない。許可済みの索引・集計は既存ファイルを更新する。他クラウドの初回作成は維持する。追加許可後は作品一覧を再読み込みして項目情報を取り直す。Web READMEにも初回作成の制限と補助更新の見送りを説明した。

Web app参照版1.0.165、Service Worker shell-v207。Web配備・VSIX再作成・利用者データへの書き込みは行っていない。前のVSIX／退避には今回の修正は含まれない。

## 実機で次に確認すること

利用者から、構想メモ・ノート保存先・集計はVS Codeで最初に作られ、通常は.mojigoto内をまとめて許可するため、未許可状態を意図的に作る確認が難しいとの報告を受領した。この状態を作るための許可解除や作品データの削除・再作成は実機確認の必須手順としない。

未許可の項目が一覧に出ない状態は自動テストで模擬し、ファイル・フォルダ・リンクが増えないことと、補助更新を見送ることを確認済み。実機で未許可の案内を再現したとは扱わない。通常の許可済み環境では、VS Codeの既存内容の表示、Web保存のVS Code反映、VS Code保存のWeb再読み込みへの反映を確認する。設定ファイルと異なり、ここでは未許可状態の実機再現を次段へ進む条件にしない。

バックアップのフォルダ・索引、web-writing-events.jsonの初回作成、利用者が指定する新規ファイル・フォルダ名の衝突は今回の修正対象に含めない。未許可を不存在と扱う可能性があるため、次段の点検対象に残す。Drive同期による削除／再作成時のID変化も実機で未観測。
