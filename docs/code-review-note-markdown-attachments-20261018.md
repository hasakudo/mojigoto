# ノートMarkdownの画像関連付け・呼び名一覧（2026-10-18）

前段の項目メモ・タグ・ふりがな・関連リンクは利用者の4点確認済み。本作業は画像の関連付けと呼び名一覧の取込範囲を追加する。

## 仕様

- 生成形式4。形式1〜3の読込も維持。生成側とWeb側の両方を更新し、Dashboardから再生成する。
- 大分類ごとの画像ID・表示名・ファイル名・相対パス・作成日を保持。画像ファイル本体のコピー・アップロード・Web表示は追加しない。同じ作品では元の画像を参照し、別作品では元の `.mojigoto/note-images/` の画像も同じ階層へ別途コピーする。
- 作品全体の `address-book.json` の表示に必要な人物・一人称・呼び方をMarkdownへ含め、取込ノート内の `importedAddressBook` へ保存する。現行の作品単位の一覧と、旧ノート内の呼び名一覧は区別する。旧ノート内の人物参照は取込後の項目IDへ付け替える。
- Webの呼び名一覧は許可済みの既存ファイルを優先する。空でも既存ファイルを優先。ファイルが一覧に見えない場合は取込ノートの一覧を表示し「Markdown取込版（表示用）」を添える。同じ生成元作品の最新版を採用し、異なる作品の人物IDを混同しない。呼び名ファイルの新規作成・上書きはしない。
- 取込版は表示用であり、独立した呼び名一覧ファイルを編集するVS Codeの画面を置き換えない。VS Codeでノートを保存しても取込版を保持する。取込版を変更するにはVS Codeの元の一覧を編集しMarkdownを再生成・再読込する。
- 呼び名一覧の保存でも自動生成を更新し、ノート本体が同じ版でも呼び名だけの変更をコピーへ反映できる。生成・保存中の変更を再確認する。
- 形式3から4への再反映は同じ原本の保存版でも追加情報を更新。取込先も編集されていれば停止。形式4から旧形式への自動反映は停止する。明示上書きは比較とバックアップを経て実行する。
- 画像の関連付け・呼び名の取込版も比較へ含める。既存の独立した一覧はノートの上書き対象にしない。
- 画像は原本とコピーで同じファイルを参照し得る。VS Codeで画像を外す場合、ノートの保存成功後に他ノートの参照を確認し、参照が残る画像は削除しない。参照確認エラー・リンク先が通常ファイルでない場合も物理ファイルを残す。
- 画像パスは `note-images/` 配下の通常の相対パスのみ。親移動・絶対パス・URL・Windowsの末尾空白/ドット等を拒否。添付情報の形・件数・ハッシュも検証する。

## 構想メモの確認への回答

構想メモ側に残したい内容を保持し、元の項目が特定できる場合はそちらから手動反映できる。新しいコピーはIDが変わるため自動では再連携しない。Markdown読込では連携IDと自動反映をOFFにし、構想メモ本体は変更しない。

自動保存と自動反映のON/OFFは別。自動反映は保存成功後に実行するため、自動保存OFFでも手動保存時に反映設定が有効なら動く。双方変更時は停止する。
