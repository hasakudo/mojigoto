## 実装

- manuscript-catalog.mjs：現在の作品の原稿ルートを再帰取得し、章フォルダ→その配下→直下原稿の順に目次を作る。各階層はWebのsortDriveItemsを利用。同名で比較が一致する場合はIDで順序を安定させる。
- 本文のreadTextや保存APIは呼ばない。取得したものは目次用のメタ情報で、未保存本文・保存状態・編集中ファイル・カーソル・履歴を変更しない。
- この目次機能の同時一覧取得はproviderごとに2件まで。中止した通信が残っていても、新しい目次との合計で枠を共有する。中止後は新しい取得を開始せず、遅い応答を表示へ使わない。共通providerのAPIに実通信中断がないため、開始済みのHTTP完了そのものを即座に止める処理ではない。
- 取得した成功フォルダの一覧は閲覧セッション内だけで保持。失敗した章の再試行では、成功分を再取得しない。「更新」では全体を取り直す。
- 管理フォルダ（.mojigoto／.git／_WORK）・参照リンク・重複を対象外として表示する。不明ID・異なる親・権限不足・通信失敗・取得上限は空原稿として完了扱いにしない。
- 初期の上限はフォルダ300、階層32、集約項目10,000。上限に達した未取得の章は明示し、それ以降の待機中の章を取得しない。1フォルダ内でproviderがページをまとめて返す仕様は変えていないため、極端に大量の項目が1フォルダにある場合の通信・一時メモリは今後の実測対象。
- manuscript-catalog-controller.mjs：編集画面とは別の閲覧状態を持ち、利用者・provider・作品・原稿ルートのドライブ／ID・元の表示画面が変われば閉じて破棄する。本文名やエラーはtextContentで表示。
- 目次は50項目ずつ。読み込み中は進捗だけを更新し、完了・一部失敗・中止で取得済みの目次を表示する。ヘッダーと閉じるボタンを固定し、目次本体だけをスクロールする。原稿一覧の操作ボタンは狭幅で折り返す。
