# Single→Multi移行後のGoogle Drive作品設定の重複作成防止

利用者から、VS Codeが移行後に作成したwork.jsonを許可する前にWebの作品設定を開くと、Webも設定を作成し、同期先にwork (1).jsonが現れて2つの設定が存在するとの報告を受領した。移行後のWeb表示成功だけでは保存・設定参照の成功を保証できないことが実機で確認された。

## 原因と修正

Google Driveのdrive.fileでは未許可項目が一覧に出ない。ensureWorkSettingsFileは一覧に設定がなければ存在しないと判断して新規作成していた。

Google Driveで設定を見つけられない場合は、新規作成せず追加許可を案内して停止する。本当に設定がない場合も未許可と区別できないため停止する。自動で空設定を作らず、VS Codeの設定ファイルを同期して許可する。案内は作品設定画面にも残す。

設定ファイルIDが未確定の場合は最新の一覧を取得し、許可前の空のキャッシュを使わない。work.jsonを優先し、SingleのsingleWork.jsonにも対応する。OneDrive・Dropboxは設定がない場合の作成を維持する。

VS Codeの移行選択画面、Webの画面内ガイド・独立ガイド、Google Drive設定ページ、Web READMEへ、同期完了後に新しい作品フォルダ・.mojigoto・work.jsonと新規／再作成された項目を追加許可し、作品一覧を再読み込みする手順を追記した。Web appの参照版は1.0.163、Service Workerはshell-v205。
