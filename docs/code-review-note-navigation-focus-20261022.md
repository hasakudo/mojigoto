# 初回ジャンプとアクティブ化時の再描画・スクロール復元（2026-10-22）

## 利用者確認と対象

4-Cの呼び名一覧と候補位置修正は利用者確認済み。予定していた、初回表示後の非アクティブなノートへのジャンプが、1回目はアクティブ化だけになる現象を調べた。対象は目次→編集、編集→プレビュー、プレビュー→編集。

## 発見と修正

- 編集画面の`focus`・再表示・リサイズでは`stabilizePreviewRender`が通常／ボードプレビューを即時と後続フレーム／タイマーで作り直し、スクロール位置も複数回復元していた。非アクティブな画面をクリックしてフォーカスが移ると、クリック対象が置き換わる経路がある。ジャンプ直後のプレビュー位置が初期位置で戻る経路もあった。
- `script-preview-layout.js`へ、内容を作り直さないレイアウト確認と初回だけの位置復元を実装。フォーカスや再表示では表示中の要素を維持する。起動時・ノートの再読込時は明示的にプレビューを描画する。80／180／300msの遅延再描画は廃止。
- 表示待ちが重なった場合は同じフレームにまとめ、非表示の間は初回の位置復元を始めない。通常のフォーカス移動やリサイズで過去の位置へ戻さない。
- 編集→プレビューのジャンプに、プレビューの初期位置復元を取り消すフラグを追加。項目・項目メモ・区分への移動にも編集位置復元より優先する既存の規則を適用する。
- 表示用プレビューとホストの移動メッセージ、タブの再利用・復元、保存・自動反映は変更しない。固定時間の再送や重複ジャンプは追加しない。

VS Code自体の仕様として避けられないとは判断していない。拡張側の干渉経路をテストで確認して修正したが、報告された実機での全経路が解消するかは修正版の確認待ち。
