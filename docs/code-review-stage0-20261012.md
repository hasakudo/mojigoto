# 第0段階：現状の記録とテスト失敗の切り分け

確認日：2026-10-12。VS Code拡張・Webのローカルソースが対象。

## 結果

当初の失敗6件は、現行仕様と古いテストの不一致5件、サンドボックスの一時フォルダでのrename失敗1件に分類した。アプリの動作・データ形式・認証実装は変更していない。

現行仕様に合わせたテスト更新と認可の失敗ケース追加後、ワークスペース内を一時フォルダとして全体テストを実行し、**361件すべて成功**。ブラウザ表示・実アカウント・本番の確認結果ではない。

- package.json：1.0.68

- 追跡ファイルの変更に加え、Web等の未追跡ファイルがある。全体を新規コミットする操作は行っていない。

`scripts/capture-review-baseline.ps1` で未コミット・未追跡ソースを保存した。保存先は Git・VSIX から除外する `.review-baseline/`。この初回スナップショットには、記録用スクリプトとGit除外設定の追加が含まれるが、テスト更新前のアプリとテストを収録している。

- 修正前：`.review-baseline/20261012-135615-d1696d/source.zip`

- ZIP SHA256：`270683E0D7AADCDA8335BFFA831809B7863969FEB4F2D37301CC93C0791FC6C3`
- 同じディレクトリにGit状態、実行環境、除外一覧を保存。
- Gitで無視するファイルに加え、Webの実設定、認証データ、環境変数ファイル、鍵ファイル、生成物、ローカルエディタ設定を除外。ZIP内に `web/config.json`、`api/auth/config.php`、認証データの実ファイルがないことを確認した。

このZIPはローカルソースの基準であり、作品データ・本番設定を復旧するバックアップではない。復元時は別途保持している環境設定を使う。第三者への公開用には作成していない。

## 6件の分類と対応

| 対象 | 原因・根拠 | 今回の対応 |
|---|---|---|
| 入れ子フォルダの並び替え | OS既定のサンドボックス一時フォルダでrenameがEPERM。ワークスペース内の一時フォルダでは同じ3テストが成功 | アプリ処理は変更せず、検証環境を記録 |
| Sheetsガイド | 内部名 `m_progress_v2.gs` を要求する古い期待。現行ガイドと配布スクリプトは利用者向け `m_progress.gs` | ガイドのダウンロード先と配布名を検証。実際のZIPも作成し、3ファイルの収録とApps Script内容一致を確認 |
| Google接続 | テストの模擬応答にscopeがなく、現行の権限検証が拒否 | 現行scopeを応答に含め、drive.file限定と `include_granted_scopes: false` を検証 |
| Google旧トークン | 古いテストがdrive.fileを旧形式と想定。現行実装はdrive.fileを受け入れ、旧driveを拒否する | 旧driveの拒否を検証。通常の接続テストでは新トークンの再取得も確認 |
| 公開ページ | 以前のDrive全体権限の説明を要求 | drive.file、親フォルダ選択だけでは不十分、追加許可の説明を検証 |
| ロゴ | 空のspanとCSSマスクを要求。現行HTMLはインラインSVG | ログイン画面とアプリの両方にSVGがあり、パスの色がテーマ変数に追従するCSSを検証。原稿アイコンの検証は維持 |

新たに1テストを追加し、Google認可でscopeが欠落、必要権限が不足、旧drive、drive.readonlyとの混在の場合に、接続を拒否してトークンを保存しないことを確認した。

## 再実行方法

通常の環境では `npm test`。このサンドボックスでは以下のように一時フォルダをワークスペース内へ指定して実行する。

```powershell
New-Item -ItemType Directory -Path .review-baseline/test-temp -Force | Out-Null
$env:TEMP = (Resolve-Path .review-baseline/test-temp).Path
$env:TMP = $env:TEMP
npm test
```

環境変数の変更は実行したPowerShellプロセス内だけに適用される。成功ログは `.review-baseline/test-after.log`。個別の関連テストは50件すべて成功、全体では361件すべて成功。

ソース基準を追加保存する場合は `pwsh -NoProfile -File scripts/capture-review-baseline.ps1`。依存関係はpackage-lock.jsonに基づき別途復元する。

`vsce ls` も成功。Sheetsの3ファイルがVSIX対象に入り、`.review-baseline/` と認証の実設定・実データは対象外だった。一方、Web本体と公開設定 `web/config.json` はVSIX対象に含まれる。Webを拡張の配布へ含める必要性と公開設定の扱いは、順位2で確認する。一覧は `.review-baseline/vsix-files.txt` に保存した。

## 次の段階へ引き継ぐ事項

1. 保存・同期レビューでは、原稿の未保存内容、外部更新との競合、通信失敗、再接続・画面復帰を先に確認する。
2. 改名・並び替えは正常時のテストが成功した。`saveFolderListOrder` の二段階renameに途中失敗時の復旧処理が見当たらないため、失敗時のパス・原稿・履歴の整合を次段階で調べる。今回のEPERMだけから実利用の不具合と断定しない。
3. Googleの古い公開準備文書2本とWeb READMEの管理セッション説明は、認証・公開手順の段階で現行仕様へそろえる。テスト成功だけで手順の整合も完了したとは扱わない。
4. 配布物・本番の対応は未確定。VSIX内容一覧は確認するが、本番の適用状況、既存公開VSIXとの比較、クラウド各社の実アカウント動作は別途確認する。
