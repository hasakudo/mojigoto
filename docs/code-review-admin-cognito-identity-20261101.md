# 管理画面のCognito照合用ID・解除済み一覧（2026-11-01）

## 変更後の動作

メールアドレスの伏せ字を維持したまま、Cognitoユーザーを手動削除するための照合情報を管理画面で確認できるようにした。Cognito削除API・IAM認証情報・権限追加は実装していない。本番・実Cognitoユーザーへの変更や削除は行っていない。

1. Microsoft／Google／審査用メールログインの署名・issuer・nonce・userInfoのsub一致を検証した後、Cognitoのissuerとsubを利用者台帳へ保存する。
2. 同じ利用者が複数のCognitoプロフィールやユーザープールを使った場合は、issuer＋subの組ごとに保持する。同じ組の再ログインは重複させず、最終利用情報を更新する。
3. 管理画面の各利用者に「Cognito照合用ID」を追加。照合先ユーザープール、ログイン方式、subを表示し、「subをコピー」でコピーできる。
4. 招待解除後の情報は、利用者一覧の下にある「招待解除済み・Cognito手動削除用」へ分ける。通常の利用者数・メール宛先には含めない。
5. 解除日から90日の既存保存期間内で、解除日・保存期限・照合用IDを確認できる。既存のcleanup処理が期限経過後に情報を削除する。Cognitoの手動削除後も、この一覧は保存期間まで残る。
6. 解除済み利用者がログインを試しても、解除日・保存期限・照合情報を更新せず、利用停止を維持する。

## 利用者による反映後の確認

既存利用者はテストのみとの報告を受けて実装した。既存データのメールアドレスからCognitoを自動照会する機能や、一括移行はない。

- テスト用の招待利用者で一度ログアウトし、改修後のログイン処理を通す。通常の画面再読み込みだけではsubは記録されない。
- 管理者専用画面の「利用者一覧」→「Cognito照合用ID」で表示とコピーを確認する。方式・プールが複数なら全件を確認する。
- AWS側では表示されたissuerのユーザープールを選び、Usersでsubを検索する。検索結果のsubがコピーした値と完全一致することを確認してから、対象のテストユーザーだけを手動削除する。
- アプリ側で招待を解除すると、同じ照合情報が解除済み一覧に移ることを確認する。未記録の場合にアプリ独自のU-…をCognitoのIDとして代用しない。

AWSコンソールの検索は前方一致であるため、削除前は結果詳細で値を確認する。[AWS公式：利用者の検索](https://docs.aws.amazon.com/cognito/latest/developerguide/how-to-manage-user-accounts.html)

## 実装・保護

- 新規 `web/api/auth/cognito-identities.php`：保存するフィールドをissuer・UUID形式のsub・方式・最終日時へ限定。メールを含むusername、トークン、パスワードは保存しない。現在の設定のissuerと一致する検証済みIDだけを追加する。
- `auth/bootstrap.php`：台帳の読込・保存往復で識別子を保持。既存レコードの未記録状態は維持。解除済みレコードの保持期限を後のログインで解除しない。
- `auth/callback/index.php`：署名検証済みのIDトークンから識別子を渡す。プロフィール更新APIや利用者入力から登録する経路は作らない。
- `admin/privacy.php`／`admin/users/index.php`：管理者APIの応答に照合情報と解除済み一覧を追加。専用管理者セッションの認証は従来どおり。通常セッションAPIの応答には追加しない。解除済み一覧もメール・ニックネーム等の伏せ字処理を通す。
- 新規 `web/lib/admin-cognito-identity.mjs`：textContentで表示。HTML挿入やブラウザのLocal Storage保存をしない。コピー失敗時は通知し、選択コピーできる表示を残す。
- 管理JS参照1.0.54／管理CSS参照1.0.50、シェルv330。新モジュールをシェルへ登録。Web本体1.0.282・共有CSS1.0.211・拡張2.0.0は維持。
