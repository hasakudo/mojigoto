# 第1段階：手動反映・VS Codeの同時保存と双方向同期（2026-10-13）

## 点検結果と修正

### Webのノート手動反映

手動反映前にノートの未保存内容を保存し、その保存が失敗した場合は反映を開始しない。開始時点のノートをコピーし、同じ作品・接続へ条件付きで構想メモを書き込む。反映中は移動・削除・構造変更・反映の重複を抑止する。

構想保存失敗ではノートの同期基準を変更しない。構想だけ保存できた場合は、ノート側の未保存同期情報を保持して再保存を案内する。通信中の項目メモ追記は同期先へ混ぜず、下書きとして保持する。成功していない反映を成功通知しない。Webキャッシュはapp 1.0.162、shell v204へ更新。

### VS Codeの保存と外部更新

従来は読み込み後の変更を確認せず、既存JSONへ直接書き込んでいた。ノートと構想メモの読み込み時に内容のSHA-256を保存基準として返し、保存前と仮ファイル完成後に現ファイルと照合する。同一プロセス内では対象パスごとに書き込みを直列化する。別画面・同期処理が同じ読み込み基準から保存した場合は後の保存を競合として停止する。同じ画面の保存キューでは、自分の前回保存から次の追加入力へ基準を進める。

既存ファイルの基準なし保存、読み込み後の削除も競合扱いにする。完成した仮ファイルを置き換えるため、書き込み・置換失敗で既存ファイルを切り詰めない。保存基準のstorageRevisionはノート／構想メモのJSON正本へ書き出さない。

ノートの保存して書き出す操作も保存キューを経由する。構想メモ保存と共通TODO保存を順番に実行し、構想の競合時にTODOだけを更新しない。自動保存の失敗を握りつぶさず通知する。

### 双方向同期と画面更新

構想→ノートの成功後に構想側の同期基準を更新する。従来は古い基準が残り、連続する二度目の反映を競合扱いにしていた。手動反映の返答でも、同期基準だけを更新して入力本文を保持する。

ノート本体と構想メモが保存できても、ノート側の同期情報保存が失敗した場合は、その状態を分けて通知する。未保存の同期情報を保存済みとして画面へ返さない。

同期の読み直し通知が届いた際、両画面とも未保存内容を置き換えない。未保存がなければ最新内容と保存基準へ更新する。明示的に更新を選んでも、読み込み中に増えた入力は保持する。
