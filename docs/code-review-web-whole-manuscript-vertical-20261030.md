# W20-C：原稿全体プレビューの縦書き・設定共用・位置保持（2026-10-30）

Web1.0.268／シェルv313／共有CSS1.0.205。利用者の次工程への進行指示を受け実装。本番・テスト環境への反映と、実クラウド・Android実機での新機能確認は未実施。

## 変更

全体プレビューの本文に折りたたみ式の「表示設定」を追加。方向、明朝／ゴシック、文字サイズ、縦書きの画面に合わせる設定、一行文字数、行間を選べる。既存の個別原稿プレビューの設定処理と保存先を使い、どちらの入口から変更しても共用する。画面・編集本文の書体設定とは分離したまま。

縦書きは右から左へ列を並べる。横スクロール／スワイプとマウスホイール、前／続きを読むに対応し、既存の最大3区間の保持と本文キャッシュ上限を維持。書体・方向などの設定変更だけでは本文を再取得しない。一行文字数指定時は既存プレビュー同様に表示高に応じて文字を縮める。

前後ボタンは同じ行に配置し、横長時の余白を抑えて回転時にも本文領域を確保した。タイトル・説明を全体的に省くスタイル整理は、利用者の後回し指定を維持。接続設定の通知重なりも今回未修正。

## 位置の保持

新しいwhole-manuscript-position.mjsで、原稿のドライブ／ID、本文の元行番号、区間番号、読みの文字を除く表示本文内の文字位置を保存する。DOM Rangeで表示文字を探し、単純なスクロール割合に依存せず復元する。ルビの読みは位置の数に含めない。

方向・書体・文字サイズ・行間・行文字数の変更、表示設定の開閉、ResizeObserver／resizeによる表示サイズ変更後に復元。縦横を繰り返しても先頭へずれ続けないよう基準を揃えた。回転で文字が縮む場合は画面端で一部見えていた文字の座標も補正する。回転が発火させたスクロール通知で、再調整前の位置を上書きしない。

同じダイアログ内で目次へ戻り、同じ原稿の「読む」を選ぶとその原稿の保存位置から再開。「先頭から読む」は先頭へ戻る。位置は最大100原稿、閲覧セッション内のメモリだけに保持し、本文は位置情報へ含めない。閉じる・目次更新・作品／利用者／接続先変更で破棄する。閉じた後や再読み込み後の永続的な読書位置の保存は今回の対象ではない。

元の行が外部更新でなくなった場合や表示範囲の端でスクロール上限に達する場合は、取得できた区間と表示可能な範囲に合わせる。異なる本文へ元の文字位置を厳密に復元する保証はしない。編集中のスナップショット、未保存状態、保存処理・カーソルは従来の保護を維持。
