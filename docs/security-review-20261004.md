# 管理画面・認証の点検（2026-10-04）

## 追記: 管理アカウントの通常利用禁止

管理者リストに含まれるアカウントは通常ログインを拒否する。既存の通常セッション・プロフィール更新も拒否する。通常セッションAPIのisAdminは常にfalse。ローカルの管理専用をmojigoto.web、普段用をlovetwo.smileの各Gmailアカウントに設定した。一般Google/Microsoft入口でアカウント選択を要求し、保存済みCognito SSOによる管理用アカウントへの自動復帰を避ける。自動28件・HTTP17件成功。今回の追加更新は本番未適用。

## 追記: 管理者専用入口とセッション分離

ローカルに `/admin/login/`、別Cognitoクライアント、別Cookieを実装。無操作15分・絶対1時間をサーバーで判定し、重要操作は5分以内の新しいCognito認証を要求する。通常ログインでは、管理者アカウントでも管理APIを利用できない。管理ログアウト後に通常の利用セッションが維持されることを実機確認した。

自動テスト25件、ローカルApacheへの認証・CSRF・期限HTTP検証15件、PHP26ファイルの構文確認が成功。Google専用ログインと非管理者拒否を実機確認。本番未適用。Microsoft専用ログインはWindows本人確認をユーザーへ引き継いでおり、完了結果は未確認。

Googleの既存SSOでは、アカウント選択のみでCognitoの新しいauth_timeが発行された。毎回のパスワード再入力・MFA実施は保証しない。次の課題は管理者IdPアカウントのMFA・復旧方法確認と、必要に応じたアプリ独自の追加認証。下記の12時間・改善候補はこの追記以前の状態。設定と本番適用順序は [admin-auth-setup.md](admin-auth-setup.md)。

## 結論と範囲

ローカルソースと、本番への読み取り専用HTTP確認を実施した。安全性の保証や網羅的な侵入テストではない。本番のFTPファイル、PHP設定、サーバー管理画面、MFA、WAF、ログ、バックアップへのアクセス制御は未確認。

本番で確認済み:

- トップページのHSTS、CSP、X-Frame-Options、X-Content-Type-Optionsが存在する。
- `/api/auth/config.php`、設定例、`/api/auth/data/users.json` は403。
- 管理者用の利用者・受付・メール・お知らせAPIは、未ログインで401。
- `/admin/` のHTMLは公開されるが、管理APIが認証を要求する。HTMLが200であることだけで侵入成功にはならない。
- 本番の管理JavaScriptは1.0.50で、メールログインの表示分岐を持つ。「未ログイン」の原因はこれだけでは確定できない。保存記録のprovider不足やブラウザキャッシュも切り分けが必要。

## 今回のローカル修正

1. メールログインの表示を「審査用（メール・パスワード）」へ変更。日時があるが方式がない場合は「ログイン済み（方式未記録）」、日時もない場合は「ログイン記録なし」とする。許可済み審査アカウントでproviderが空の場合は利用可能なメール方式を表示する。履歴を捏造せず、最終ログイン日時が欠落している場合は「記録なし」を表示する。
2. アドレス全文表示ボタンと解除APIを撤去。古い解除セッションでも伏せ字を維持。利用者のアドレス、ニックネーム内のアドレス、受付のアドレス・本文・氏名、操作履歴、送信ボックスの件名・本文にある一般的なメール表記もサーバー側で伏せ字にする。画面だけ隠して全文をブラウザへ返す方式は使用しない。利用者IDを使う招待停止・削除・宛先解決は維持する。
3. IDトークンは従来、発行元・対象・期限・nonceを確認していたが、RSA署名の確認がなかった。Cognitoの既定JWKSエンドポイントから公開鍵を取得し、OpenSSLでRS256署名を検証するよう変更した。token_use=id、sub、有効期限、未来のiat/nbf、nonceも検証し、userInfoのsubとの一致を要求する。鍵取得や検証に失敗した場合はログインを拒否する。
4. 管理JSの参照版を1.0.51へ、Service Workerのキャッシュ版をv154へ更新する。

本文の伏せ字は一般的なASCIIメール表記を対象とする。画像、難読化表記、国際化アドレス、本文に含まれるその他の個人情報まで自動で完全に除去するものではない。本人が新規招待欄へ入力するアドレスは処理に必要で、入力中の欄は対象外。本人のセッションAPIはログイン本人のメールを返す。サーバー内の元データは通知配送のため保持する。

管理者セッションを乗っ取られた場合、伏せ字にしても招待変更・メール送信等の管理操作は可能。サーバー自体を侵害された場合は元データを読まれる可能性がある。全文表示撤去だけで侵入対策が完了したとは判断しない。

## 本番適用

今回の更新用ZIPはローカル設定・利用者データ・本番のお知らせを除外する。本番へ転送したあと管理画面を再読み込みし、以下を確認する。

- アドレス表示ボタンがない。
- テスターの方式表示が審査用になり、メール全文が利用者一覧へ表示されない。
- Microsoft／Google／審査用メールの再ログインが成功する。
- 本番PHPでOpenSSL拡張が有効で、CognitoのJWKSへのHTTPS接続ができる。追加の秘密値は不要。
- 検証用ヘルパーPHPのHTTPアクセスは403である。

既存のconfig.php・config.json・利用者JSONをローカルのもので置き換えない。今回の修正は本番へ自動アップロードしない。

## 追加で確認する事項

優先して、管理者のGoogle／MicrosoftアカウントとAWS／ホスティング管理アカウントのMFA、管理セッションの有効期間、FTP/SFTP・バックアップ・ログの保護を確認する。現行アプリのセッション上限は設定例で12時間で、管理APIも同じ上限を使用する。管理者専用の短い有効期間と重要操作時の再認証は今後の改善候補。

データを公開ディレクトリ外へ移す場合、利用者・フォーム・送信メールの保存先を一緒に整合させる必要がある。現在は.htaccessによる403を確認したが、PHP/Apacheの設定変更やホスティング移行時にも再確認する。
