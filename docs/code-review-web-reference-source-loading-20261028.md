# 関連作品の参照元読み込みを明示（2026-10-28）

利用者の実機では、1.0.247の候補取得10,166ms、expandedFolders=0、fallbackFolders=10、managementFolders=10だった。直接取得経路は使われず、全作品が通常探索へ戻っている。戻った理由はこの件数だけでは特定できない。利用者は待機中でも現在作品のノートを操作できることを踏まえ、参照元が読み込み中であると誤認なく分かる表示を要望。

## 変更

原稿のノート参照とノートプレビューの両方で、「参照元作品」の横に「関連作品を読み込み中…」バッジを追加。セレクトの直下に「この作品のノートは操作できます。関連作品への切替は読み込み完了後に利用できます。」と表示する。バッジと案内は関連作品の候補取得だけに連動し、現在作品の種類／ノート選択と内容表示は従来の動作を保つ。

候補取得が完了するとバッジ・案内を隠して参照元選択を有効にする。失敗時も読み込み表示を終了し、既存の失敗案内と自作品の参照を残す。閉じる際は表示をリセットする。古い要求の完了が、開き直した後の新しい読み込み表示を消さないよう既存の所有状態／要求順チェックを維持する。

読み込み状態のaria-busyは参照元セレクトだけに設定し、画面全体を読み込み中にしない。セレクトに明示的な「参照元作品」の名前を設定し、案内は待機中だけaria-describedbyで結び付ける。バッジはrole=status。色だけに依存せず文言でも状態を示す。新しい通信や保存処理は追加していない。
