## 根拠

一覧取得と本文取得を毎回行う代わりに、保存済みの本文に対応する最新のeTagを確認できれば本文を再利用できる。毎回の版確認は省略しない。書込前のOneDrive版確認とIf-Matchによる競合保護、必要な本文・同期情報の書込順序は維持する。

## 変更

verified-file-read.mjsを追加。OneDriveだけがsupportsVersionedContentCacheを明示し、既知のファイルIDに対する最新メタデータを毎回取得する。ID・ファイル名・親フォルダ・ドライブ・eTagが確認できた場合に限る。同じeTagなら対応する保存済み本文を使い、違うeTagならその最新メタデータから本文を再取得する。OneDriveのgetItemMetadataにダウンロードURLも含め、本文再取得時にさらにメタデータ取得を重ねない。

構想→項目では、初回の一意な出典探索で得た本文・ファイル情報を、接続・作品・ルート・出典条件ごとに保持する。出典は最大8件まで。返す編集用データは複製し、画面上の入力を保持本文へ混ぜない。自分で項目側へ反映した後の本文とeTagも記録して、次回に最新の版確認後に再利用する。ファイルの改名・移動・削除や項目が見つからない場合は従来の一覧・ID探索へ戻す。変更後の本文を読んで項目が移動していた場合は、同じ版を再度読まないようにする。

項目→構想の全体設定による自動反映でも、最後に取得・保存成功した構想ファイルの本文・版を接続・作品・ルートごとに保持する。連続した反映で版が変わらなければ、一覧と本文の再取得を省略する。外部更新があれば本文を読み直して従来どおり競合を判定する。従来の未設定状態の自動反映・手動反映は既存経路を維持する。

通信・認証エラーは以前の本文を使わず停止する。404と所在不一致は再探索へ戻す。版不明のファイルは保持本文を使わない。Google Drive・Dropboxは今回再利用の対象にせず既存の取得経路を使う。本文は実行中のメモリにのみ保持し、localStorageやsessionStorageには保存しない。メモの最新入力を信頼済みの保存本文として扱わない。
