# 手動反映の意図と自動反映の停止条件（2026-10-13）

利用者から、内容が違うために反映したいのに、反映ボタンも自動反映も止まるなら意味がないとの指摘を受領した。前回は停止と入力保持の安全性を確認したが、手動反映の用途まで制限していた。内容の相違を解消する操作として仕様を見直した。

## 操作の意味

| 操作 | 採用する内容と停止条件 |
| --- | --- |
| 項目メモから手動反映 | 押した項目メモの本文・形式・タグを構想メモへ採用する。既知の両側変更でも実行できる。 |
| 構想メモから手動反映 | 押した構想メモの内容を項目メモへ採用する。既知の両側変更でも実行できる。 |
| 自動反映 | 前回同期から片側だけ変更された場合に反映する。両側が別々に変更されていれば、手動で採用する側を選べるよう停止する。 |

手動採用は対象メモに限定する。反映先ファイルを読み直してから書くため、無関係な項目は保持する。読み直し後、書き込み中に別プロセスがファイルを変更した場合は引き続き停止する。反映先画面に未保存入力があれば、その入力を勝手に消さず保持・通知する。手動反映で更新されたファイルと、残した入力を比較して読み直せる。

自動反映は、変更していない側の単なる保存を理由に、変更された側の内容を元へ戻さない。同期基準が分からないリンクは手動反映で採用する内容を確定してから使う。自動保存そのものと自動反映のON/OFFは別設定。

## 修正

- データストアへ手動採用の明示フラグを追加し、両画面の手動反映ボタンの受信処理だけから指定する。自動反映では指定しない。ファイル全体の保存基準照合は維持する。
- 手動反映は先の保存キューの完了を待ち、保留中の自動保存を整理してから実行する。手動反映後の同期基準を画面側・ホスト側へ引き継ぐ。
- 保存中に追加された入力の保存では、自分の前回反映の同期基準を引き継ぐ。本文、タグ、形式、自動反映設定、リンクの選択は追加された入力を保持する。
- 構想の反映後に同期情報を書き直した場合も、次の保存が始まる前にファイルの保存基準を更新する。古い基準を使って自分の保存と競合しないよう修正した。
- ノートの反映済み判定は時刻だけでなく内容の指紋を使う。時刻情報が同じ・未設定でも片側の変更を反映できる。
- リンク済みの項目メモは、空にした本文も手動反映できる。未リンクで空の項目メモの新規作成は従来の案内を維持する。
