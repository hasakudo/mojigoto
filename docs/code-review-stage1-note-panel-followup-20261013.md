# ノート通常保存・自動保存バッヂの追補（2026-10-13）

利用者のG:実機確認で、ノートの手動・自動保存が「ファイルが読み込み後に更新されました」で止まった。構想メモの手動・自動保存は成功したが、自動保存OFFでもONバッヂが表示されるとの報告を受領した。往復反映の実機確認は未着手。

## 原因と修正

前回追加したノートの保存基準更新は、attachNotePanel内でconstとして受け取ったnoteへ再代入していた。初回はファイル保存後に `TypeError: Assignment to constant variable.` が発生し、パネル内の基準が進まない。次の保存は古い基準と保存済みファイルを比較して競合となる。今回は変更するパネル内データをletとして保持する。外部変更を止める照合は維持し、基準の再取得による無条件上書きへは変更していない。

前回のテストは保存関数を抽出し、テスト側で可変のnoteを与えていたため、パネルの定数宣言との組み合わせを検証できていなかった。実際のattachNotePanel全体を実行するテストを追加し、修正前に定数への代入エラーを再現した。

構想メモの `.autoSaveBadge` は `display: inline-flex` がhidden属性による既定の非表示より優先されていた。`.autoSaveBadge[hidden] { display: none; }` を追加した。ノート側にも同じ非表示ルールを追加した。バッヂは画面の自動保存設定 `mojigoto.webviewAutoSaveEnabled` に対応する。ノート／構想間の自動反映設定とは別で、自動反映OFFだけではバッヂを消さない。
