# Web読込用Markdownの詳細項目対応（2026-10-17）

## 結果と範囲

呼び名一覧の別タブ化は利用者実機で確認済み。次の作業として、VS Codeのノート別最新版Markdownに詳細情報を追加し、Webで読み込めるようにした。専用形式の版を3へ更新した。ノートJSON自体のschemaVersionは4のまま。

| 内容 | 専用形式3 | 旧専用形式1／2・通常Markdown |
|---|---|---|
| 大分類・区分・補足・項目・本文 | 維持 | 維持 |
| 項目名のふりがな・本文中のルビ記法 | 項目名設定と本文の記法を維持 | 本文中にある記法は維持、項目名の設定は含まない |
| 項目メモ | 通常／リストの種類、本文、タグ | 含まない |
| 関連リンク | 項目・区分の両方。生成元情報を保持して照合 | 含まない |
| 構想メモとの連携・自動反映 | 連携ID・同期状態を取り込まない。コピー側の自動反映を明示OFF | 含まない |
| 画像・呼び名一覧 | 含まない | 含まない |

専用情報はHTMLコメント内のJSONに持たせ、読みやすい基本構造と本文のMarkdownを維持する。通常のMarkdown書き出し／インポートへの項目メモ追加は今回の対象に含めない。

## 生成と互換性

`web/lib/generated-note-markdown.js` をVS Code／Webの共通形式とし、詳細情報の整形・型検証・読込・自己リンクの対応付けを共用する。CJS生成側の `src/export/web-note-markdown.js` は保存済みJSONだけを読み、既存のファイル名・同じ最新版1ファイルの更新方法を維持する。従来のファイルも同じ保存版から形式3へ更新する。変更済みの手書きファイルは従来どおり上書きしない。

項目数・型・参照先・ハッシュを検証し、不正な詳細情報や見出し構造の不一致を作成前に停止する。項目メモの任意フィールドを丸ごと採用せず、対象フィールドだけを取り込む。関連ファイル名はファイル名部分だけにし、PCの絶対パスを参照情報へ持ち込まない。構想メモIDや自動反映を意図しない既存メモへ接続しない。生成結果がWebの上限10MBを超える場合、または同じノート内のリンク先が消えている場合は、前の生成物と原本を残して警告する。

形式1／2の読込を維持。形式2から作ったコピーも、元の保存版が同じでも形式3の詳細を追加できる。Web側も編集されていたら停止する。形式3で詳細を持ったコピーへ旧形式を自動反映して内容を失う操作は停止し、再生成を案内する。手動の「既存ノートに上書き」はこれまでどおり比較とバックアップを必須とし、選んだファイルにない内容は引き継がないことを明記した。

## IDと関連リンク

`web/lib/note-template-sync.mjs` は形式3でも生成元ID→読込先IDの対応を保持する。コピーを新規作成・更新・上書きする各経路で自己リンクを最終的なノート・分類・項目IDへ付け替える。元の項目を別大分類へ移した場合も対応を維持する。既存ノートのID・名前・順序の維持、他のノートから来るリンクを壊す変更の停止、保存基準と作品の再確認は継続。

別ノートへのリンクは `importTarget` に生成元の作品・ノート・項目の情報を保持する。同じ作品の識別情報が一致する原本か、その生成元を記録した読込先のコピーを照合する。単に名前やIDが同じ別作品へは接続しない。読込先でノートの種類を変えて作成した場合も、生成元の対応から実際の種類と項目IDを取得する。

原本への接続には、ノート自体に加えて同じ作品の `.mojigoto/web-import-settings.json` がWebから確認できる必要がある。Google Driveで見えていない場合は追加許可する。この確認ができなければ原本のIDだけで作品を推測しない。リンク先のMarkdownをコピーとして読み込む経路では、この設定ファイルの追加許可は不要。

参照元を先に取り込んでもリンク情報は失わない。リンク先のMarkdownを後から同じ作品へ取り込めば、参照元を読み込み直さず次のクリックで解決できる。原本を使う場合は、その作品とノートがWebから確認・追加許可できる必要がある。参照先が不明・未取込・重複の場合は案内し、別の項目へフォールバックしない。原本とコピーの両方が同じ生成元として確認できて一意でない場合も停止する。

Webの関連プレビューに実際の対応先IDを渡し、同じ参照先の確認結果を既存のキャッシュへ保持する。初回の生成元照合はノートを最大4並列で読み込む。作品切替・新しい表示要求があれば遅れた結果を表示・キャッシュしない。VS Codeの保存側とWebView側も `importTarget` を保持し、VS Codeで読み直して保存しても参照元の対応情報と次回読込の基準ハッシュを落とさない。VS Codeの関連先解決にも同じ照合規則を使用する。

## 画面・更新

プレビューに項目メモ・タグ・ふりがな・関連リンク件数を加え、形式3は比較にもそれらを含める。関連先の識別情報も比較し、見かけの名前が同じリンク変更を見落とさない。通常Markdownは従来の基本内容の比較を維持する。作成・反映カード、上書き前の説明、ヘルプ、Dashboard、README、案内板、アップロードガイドを更新した。

Web本体とbootは1.0.192、Service Workerはv237へ更新。変更した共通モジュールは従来のAPP_SHELLに含まれる。生成側とWeb側の両方を更新し、Dashboardの「Web読込用Markdown」→「今すぐ更新」で再生成してから試す。古いWeb版は形式3に対応しない。新しい秘密設定や本番設定の追加は不要。
