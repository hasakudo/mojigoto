# メモ保存時のバックアップ・反映の並行化（2026-10-26）

## 実環境の報告

利用者がOneDriveの速度計測結果を提供。構想保存の本文書込2482ms、バックアップ8034ms、項目反映4831ms（内訳に出典ノート取得1467ms・同期情報書込1619msを含む）だった。同期情報保存後のバックアップは0ms。内訳と全体は重複しているため合算しない。前回の出典探索削減はreads=1、fallback=falseとして機能しているが、バックアップ待ちが最大の段階だった。入力停止から保存済みまで約13秒との利用者の体感報告と、段階別計測値は分けて扱う。

通知なしの反映失敗は利用者側でも再現せず、ダウンロード先に関する通知だった可能性があるとの補足を受領。既知の未解決不具合として断定しない。項目側の前回修正について、実機確認完了の報告までは受けていない。

## 変更

- 項目メモ・構想メモとも、本文書込後にバックアップを開始し、完了待ちをメモ反映の後へ移動した。両処理を並行させる。最新本文取得・eTagによる競合判定と同期先書込の順序は維持する。
- 両処理完了まで画面移動の保護を維持する。項目側は反映フラグをバックアップ完了まで保持。構想側は反映が先に終わった場合のバックアップ待ちをsavingで保護し、バッヂにバックアップ中と表示する。離脱後に処理を放置する背景処理には変更しない。
- バックアップ失敗は通知し、本文とメモ反映の成功を取り消さない。待機中の追加入力は未保存に保持して次の自動保存を予約する。反映エラー・競合状態はバックアップ完了で隠さない。
- バックアップ保存先を調べる同一フォルダ一覧の再取得を削除。既存の保存先なら一覧取得は3回から2回になる。indexのeTagは最初に得たものを使用し、並行更新時の条件付き書込を維持する。
- バックアップの対象情報・本文・provider・管理フォルダ・間隔を処理開始時に固定。別作品へ切り替わった場合に保存先を取り違えず、完了したstorageを別作品の画面キャッシュへ設定しない。
