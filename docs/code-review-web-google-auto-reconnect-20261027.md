# Google Drive自動復帰と操作が必要な再認証の区別（2026-10-27）

## 利用者報告と調査

利用者が3クラウドの接続・表示・履歴を確認し、Googleだけ自動接続できなかったと報告。発生条件は一度ログアウトして再ログインした後との補足を受領。実環境のトークンや通知本文は取得しておらず、実際に接続情報が失効／消失したか、ポップアップが拒否されたかは断定しない。

現在のGoogleDriveAuthはGoogle Identity Servicesのtoken modelを使い、接続情報をsessionStorageへ保持する。有効な接続情報がある場合は既存の自動復帰経路が使える。一方、有効な接続がない場合にもreconnectPreviousCloudが起動処理内でsignInを呼んでいた。新しいtoken取得はユーザー操作を起点とする方式であり、起動時の呼出を自動接続として保証できない。

根拠は[Google token model公式ガイド](https://developers.google.com/identity/oauth2/web/guides/use-token-model)、[Googleエラー処理](https://developers.google.com/identity/oauth2/web/guides/error)。認証画面が開けない／閉じられた場合とOAuthエラーは区別される。自動復帰と新しい認証を同じように案内しないようにする。

## 変更

- Googleで有効な接続がなければ、起動時のsignInと失敗抑止マーカーの作成を行わず操作を待つ。有効な接続がある場合は従来どおり作品ルートへ自動復帰する。
- 自動接続ON・Google未接続の場合は、前回の接続先は選択済みで有効な接続がないことを案内し、「Google Driveに再接続」ボタンを表示する。
- 自動接続の説明をクラウド切替時に更新。Googleは有効な接続がある間の自動復帰と、期限切れ等でのボタン操作が必要な再接続を明示する。
- OneDrive・Dropboxの自動認証開始と失敗後の再試行抑止、Googleの手動再接続・prompt指定、許可範囲とsessionStorageの保持方針は維持する。

この変更は、ログアウト後も常に操作なしでGoogle認証を完了する機能ではない。現在の方式の制約を案内し、起動時の認証ポップアップ試行を止める改善である。長期の自動再認証はサーバー側の認証方式やトークン管理を含めた別設計になるため、今回は実装しない。
