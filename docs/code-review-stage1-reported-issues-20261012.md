# 第1段階・追加報告：Google取り込み作品とWebノート

確認日：2026-10-12。利用者から報告された3点を優先して調査・修正した。

## 1. Google取り込み作品でVS Codeの作品切り替えが失敗

利用者確認：Google Drive for desktopはストリーミング（G:）を使用している。

報告された作品フォルダを読み取り確認したところ、サンプル作品の「原稿」は実ディレクトリとして存在し、`_WORK/manuscript` は存在しなかった。作品・原稿・Drive設定の変更は行っていない。

同じ形式の日本語・全角括弧・取り込み日時を含む名前では、ローカルファイルシステム上のjunction作成・置換に成功した。このため名前の変更を最初の対策にせず、ストリーミング先でリンクを作る方式との相性を主な原因候補として扱う。G:上でリンク作成を再実行して確定した結果ではない。

Windowsのjunctionは[NTFSのリンク機能](https://learn.microsoft.com/en-us/windows/win32/fileio/hard-links-and-junctions)であり、Googleの[ストリーミングとミラーリング](https://support.google.com/drive/answer/13401938)は異なる保存方式である。Google公式資料だけから、すべてのストリーミング環境のjunction対応を断定しない。

修正：

- 作成先がjunction非対応等で失敗した場合、`mojigoto.manuscriptRoot` を選択作品の実原稿フォルダへ設定し、直接参照する。
- MultiモードとworkRootは維持する。移行後の切り替え・作品改名も直接参照を使う。
- 未保存文書の確認は、現在設定されている原稿フォルダを対象にする。
- `_WORK/manuscript` に実フォルダ・実ファイルがある場合は削除しない。
- junctionを使える保存先は既存方式を維持する。新しいリンクを作成してから旧リンクを退避・置換し、途中失敗時は旧リンクを戻す。実フォルダを再帰削除して片付ける処理は使わない。

`manuscript-switch.test.js` の7件で、非対応エラー、実フォルダ保持、置換失敗の復旧、直接参照の継続、通常junction、日本語の実ファイルシステム、作品切替コマンドを確認した。コマンドの検証では、失敗から直接参照へ切り替え、次回はjunction作成を試みず、Multi設定と原稿を保持することを確認した。

この実行環境のサンドボックスはjunction作成をEPERMで拒否したため、作成テストと全体テストは制限外で実行した。書き込み先はリポジトリ内の専用一時フォルダであり、G:の作品には書き込んでいない。

## 2. Webノートの目次・プレビューが保存後に更新されない

原因：保存後にノートデータは更新していたが、目次と開いたプレビューを再描画していなかった。

- 目次の描画を独立させ、保存後に最新のノートデータで更新する。
- 開いている目次・プレビューは入力変更にも追従する。
- 保存のために編集欄全体を再生成しない。入力中のカーソルと下書きを保持する。
- 開いているプレビューの大分類の開閉状態を保存後も保持する。
- 保存中の追加入力は、送信済み内容と区別した未保存内容として目次へ反映する。

関連して、通信失敗時の自動保存の無限再試行を止めた。また、ノート本文が保存済みでバックアップだけが失敗した場合に「保存失敗」と表示しないよう、バックアップのエラー通知を分離した。

修正前の保存関数を使う比較テストでは、表示更新・追加入力・通信失敗・バックアップ失敗の4件が失敗し、修正後は成功した。比較ログは `.review-baseline/stage1-note-original-results.log`。

## 3. Webで作った項目メモに構想メモ同期ボタンがない

表示条件は `linkedConceptMemoIds` の有無であり、VS Codeの自動反映ON/OFF自体は表示条件ではない。Webには未リンクの項目メモから構想メモを作成する入口がなかった。

- 未リンクの項目メモへ「構想メモを作成」を表示する。
- 作成済みのリンクがある場合は「構想メモへ反映」を表示する。
- メモの本文・形式・タグ・出典ID・同期指紋を引き継ぐ。Webの出典パスは作品相対パスとする。
- 自動反映の設定を勝手にONへ変更しない。手動作成と自動反映は別の操作として扱う。
- 構想メモ保存に失敗した場合、存在しないリンクをノートへ保存しない。
- 構想保存後にノートの保存だけ失敗した場合は、リンクと下書きを未保存として残して通知する。再実行時に同じ出典の構想を重複作成したり、構想側の編集を上書きしたりしない。
- 保存中は構造変更ボタンを止める。作成したリンクは項目IDで付け、処理中に位置が変わっても別項目へ付けない。
- VS Codeの手動作成・自動反映も、リンク済みIDを渡してWebで作った同じ構想を再利用する。相対パスとPCの絶対パスの違いだけで二重作成しない。

構想とノートの2ファイルを一つのトランザクションで保存する機能ではない。片方の保存に失敗した状態を保持して回復できることを検証した。
