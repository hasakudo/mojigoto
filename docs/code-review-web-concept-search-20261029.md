## 依頼と状態

原稿の確認項目1〜4は利用者が「確認できる範囲で」検証したとの報告を受領。クラウド・端末・環境の網羅範囲や反映先は未指定であり、全組合せ確認済みとは扱わない。次工程として構想メモの検索・置換を実装した。ガイド整理と歯車メニュー整理は利用者指定の後続予定に追加し、今回の対象には含めない。

Web1.0.257／シェルv302／CSS1.0.199。拡張機能は1.0.68のまま。本番・テスト環境への反映、コミットは実施していない。

## 実装と境界

- 構想メモ編集の歯車に「この構想メモを検索・置換」を追加。未保存入力を含む現在1件のタイトル・本文を検索し、行と文字位置へのジャンプ、1箇所／選択候補の置換、直前1操作の取り消しに対応。
- テキスト・リスト・TODOが対象。タグ・フォルダ・出典・同期情報と他メモは検索しない。ルビ・傍点の保護は共有コアに従う。
- リスト・TODOの行数、空行の位置、TODOチェック記号を変える操作と、タイトルへの改行は適用前に全体を拒否する。行の追加・削除やチェック状態は通常編集を利用する。通常の文字置換では行ID・checked／done・未知フィールドを保持する。
- 専用adapterがタイトル・本文を一時的な検索用データへ対応付ける。このデータは保存せず、変更は実メモへ戻してmarkConceptDirtyを1回呼ぶ。既存の保存、条件付き書込、バックアップ、自動反映経路を利用し、他メモを共有JSON内に保持する。
- 保存・同期・移動処理・同期ブロック・競合・IME変換中は置換と取り消しを抑止。concept-saveに任意の状態更新通知を加え、保存終了時にも操作可否を更新する。
- 保存後も同一セッションなら戻せる。対象フィールドを後から編集した場合は拒否し、別フィールドの入力やメタ情報は保持する。別メモ・scope・型・行IDの変更、再読込・復元で履歴を破棄する。
- 共通コントローラーに任意の事前検証とbusy判定を追加。ノート・原稿の既存動作も回帰確認した。専用ガイドをアプリ内と単独ページへ追加。
