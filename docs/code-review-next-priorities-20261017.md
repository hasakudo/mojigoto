## 今回の区切り

利用者からルビ表示・操作について「ひとまずここまでで良い」との判断を受領。ルビ対応を一区切りとし、次の2系統へ進める。今回は計画・要望の記録とコードの初期照合のみで、機能の実装は次の作業単位。

| 1 | VS Code | 外部ExportRootの倉庫表示 | 設定済みの書き出し先を、開いているフォルダの直下以外でも表示する。Single／Multi、作品切替、更新・ファイルを開く操作、倉庫内の操作対象を確認する |

- `src/tree/work-tree-provider.js` の `getWarehouseRoot` は、exportRootの親が期待される作品ルートと一致するときだけ倉庫にしている。外部ExportRootの表示はこの制限と倉庫の操作・更新を一緒に確認する。

## 前述を導入した後の追加予定

| 項目 | 対象 | 進め方・確認点 |
|---|---|---|
| ノートの通常書き出し／インポートに項目メモを含める | VS Code | Web読込拡張で作る変換処理を共用できるよう設計する。通常の書き出し／読込への導入は後続。対象形式、読みやすい表示と復元用データ、挿入／置換時のID・リンクを確認する |
| 原稿を章単位でまとめて書き出す | VS Code | 章の選択と配下原稿の順序、対象形式、出力ファイル名を具体化する。章境界の定義や既存の書き出し機能の再利用範囲を調査する |
| 構想メモをノートの項目順で表示する | VS Code／Web | 「ノートで絞り込み、大分類→区分→項目の順に並べる」案として記録。項目にリンクするメモを利用し、複数ノート・リンクなし・複数の対応先・ピン留めとの優先関係は実装前に整理する |
| ノートプレビューの区分／項目をクリックしても閉じない | Web | 編集欄へ移動しながら参照を維持する。画面幅とフォーカス、編集欄が隠れない配置、明示的な閉じる操作を確認する |
| ノートプレビューで別のノートも参照できる | Web | 原稿のノート参照を基礎に選択導線を設計する。参照先を変えても現在編集中のノートを切り替えない。未保存の現在ノート・他ノートの読込・参照から編集への移動を区別して確認する |
| 表示専用ノートプレビューの項目メモを一括で開閉する | VS Code | 初期は閉じた状態を維持し、全項目メモを開く／閉じる操作を追加する。プレビュー・ボード、個別開閉、更新・タブ復元との関係を確認する |
| ノート参照と構想メモ一覧の開閉ボタンの重なりを直す | Web | 広い画面で、連携元ノート参照と構想メモ一覧の開閉が重ならない配置にする。両パネルの開閉と画面幅を確認する。「項目メモ」との報告はこの2機能を併用する構想メモ編集画面を対象とする初期整理であり、実装時に該当配置を確認する |

追加項目は前段の導入後に小分けに扱う。通常ノートの項目メモ対応は3と共通の基礎を使えるが、別機能として実機確認を行う。構想メモの「項目順」は並べ替えの要望も含むと解釈した案であり、詳細はその段階で確定する。

Webのプレビューが閉じる動作は、`web/app.mjs` の `moveToNotePreviewTarget` が移動前に `notePreviewDialog.close()` を呼んでいることを確認した。構想メモの現行VS Codeの並び順はタイトル・作成・更新等で、ピン留めが優先される。新しい順序はこの扱いとの関係を確認する。追加5項目について実装完了・実機検証済みとは扱わない。
