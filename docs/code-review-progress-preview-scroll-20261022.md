# SNS画像プレビューの縦長画像を枠内でスクロール（2026-10-22）

## 問題と変更

作品数が多い進捗画像で、プレビューが枠からはみ出して下部操作を覆うとの報告に対応。元の枠は高さの上限と内部スクロールを持たず、60作品分の描画では枠自体が約1,934pxに伸びていた。

- `.progressSharePreviewStage`に画面高の60%／640pxの小さい方を上限として設定。padding・borderを上限に含め、`overflow: auto`で画像を枠内スクロールにする。
- プレビューの高さ計測にborderを含むoffsetHeightを加え、拡縮後の高さは切り上げる。画像末尾の枠が計測差・丸めで欠けることを防ぐ。
- ダイアログ全体の既存スクロールは維持。狭い画面や低い画面でも、必要に応じてダイアログをスクロールして下部ボタンへ移動できる。枠の末尾から外側への通常のスクロール連動を制限しない。
- PNGを生成するCanvas処理・出力サイズ・保存処理は変更しない。プレビュー枠だけを制限し、保存画像を切り取ったり縮めたりしない。Webは未変更。

## 検証

- 実際のモーダルHTML・CSSとプレビュー描画／配置関数を用い、外部サイトへ接続せずHeadless Edgeで確認。データは2作品／60作品、画面は1200×850・420×760・1200×400の6条件。
- 枠の内部スクロール、縦長画像の末尾までの到達、枠とフッターの非重複、横方向のページはみ出しがないこと、ダイアログの末尾でフッターが見えること、保存ボタンへの実クリックが届くことを検証。
- 保存ボタンのクリック検証ではテスト用受信処理を置き、OS保存処理は起動していない。保存本体は既存テストで検証する。
- 広い画面と狭い画面のスクリーンショットを目視確認。検証スクリプトは`.review-baseline/verify-progress-preview-layout.cjs`、結果は`.review-baseline/progress-preview-browser-after.log`、画像は`.review-baseline/progress-preview-after-*.png`。
