# 全体置換インポート・選択挿入後の候補更新（2026-10-13）

利用者から、全体置換インポートが「ファイルが読み込み後に更新されました」で失敗し、選択挿入・上書きは成功するが挿入先候補が再読み込みまで古いとの報告を受領した。

## 原因と修正

全体置換は新しいタイトル・種類・大分類だけをsaveNoteFileへ渡しており、読み込んだファイルの保存基準が欠けていた。既存ファイルは基準なしで保存しない安全確認を追加した際、インポート経路へ基準を渡す修正が漏れていた。置き換える本文と以前の本文を比較して止めていたわけではない。

置換確認の前に対象ノートを読み、保存基準を置換内容へ添える。ノートIDと表示順も維持する。置換は従来の確認操作を経由する。確認中・保存中に外部変更が入れば引き続き停止し、単に内容が違う置換は成功する。

新規ノート作成でも、ファイルは作成済みだが返却するnoteに保存基準がなかった。createNewNoteが実際に書いた内容の基準を返すよう修正し、新規インポートの続く初回保存へ引き継ぐ。基準値はJSON正本へ書き出さない。

選択インポートでは、成功返答に保存済みノートから作った挿入先の大分類・項目候補を含める。画面内の候補データを更新し、保持して開く場合も選択候補とプレビューを再描画する。インポート元の再読み込みや画面全体の作り直しを必要としない。

## 検証

`test/note-import-save.test.js` に6件追加した。

1. 内容が異なる全体置換の成功、元のノートID・表示順保持。
2. 置換確認中に入った外部更新を保持して停止。
3. 置換確認の取り消しでファイルを変更しない。
4. 実際の新規ノート作成に続く新規インポートの保存成功。
5. 選択挿入の成功返答に新しい大分類・項目を含める。
6. 実際の生成スクリプトの候補データ宣言・受信処理・描画関数を使い、再読み込みなしで候補を描き直す。
