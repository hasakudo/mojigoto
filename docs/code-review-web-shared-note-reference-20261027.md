# 作品共通ノート W16-A：関連作品の読み取り参照（2026-10-27）

## 合意と範囲

利用者が設計案を確認し、まずVS Codeの既存設定を使い、関連作品ノートを読み取り表示する初期案の実装を承認。原稿の「ノート参照」を対象に実装した。Webから関連作品を登録・解除するW16-Bは未実装。

## 操作

1. VS Codeの作品設定で関連作品を登録し、クラウド同期を完了する。
2. Webで同じクラウド・作品ルートに接続し、原稿の歯車から「ノート参照」を開く。
3. 「参照元作品」で現在作品または関連作品を選び、「種類」でプロット／資料、「ノート」で表示対象を選ぶ。

初期選択は現在作品。関連作品を選んでも、編集中の原稿・作品・保存先は切り替わらない。参照元作品名と読み取り専用であることを表示する。通常の原稿の自動／手動保存は従来どおりで、参照処理のための作成・更新・削除は行わない。

## 実装

shared-note-reader.mjsはproviderと参照対象の作品を明示して受け取る。設定を読み取り、保存済みworkIdと現在作品のrelatedWorkIdsから直接関連する作品を解決する。フォルダIDや作品名で関連付けを代用せず、欠損したworkIdを生成しない。A→B→Cの推移的関連や相手側にだけある関連は自動で追加しない。片側だけの直接関連は参照可能だが、その状態を案内する。

関連先と現在作品のID重複を検出した場合は曖昧な作品を候補にしない。未確認・未許可・読込失敗のIDを設定から削除しない。他作品のノートを読む前に、現在作品と相手の保存済み設定を再確認し、関連解除やID変更で以前の候補から読み進めない。設定を読む際は最新の項目情報を取得し、OneDriveの旧カタログに含まれるダウンロード情報をそのまま使わない。

ノート読込はフォルダ一覧とJSON本文の取得・正規化だけを行う。既存のensureNoteFolderやselectedWorkの一時的な差替えを使わない。未許可・取得失敗・破損は空一覧と区別し、参照元または種類の選び直しで再試行できる。Google Driveは追加許可済みのノートだけを表示し、保存先が不明な場合も新規作成しない。

reader-note-reference-controller.mjsが参照元選択と読込の所有状態を管理する。利用者・クラウド・ルート・provider・編集中作品の一致と、参照元／種類ごとの要求順を確認してから表示する。関連設定の確認中も自作品のノートを先に表示する。接続・作品・種類・参照元の切替やパネルを閉じた後の古い応答を反映しない。参照キーには所有作品・種別・クラウド項目を含め、同じノート内部IDや作品名の衝突で取り違えない。

永続キャッシュは追加していない。パネル内で保持する候補・本文は閉じる際に破棄し、開き直し時に再取得する。既存の作品検出へ事前読込を加えず、原稿や作品一覧の起動時の待ちを増やさない。関連設定のある作品ではパネルを開く時に候補作品の設定を確認するため、その間の待ちは残る。他作品のノート本文を一括先読みする処理はない。

原稿ノート参照の既存描画を再利用し、項目詳細・項目メモなど現在の表示範囲を維持。ノート一覧・ノート編集・構想メモ、画像添付や関連リンクの機能拡張は対象外。内蔵・独立ガイドの説明を更新した。
