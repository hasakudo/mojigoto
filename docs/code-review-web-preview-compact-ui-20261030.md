# 原稿プレビューの入口と本文可視範囲の整理（2026-10-30）

Web1.0.269／シェルv314／共有CSS1.0.206。本番・テスト環境への反映、実クラウド・Android実機での新UI確認は未実施。

利用者の依頼に従い、原稿画面のプレビュー設定を折りたたみ、「ページ」「全体」を左右に配置した。全体プレビューは装飾用のタイトル・繰り返すファイル情報を減らし、本文を中心に表示する。

## 変更

- 原稿画面の「プレビュー」を開くと、左が「ページ」、右が「全体」。表示設定はその下にあり、初期状態では閉じる。プレビュー入口を閉じると内側の表示設定も閉じる。
- 全体本文の上部は「目次・表示設定・閉じる」。作品名の見出しはダイアログのアクセシブルな名前として残し、読み取り時は視覚的に省略する。目次画面では作品名を維持。
- 本文に繰り返していたファイル名・パス・区間番号・入力由来の説明は表示設定内へ移動。本文由来の見出しや原稿内容は省略しない。各原稿のarticleにもファイル情報のaria-labelを付ける。
- 下部は前へ／短い進捗／次へ。読込中・失敗・中止は短い状態表示とし、失敗の本文と再試行は残す。保持区間内に未保存入力があればバッジを表示する。
- 表示設定は本文へ重ねるパネルとし、上部の閉じるボタンを覆わない。表示設定の共用、位置復元、目次・前後移動、本文キャッシュや保持区間の上限を維持。
- 読み取り時は画面の高さを広く使い、上部・下部の操作を固定。外側ダイアログの二重スクロールを抑え、本文だけをスクロールする。縦書きの余白計算も実際の12px×2に合わせた。

ガイドも「ページ」「全体」の入口と折りたたみ設定の説明に更新。接続設定の通知がモーダルに隠れる件は今回の対象外で、後続のまま。

## 検証

全1,821テスト成功。既存テストは、プレビュー入口の新しい順序、本文から移動したファイル情報、短い失敗表示に合わせて更新した。ガイド生成の--check一致。

実クラウドを使わない仮データのブラウザで確認した。

- 原稿画面の入口はページ／全体が並び、設定が閉じている。展開して文字サイズを変更し、ページプレビューに本文が表示される。開き直すと設定は再び閉じる。
- 406×827相当で横書きの本文領域686px、縦書き671px。前段階の縦書き451pxに対して約220px拡大。最終状態の外側ダイアログはclientHeight／scrollHeightとも794pxで、外側のスクロールなし。
- 横長827×406相当では本文265px。縦書きで第5行付近まで進んで回転しても、同じ箇所付近を保持した。
- 本文由来の見出し、ルビ、傍点と空行は維持。ファイル情報は表示設定内で読める。設定表示中でも閉じるボタンをクリックできた。
- 未保存の原稿だけを目次から表示し、未保存バッジを確認。開閉前後で本文と選択位置24が一致、dirty=true、writes=[]。本文内のタイトルや説明はなく、入力した本文だけを表示。
- 本文取得失敗時に本文へエラー理由、下部へ「取得失敗」、再試行ボタンを表示。再試行で通常表示へ戻った。

iframeの寸法・操作検証であり、Android実機の描画性能や操作の最終判断は利用者確認待ち。仮データiframeでは一部のマウス操作がツールの座標取得で失敗したためキーボードでも検証し、通常タブでは設定表示中の閉じるクリックを別途確認した。
