# Web：クラウド接続後の待ち時間と一覧の先行表示（2026-10-26）

## 結果

W13の最初の修正として、保存済みの作品一覧を全取得完了前に表示し、作品・原稿を開けるようにした。最新情報は背景で確認する。接続に必要な利用者認証と、前回の編集画面を復元するときの保護は維持する。

ローカル検証済み。本番・利用者のテスト環境への配備は未実施。前段のW14／W15（歯車の接続設定、ガイドのヘッダー）は利用者からテスト環境で操作確認済みの報告を受領した。

## 調査で確認した待ち

- `loadWorks` は保存済みカタログを読み込んでも作品カードを描画せず、作品設定の再取得と並び順の確定を待っていた。先行表示用のデータと計測は存在していたが、保存済み一覧が操作できる状態にはなっていなかった。
- 初回接続の利用者認証完了後も、クラウド側の読込完了まで起動中の表示が残る経路があった。
- OneDrive／Dropboxは、保存済みの作品フォルダへ戻れる場合も、ドライブ直下のメタデータを先に取得していた。
- Google Driveを使う場合にもOneDriveのトークンを確認する経路があり、未選択のクラウドの確認が待ちに加わる可能性があった。
- Single作品では、作品候補にならないと分かっている原稿フォルダの内容まで、作品検出のために取得していた。
- 作品設定と共有集計の本文取得は既に並列だった。この部分は変更していない。

## 実装

1. 利用者・クラウド・登録ルートが一致し、前回の編集画面の復元待ちでない場合は、保存済み一覧を選択中の並び順で先に描画する。最新情報の確認中であることを一覧の状態欄へ表示する。キャッシュがない場合、壊れている場合、利用者やルートが異なる場合は利用しない。
2. 背景更新の完了で初期履歴を二重に登録しない。先行一覧から編集へ移動しても、勝手に一覧へ戻さず、本文・保存基準・未保存状態を保つ。最新の並び順は必要情報がそろってから更新する。
3. 一覧・集計処理のプロバイダーを開始時点で保持し、処理番号・利用者・登録ルートを照合する。古い応答の描画・カタログ保存と、クラウド切替後の別プロバイダーでの再試行を防ぐ。フォルダ選択への移動時は、取得中の作品一覧と集計を無効にする。接続確認中のトークン・ルート応答も切替後に採用せず、履歴復元による正当なプロバイダー変更で失敗した場合の起動復旧は維持する。
4. 先行一覧の最新取得に失敗した場合は、一覧を残してエラーを通知する。取得失敗を空の最新カタログとして保存しない。
5. 利用者認証完了後、前回画面の復元待ちでなければ起動画面を解除する。保存済み作品があるOneDrive／Dropboxの不要なルート取得を省き、未選択クラウドのトークンは取得しない。
6. Singleの原稿フォルダを作品候補用に取得しない。原稿一覧を実際に開く際の読み込みは維持する。

主な対象：`web/app.mjs`、`web/lib/work-discovery.mjs`、対応テスト。保存形式・クラウド権限・認証方式は変更していない。本体／起動ビルド1.0.210、Service Workerシェルv255。拡張の版1.0.68は変更なし。

## 計測

接続の公開設定・利用者認証・クラウド認証応答／トークン・必要時のルート取得・履歴復元を分けた。作品検出はルート一覧、子フォルダ一覧、管理フォルダ一覧、設定／共有集計、詳細集計は索引と本文／件数に分けて計測する。従来の「速度計測結果をコピー」へ同じ形式で含め、直近30件を保持する。トークン・設定値・本文は計測結果に含めない。

同じ検証用プロバイダーで、本文取得に5秒、フォルダ取得に各100msの遅延を加えてブラウザ比較した。実際のクラウドや認証サーバーの測定ではなく、1作品の一覧ロードの比較である。

| 構成 | 一覧表示開始 | 全処理完了 | 一覧取得回数 |
|---|---:|---:|---:|
| 変更前・保存済み一覧あり | 5,387ms | 5,387ms | 3回 |
| 変更後・保存済み一覧あり | 115ms | 5,341ms | 2回 |
| 変更後・保存済み一覧なし | 5,230ms | 5,231ms | 2回 |

全取得の待ち自体を消した結果ではない。保存済み一覧を使える場合に操作開始を早めた結果であり、実クラウドで同じ秒数や改善率を保証しない。初回・キャッシュが使えない場合は必要な作品情報の読み込みを待つ。

追加のブラウザ検証では背景取得を15秒待たせ、完了前に作品→原稿を開いて未保存の追加入力を行った。全処理完了後（15,343ms）も原稿画面と追加入力が残り、ブラウザのエラーログは0件だった。最終ソースでも保存済み一覧の先行表示を確認した。
