# 6-E3 起動接続・イベント所有と終了処理（2026-10-25）

## 変更

共有ノート集計・索引監視は利用者確認済み。起動時の接続とイベント登録・終了を点検した。

- ツリーコマンド登録→初回案内→共有執筆記録読込→250ms後のツリーフォーカス予約→送信リマインダーの順序を`src/setup/startup-sequence.js`へ分離。各待機後の終了判定と、フォーカスタイマーの終了時解除を追加。
- 共有執筆記録の読込関数は呼出時の値を参照する。起動中に初期の仮関数から実処理へ接続する従来動作を維持。文字数更新・読込の接続変数をactivate内へ移し、別の起動インスタンスの接続を使わない。
- 原稿保存の`logOnSave`がstats-commandsとextensionで二重登録されていた。stats-commands側を残し、extension側を削除。従来は800msの記録ガードでも抑止されており、二重登録が常に二重記録になると断定はしない。
- エディター切替時の文字数更新もcounts-statusとextensionで二重登録されていた。counts-status側へ集約。
- 文字数表示は個別アイテムではなく既存のdispose関数をcontextに所有させる。タイマー・アイテムを一度だけ終了し、終了後の公開操作・遅れたイベント・キュー済みタイマーを拒否。
- 保存時の章／全体の差分基準更新を待った後に世代を再確認し、終了済み／新しい計算に置き換わった結果を表示しない。開始済みの状態保存自体は取り消さない。
- 起動側の不要になったimportのみ整理。ステータスバーの範囲判定・数値計算、初回集計・索引、シリアライザー・コマンドの接続、保存形式・Webは維持。版は1.0.68。インストール・公開・コミットは行わない。
