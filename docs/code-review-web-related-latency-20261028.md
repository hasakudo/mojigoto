## 修正

履歴経由の参照用カタログ探索で通常のdiscoverWorksを使い、全作品の設定本文・共有集計を取得した後、関連候補照合で設定をもう一度取得していた。参照用のdiscoverReferenceWorksではフォルダ・設定ファイルの一覧だけを検出し、設定・集計本文の取得を省く。必要なworkId／relatedWorkIdsは従来どおり、最新の項目情報を確認して設定本文から照合する。通常の作品一覧の設定・集計表示には変更しない。

これにより、参照候補確定前の設定本文取得は各作品につき1回になる。2作品の検証では通常探索だけで発生する設定本文2回の読み込みを省き、その後の照合で2回だけ読む。共有集計本文は参照専用探索では取得しない。設定の版確認、関連解除・重複IDの検出、読み取り専用性、接続／画面切替後の応答破棄は維持する。初回のルート・作品・管理フォルダ探索と設定確認の通信待ちは残る。

原稿・ノート両方の「参照元作品」は作品タイトルだけに変更。タイトルが空ならフォルダ名を使う。「この作品」の表示は残す。参照専用の軽量探索ではタイトル本文も省くため、候補照合で読み取った保存済みタイトルを参照用のコピーへ反映する。state.worksや編集中作品は書き換えない。参照先の識別キーは引き続き作品ID・クラウド項目を使い、表示名を識別には使わない。

速度計測に「関連作品・現在作品設定」「関連作品・作品候補取得」「関連作品・候補設定確認」を追加。記録は経過時間と件数だけで、作品名・本文・IDは含めない。次の実機計測でフォルダ検出と設定確認のどちらに時間を使うか切り分けられる。
