# バックアップ・復元と執筆記録の保存安全性（2026-10-13）

Google Driveの作品設定は利用者が未許可時の作成停止と許可後の表示・編集保存を実機確認した。構想メモ等の意図的な未許可状態の再現は必須にせず、次のバックアップ・執筆記録の点検へ進んだ。

## 原因と修正

Webのバックアップは未許可の保存先や索引を不存在と判断して作成し、索引の読み込み失敗後に見えるスナップショットだけで再構築する経路があった。Google Driveでは保存先が見えなければ追加許可を案内して停止し、索引の破損／消失時もWebでは再構築しない。VS Codeで最初のバックアップを作成、同期・追加許可して使う。索引復旧はVS Codeで行う。ほかのクラウドでも索引の通信失敗は再構築へ切り替えず、スナップショット取得失敗時は部分的な索引を書き込まない。

復元するスナップショットのID・本文・ハッシュと、ノート／構想メモのJSON形式を事前に検証する。Webは保存・反映中の復元を止め、自動保存と画面移動を復元中の共通ロックで抑止する。ノートの未保存入力も退避対象とする。退避中の追加入力では本体を書き換えず停止し、書き換え中に入った入力は未保存として画面に保持する。復元前の退避が失敗したら本体を保存しない。空の構想メモ復元時に存在しない表示関数を呼ぶ経路も修正した。

VS Codeのノート／構想メモ復元は直接writeFileする経路を、読み込んだ内容を照合して仮ファイルから置き換える保存へ変更した。バックアップJSON保存も同じ方式を使い、rename拒否時にcopyFileで元ファイルへ書き込むフォールバックを廃止した。索引の読み込み時の基準を保存まで引き継ぎ、スナップショット作成中の他端末の索引更新を上書きしない。索引競合時は保存済みスナップショットが索引未登録で残る場合があるが、データを削除して帳尻を合わせない。

VS Codeの原稿復元は退避中のdocument.version変更で停止する。本文・ID・ハッシュ検証も追加した。実際の反映・保存はVS Codeの文書編集APIを使う。

Webの執筆記録は通信失敗・不正JSON・不正形式を空の記録として扱って保存していたため、読み込み失敗時は書き込まず停止するよう変更した。Google Driveで保存先が見えない場合も新規作成しない。初回の保存先はVS Codeの集計更新時にwxで作成し、既存の正常／破損ファイルを上書きしない。競合時の再試行では最新版を読み、他端末のイベントを保持する。原稿の保存成功と記録保存失敗は分けて通知する。復元後の記録保存失敗や、自動バックアップ失敗も通知する。
