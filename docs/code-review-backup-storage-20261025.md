## 変更

自動反映設定の切替・確認は利用者確認済み。原稿とノート／構想メモのバックアップが共有する保存境界を点検した。

- 共通の索引ファイルを使う一方、構造化データの待ち行列は専用Map、原稿側の作成・保護等には操作単位の待ち行列がなく、同時操作時に同じ古い索引を読むことを再現。
- `src/backup/backup-storage.js`へ索引単位の待ち行列と重複していた`writeJsonAtomic`を集約。絶対パスを使い、Windowsでは大文字小文字の表記差も揃える。
- 原稿・ノート・構想メモの作成、一覧取得に伴う索引再構築、保護変更、原稿移動による履歴パス更新を、共通の索引の読込から保存完了まで順に処理する。低水準の既存公開ヘルパーと公開APIは維持。
- 原稿の手動作成は待ち行列に入る前の本文を保持。自動作成は間隔判定と作成を同じ操作内で処理し、作成本体への内部委譲で待ち行列の二重待ちを避ける。
- 失敗しても後続操作を進め、最後の操作完了時に待ち行列の参照を解放する。別の索引の操作は待たせない。
- 文字数・ハッシュ・重複判定・保持数・保護・復元前の退避・移動時の判定・保存形式は維持。既存の原子的ファイル保存と外部更新の競合検出も維持。プロセス内の操作順を整える変更であり、別プロセスとの競合検出を無効にしない。
