# ノートの検索・置換え：初回実装案（2026-10-25）

## 現在地

追加修正1～6は利用者確認済み。本設計案と進め方は利用者が承認。7-A・7-Bの置換動作と[モーダル表示](code-review-note-replace-modal-20261025.md)も利用者確認済み。原稿には[作品ツリーから標準検索を開く入口](code-review-tree-manuscript-search-20261025.md)を追加し、実機確認待ち。以下はノートの初回範囲と後続拡張の方針。

## 初回の範囲

- VS Codeで開いている1つのノートの編集データが対象。未保存の入力も含める。保存済みファイルを直接書き換える方式にしない。
- プロット・資料で同じ仕組みを使う。表示専用プレビューは置換入口にせず、編集側の変更を表示へ反映する。
- 現在のノート検索パネルの「置換…」からモーダルを開く。通常の検索・絞り込み・ハイライトを維持し、編集・プレビュー領域を押し下げない。
- 全作品・他ノートへの一括置換、原稿・構想メモ、選択範囲／大分類単位への限定、正規表現、Web対応は後続。

## 対象フィールド

| 区分 | 初期値 | 初回の置換対象 |
|---|---|---|
| 名称 | ON | 大分類名、区分名、補足、項目名 |
| 項目詳細 | ON | 項目の本文 |
| 項目メモ | OFF・選択可能 | 項目メモの本文。テキスト／リスト／TODOも保存している本文文字列を扱う |
| ふりがな | 対象外 | 項目名の別フィールド`headingRuby`は維持 |
| タグ | 対象外 | 配列の重複・正規化ルールがあるため、初回は置換しない |
| その他 | 対象外 | ノート名、関連リンクの表示名、画像名、呼び名一覧、ID、同期情報、パス、設定値など |

通常検索でふりがなやタグが一致する動作は維持する。「検索に一致した項目の全フィールド」を置換するのではなく、置換対象フィールドで一致箇所を別途列挙する。大分類名が一致して配下全体が見えていても、配下を無条件には変更しない。

## 一致とルビの扱い

- 文字列検索のみ。検索語を正規表現にせず、置換文字の`$1`・`$&`等もそのまま文字列として扱う。空の検索語は実行不可。空の置換文字は削除として許可する。
- 既存検索と同じく大文字・小文字を区別しない初期値とし、置換欄には「大文字・小文字を区別する」を用意する。全角半角・読み・表記揺れの自動同一視は行わない。
- 一致は元文字列の位置を保持する。小文字化で長さが変わるUnicode文字やサロゲートペアに対応し、正規化後の添字を元文字列へ直接流用しない。
- 初回は有効なルビ記法の全体（親文字・読み・区切り記号）と傍点記法を保護する。記法の途中や親文字と読みをまたぐ一致は置換しない。モノルビの対応関係を崩さないことを優先する。
- 保護部分の一致は「ルビ等のため置換対象外」として件数・場所を表示し、黙って置換済み扱いにしない。不完全な記法で安全な範囲を判断できないフィールドも対象外として理由を表示する。
- 置換文字から新しいルビ・傍点記法が成立したり既存の保護境界が変化する場合は適用を止め、通常編集へ案内する。初回をルビ編集機能の代わりにしない。
- ルビの親文字だけの置換、読みの置換、モノルビの再配分は、初回の確認後に別仕様として検討する。

## 操作の流れ

1. 通常検索から「置換…」のモーダルを開き、検索語・置換文字・対象フィールドを指定する。場所を押すと閉じて編集欄へ移動し、再オープンして続けられる。
2. 候補を「大分類／区分・項目／フィールド／行」と、変更前→変更後の短い抜粋で表示する。閉じた項目メモも候補に出し、場所をクリックするとその入力欄を開いて該当位置へ移動する。
3. 「この箇所を置換」で1箇所ずつ処理できる。複数は候補のチェックと「全候補を選択」を使い、「選択したN箇所を置換」で適用する。初期の一括選択はしない。
4. 適用後に件数と「直前の置換を戻す」を表示する。ノートの編集／リスト／ボード／表示専用タブと、未保存表示を更新する。

選択した候補と変更前後を既に一覧で確認できるため、毎回のモーダル確認は追加しない。「全候補」は通常検索で画面に残った行ではなく、置換条件で列挙した候補の集合であることを明示する。空白・改行だけへの変更も、抜粋で分かる表示にする。

項目メモをONにした場合のみ「保存時は項目メモの自動反映設定にも従います」を置換欄に短く表示する。通常の執筆画面へ長い説明は追加しない。詳しい説明はガイドへ置く。

## 適用・保存・取り消し

- 候補にはノート／大分類／項目ID、フィールド、元文字列、一致位置、作成時の編集リビジョンを保持する。候補の表示中に入力・並べ替え・追加削除・外部更新があれば、再計算して古い選択を解除する。
- 適用直前にもIDと元文字列を照合する。一部だけを古い内容へ当てず、食い違いがあればその操作全体を中止して候補を更新する。
- 同じフィールドの複数箇所は元文字列を基準に一度だけ組み立てる。挿入した文字へ再置換を繰り返さず、重複した一致を二重に適用しない。
- 変更するのは対象文字列だけ。項目メモを変えた場合は通常編集と同じく更新時刻を更新し、リンクID・同期設定・指紋を直接初期化しない。
- 一操作につき`markDirty`を1回呼び、既存の未保存表示・自動保存・保存競合保護・項目メモの自動反映・出典名更新へ乗せる。自動保存OFFでは手動保存まで未保存を維持する。
- 専用の「直前の置換を戻す」を1操作分用意する。フィールド単位の変更前／変更後とIDを保存し、ノート全体を過去スナップショットへ置き換えない。Ctrl+Zの既存入力操作を横取りしない。
- 戻す際も、対象フィールドが変更後のままかを照合する。後からそのフィールドを編集・削除していたら戻さず通知する。無関係な入力は保持する。次の置換で戻す対象を更新し、再読込・タブ終了後は保持しない。
- 自動保存後もノートの文字列を戻す操作は可能とする。戻した内容も通常保存を通す。保存によって構想メモへ既に自動反映された内容は、既存の同期・競合保護に従う。別画面の編集まで一括して巻き戻す機能ではない。

## 現行コードで確認したこと

- `script-utils.js`の通常検索は大分類名・区分名・補足・項目名・ふりがな・本文・項目メモ・タグを対象にする。大分類名一致では配下項目も表示する。検索一致と置換対象の分離が必要。
- `display-renderer.js`には元文字を保持するハイライトと、明示的なルビ・傍点の描画がある。置換では生成HTMLを変更せず、元文字列に対する範囲を扱う必要がある。
- `editor-view.js`の`markDirty`はリビジョン・未保存状態・保存要求をまとめて更新する。別の直接保存経路を増やさない。
- 項目メモの通常入力は本文変更時に`updatedAt`を更新する。置換でも同じ意味を保つ。
- コピー専用の取り消しには大分類全体のスナップショットがあるが、置換の取り消しへそのまま流用すると別の入力を巻き戻す恐れがあるため、文字列差分を使う。

## 実装の分け方

1. **7-A：置換候補の列挙** — DOMや保存処理に依存しない対象抽出・一致範囲・保護部分の判定を実装し、置換前後を計算する。まだノートを変更しない。
2. **7-B：VS Codeの操作** — 現在ノートの置換欄、候補の確認・選択・ジャンプ、1箇所／複数適用、直前の置換を戻す、通常の保存・表示連携を実装する。
3. **7-C：範囲拡張を検討** — 実機確認後に、ルビ内・ふりがな・タグ、大分類単位、Webへの展開順を利用者と決める。

Webへ展開する場合は候補計算の純粋関数を共有可能にし、Web固有の保存・自動反映・画面サイズに合わせて操作部を実装する。VS CodeとWebの同時導入を初回の前提にしない。

## 実装時の検証

- 名前・本文・メモの候補件数、同じ行の複数一致、重なる一致、改行・空白・絵文字、大小文字、Unicodeで長さが変わる文字、置換文字の`$`や記号。
- ルビ・傍点・モノルビ列と不完全な記法の保護、保護部分の件数表示、通常文字列から記法が生じる置換の拒否。
- 折り畳まれた項目メモ、検索フィルターと対象選択の違い、対象外フィールド／ID／リンク／タグ／ふりがなの保持。
- 候補生成後の別入力・並べ替え・削除・外部更新、IME変換中、連打、古い候補の適用防止、大きいノートの候補表示負荷。
- 取り消し時の別入力保持、複数箇所を1操作として戻すこと、保存後・自動保存OFF・自動反映ON/OFF・既存の同期競合。
- 1／2カラム、文字倍率、ボード、表示専用タブ、入力補助、対象入力欄へのジャンプ。
