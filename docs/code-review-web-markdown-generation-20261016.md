# ノートごとの最新版Markdown自動生成：3b（2026-10-16）

原稿・ノートの新規読込と冒頭プレビューを利用者実機で確認済み。次の小単位として、VS Codeで作品ごとに自動生成をON／OFFし、保存済みノートごとに最新版Markdownを1ファイルだけ更新する機能を実装した。

## 操作と保存先

Dashboardの「保存設定」→「Web読込用Markdown」で「この作品のノートを自動更新」をONにする。初期OFF。ON時に現在の作品のプロット・資料を生成し、以後はVS Codeでの保存成功後に更新する。「今すぐ更新」でも保存済みの内容から追いつける。OFFにしても生成物を削除しない。再ONで保存版を生成し直す。

作品内の `.mojigoto/web-import-settings.json` にON／OFFと専用の作品IDを保存する。既存のwork.json／singleWork.jsonの保存形式やVS Codeの全作品共通設定を変更せず、作品設定との同時保存で項目が消える問題を避けた。Dashboardの古い画面・作品切替前の操作・破棄済みパネルから別作品を変更しない。

生成先は `.mojigoto/web-import/plots/` と `references/`。ファイル名はノートIDから計算した固定の識別名であり、タイトルではない。タイトル・JSONファイル名を変更しても同じ生成先を使う。ノート名は生成ファイル内に保持し、Webの選択後プレビュー・名前欄に表示する。_WORKや外部ExportRootを基準にしない。元ノートを削除した際もMarkdownは残す。整理・削除は自動では行わない。

## 保存と保護

- 通常／自動保存、新規作成・テンプレート作成、既存インポート・コピーからsaveNoteFileへ進む経路、項目メモ反映、並び替え、作品間コピー成功後、ノートのバックアップ復元後へ接続した。本文を変えない全作品共通の自動反映既定の移行は生成契機に含めない。
- 原本の保存成功後に生成を予約し、元の保存結果を待たせない。生成時にはディスクの保存版を読み直す。未保存入力や原本の保存競合は生成しない。生成中に原本が変わった場合も古い保存版を確定せず、次の保存／今すぐ更新で再試行する。
- 作品単位で生成・ON／OFF・再生成を順番に処理する。同じ保存版は生成時刻も含めて書き直さず、世代ファイルを作らない。既存の版照合付き・一時ファイルからの安全な置換を使う。
- メタデータに形式版、作品／ノートID、種類、ノート名、元JSONファイル名、元保存版の指紋、生成時刻、本文と生成物の指紋を保持する。端末の絶対パスや資格情報は含めない。
- 手動編集済み・手書きの同名Markdown、別の作品／ノートの生成物、未対応形式では上書きを止める。退避・移動後に再試行する。生成先のリンクも辿らない。
- 同じ種類内に重複IDがある場合は両ノートの生成を止める。別作品は独立。IDがない旧ノート／旧形式は原本を勝手に変更せず、ノートを一度保存してから再試行する案内にした。
- 失敗はDashboardに閉じるボタン付きで残し、通常保存後の失敗は開いているノートの警告にも通知する。同じ失敗を保存のたびに通知し直さない。一括生成中は個別のネイティブ通知を連打せず、Dashboardへまとめる。他のノートの成功だけで未解決の警告を消さない。原本の保存成功は取り消さない。

外部エディターやWebからの更新を常時監視して生成する処理は追加していない。その場合はVS Codeの「今すぐ更新」で保存版を読む。OFF時・元ノート削除時の生成物削除、詳細項目の完全復元、世代バックアップ、Markdownとの双方向同期は今回の範囲外。

## Web側

新規ノートの既存のMarkdown読込で専用形式を検証し、ノート名と基本構造を読み込む。専用コメントを本文として取り込まない。生成物が手動変更されている場合や未対応版は読込を止める。基本構造・本文だけが対象で、項目メモ・関連リンク・画像・呼び名一覧・独立ふりがなを復元できるとは表示しない。

生成された本文内の見出しらしい行を構造と誤認しないよう専用形式でエスケープし、Web読込後に元へ戻す。字下げ・コードフェンス内も扱う。通常のMarkdownの解析は変えない。ノート／項目IDは新しく作り、自動反映先を複製しない。

今回は新規コピーの作成であり、読込時にも明記する。3cの「以前の読込先を提示する」「同じ保存版なら何もしない」「両側変更を比較する」は未実装。同じMarkdownを繰り返して新規作成するとコピーが増えるため、元ノートをそのまま編集する場合は原本JSONを許可して使う既存経路を優先する。

## 実機で確認すること

1. **Single／Multi**：Dashboardの保存設定で対象作品だけONにし、plots／referencesそれぞれにノート数分のmdができることを確認する。別作品はOFFのままで、再起動後も対象作品のONが保持されること。
2. **同じ1ファイルの更新**：ノートの本文・タイトルを手動／自動保存し、同じmdが更新され件数が増えないこと。OFF中は変わらず、再ON／今すぐ更新で保存版に追いつくこと。
3. **Web**：生成したmdを新規ノートの読込で選び、ノート名と冒頭を確認してコピー作成できること。元JSONを許可済みで同じノートを編集したい場合はMarkdownで別コピーを増やさない。
4. **保護**：確認用の生成mdに手動で追記してから原本を保存し、mdが上書きされず警告が残ること。原本の保存自体は成功し、mdを退避・移動して今すぐ更新すれば再生成できること。
5. **G:の追加確認**：通常保存時に同名mdが1つだけであること、Drive同期完了後にもファイル選択から最新の内容が読めることを確認する。今回のローカルファイル選択はGoogle Drive連携の追加許可を使わない。今後Drive APIから生成物を直接読む場合は、PCで作成したファイルの初回許可と、更新後にも同じ許可で読めるかを別途確認する必要がある。

G:ストリーミングでの実Drive fileId維持は未検証。今回の安全な置換が同じDrive項目として同期される保証はしていない。将来のDrive APIからの直接読込に向け、固定パスの上書きだけで追加許可が不要になるとは案内せず、権限維持のために原本や生成物の版照合を外さない。実機で問題があれば、次の段階へ進む前に保存方式を見直す。
