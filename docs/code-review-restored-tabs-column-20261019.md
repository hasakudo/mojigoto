# 復元が終わっても開けない問題の追補（2026-10-19）

WebのHOME履歴スクロールは利用者確認済み。VS Codeでは、復元済みの構想メモを作品ツリーから開く場合と、復元タブにない別のノートを新しく開く場合に「タブの復元を待っています」で停止したため、復元の照合処理を修正した。

## 原因と修正

- 前回の照合は、シリアライザーへ渡されたパネルのviewColumnとTabGroup.viewColumnを直接比較していた。VS Code内部のEditorGroupColumnは0始まりで、復元コールバック直前の生成経路ではその値がパネルへ直接渡される。一方、タブ一覧と後続の表示状態通知は1始まりへ変換される。そのため、復元自体が完了していても待機集合からタブが除かれず、再度のシリアライザー呼出しを待ってタイムアウトした。
- シリアライザー入口でのみ0始まりの位置を補正する。後から届く表示状態通知は1始まりのまま使用し、二重変換しない。一意のタブ名は位置が不明でも照合できる。
- 同じグループに同名タブが複数ある場合、位置と名前だけで個別の背景タブを決めつけない。選択時のパネル状態を照合し、候補全体の復元が揃った場合はまとめて待機集合から除く。対象作品・ノートの再利用は各画面が保持するファイルパスの登録で行う。
- 復元中に未保存印などでタブ名が変わっても、復元開始時のタブ名を控えて完了を判定する。完了後は照合用リスナーと記録を解除する。
- 新規タブを作る前に、実行中の復元処理と登録の完了を引き続き待つ。タイムアウトを短くして新規作成へ進む変更や、既存タブの閉鎖・本文の書き換えは行わない。

一次資料：[復元コールバックのパネル生成と表示状態変換](https://github.com/microsoft/vscode/blob/main/src/vs/workbench/api/common/extHostWebviewPanels.ts)、[EditorGroupColumnの定義](https://github.com/microsoft/vscode/blob/main/src/vs/workbench/services/editor/common/editorGroupColumn.ts)。

## 検証

- 前回のテストダブルも復元コールバックへ1始まりを渡していたため、この差を検出できなかった。実際の受け渡しに合わせ、復元時は0始まり、後続通知は1始まりに修正。
- 利用者の2ケースを先に追加し、修正前に両方失敗することを確認。ログ `.review-baseline/restored-tabs-column-before.log`。修正後は復元済みタブを再選択・再シリアライズすることなく、既存の再利用と別ノートの新規表示へ進める。
- 同名タブの一括完了、一部だけ復元済みの選択通知、位置不明の一意タイトル、復元途中の名前変更も追加。共通復元処理の全18ケース成功。
- Webのコード・配布版は変更しない。VS Codeの再読み込み／再起動後のネイティブ操作は利用者の実機確認が必要。インストール・本番更新・実作品データの操作は未実施。

1. 構想メモと複数のノートを開いて再読み込み／再起動し、復元後に作品ツリーから同じ構想メモを開く。エラーと重複がないこと。
2. 復元されたタブに含まれない別のノートを作品ツリーから開く。復元待ちにならず新たに開けること。
3. ノート編集・表示専用プレビュー／ボード・Dashboardなどの同じ入口から再度開き、タブを再利用すること。
